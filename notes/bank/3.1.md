## lc-combinations Combinations (tier 1, pattern generate-all, set practice)
- Budget: n ≤ 20, output C(n, k) lists.
- Idea: Recurse on the next number to take, starting after the last one taken; stop when k are chosen. Optional cut: stop if too few numbers remain.
- Techniques: 3.1
- Needs this topic because: the basic choose-or-skip recursion that lists every object.
- Tier reasoning: LeetCode Medium, the first template of the topic.

## lc-subsets-ii Subsets II (tier 1, pattern generate-all, set practice)
- Budget: n ≤ 10.
- Idea: Sort. At each depth loop over the next element to add; skip nums[i] when i > start and nums[i] == nums[i − 1], so equal values are taken in a fixed order and no subset repeats.
- Techniques: 3.1, 1.1
- Needs this topic because: duplicate-skipping in generation.
- Tier reasoning: LeetCode Medium; one rule on top of plain subsets.

## lc-permutations-ii Permutations II (tier 2, pattern generate-all, set practice)
- Budget: n ≤ 8.
- Idea: Sort; keep a used[] array. Skip nums[i] if it equals nums[i − 1] and nums[i − 1] is not currently used, so equal values are placed left to right.
- Techniques: 3.1, 1.1
- Needs this topic because: generating distinct permutations with duplicates.
- Tier reasoning: LeetCode Medium; the skip condition is the usual bug.

## lc-combination-sum-ii Combination Sum II (tier 2, pattern generate-all, set reserved, for drill)
- Budget: n ≤ 100, target ≤ 30.
- Idea: Sort; recurse with a start index and remaining target; break the loop as soon as candidates[i] > remaining; skip equal values at the same depth.
- Techniques: 3.1, 1.1
- Needs this topic because: generation with a sorted early break and duplicate skipping.
- Tier reasoning: LeetCode Medium.
