Solution notes for every bank problem (bank plan Section 7.4). Not shown on the site. † = Codeforces problem checked through the official API only (title, rating, tags); the statement could not be opened from the build environment, so the idea below needs a spot-check on the page.

## lc-longest-increasing-subsequence Longest Increasing Subsequence (tier 2, pattern lis, set practice)
- Budget: n ≤ 2500 (O(n²) passes; aim for O(n log n)).
- Idea: tails[k] = smallest possible tail of an increasing subsequence of length k + 1; for each x replace lower_bound(x) or append.
- Techniques: 3.4, 1.4
- Needs this topic because: the smallest-tail template.
- Tier reasoning: LeetCode Medium; the canonical problem.

## cses-1145 Increasing Subsequence (tier 2, pattern lis, set practice)
- Budget: n ≤ 2·10^5.
- Idea: Smallest-tail array with lower_bound (strict increase). O(n log n) is required.
- Techniques: 3.4, 1.4
- Needs this topic because: LIS at a size where O(n²) fails.
- Tier reasoning: CSES.

## lc-number-of-longest-increasing-subsequence Number of Longest Increasing Subsequence (tier 3, pattern lis, set reserved, for review)
- Budget: n ≤ 2000.
- Idea: O(n²): len[i] and cnt[i]; for j < i with nums[j] < nums[i], a longer len resets cnt, an equal len adds cnt[j]. Sum cnt over the maximum len.
- Techniques: 3.4
- Needs this topic because: counting optimal subsequences alongside their length.
- Tier reasoning: LeetCode Medium; the count bookkeeping is error-prone.

## lc-minimum-number-of-removals-to-make-mountain-array Minimum Number of Removals to Make Mountain Array (tier 3, pattern lis, set reserved, for checkpoint)
- Budget: n ≤ 1000.
- Idea: inc[i] = LIS ending at i from the left, dec[i] = from the right. For i with inc[i], dec[i] ≥ 2: keep inc[i] + dec[i] − 1. Answer n − max.

## lc-make-array-strictly-increasing Make Array Strictly Increasing (tier 4, pattern lis, set reserved, for exam)
- Budget: n, m ≤ 2000.
- Idea: Sort and dedupe arr2. dp maps "last value" → fewest operations after i elements; from each state keep arr1[i] if larger, or replace with the smallest arr2 value > last (upper_bound).
- Techniques: 3.4, 1.1, 1.4
- Needs this topic because: increasing-sequence DP keyed by the last value.
- Tier reasoning: LeetCode Hard.

## ac-abc354_f Useless for LIS (tier 5, pattern lis, set practice)
- Budget: T test cases, Σ N ≤ 2·10^5 (N ≤ 2·10^5).
- Idea: L[i] = LIS ending at i (left to right), R[i] = LIS starting at i (right to left, as decreasing). A_i is in some LIS iff L[i] + R[i] − 1 = overall LIS length.
- Techniques: 3.4, 1.4
- Needs this topic because: LIS lengths in both directions per index.
- Tier reasoning: ABC F (difficulty about 1640).

## ac-abc393_f Prefix LIS Query (tier 5, pattern lis, set practice)
- Budget: N, Q ≤ 2·10^5.
- Idea: Sort queries by R. Extend the smallest-tail array one element at a time; at R, the answer is upper_bound(tails, X) − tails.begin() (tails is sorted, and a tail ≤ X means that length is reachable with elements ≤ X).
- Techniques: 3.4, 1.4, 1.1
- Needs this topic because: reading more than the length from the tails array.
- Tier reasoning: ABC F (difficulty about 1280).

## lc-maximum-length-of-pair-chain Maximum Length of Pair Chain (tier 2, pattern lis-reduction, set reserved, for lookalike)

## lc-maximum-height-by-stacking-cuboids Maximum Height by Stacking Cuboids  (tier 4, pattern lis-reduction, set practice)
- Budget: n ≤ 100.

- Tier reasoning: LeetCode Hard; the rotation argument is the step.
