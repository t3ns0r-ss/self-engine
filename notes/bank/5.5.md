## cf-220B Little Elephant and Array (tier 2, pattern threshold-split, set practice) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) A value x can count only if it occurs at least x times overall, so fewer than √(2n) values qualify. Keep prefix counts for each candidate and answer every query by checking all candidates.
- Techniques: 5.5, 1.2
- Needs this topic because: few "large" candidates make per-candidate work affordable.
- Tier reasoning: rating 1800.

## cf-1207F Remainder Problem (tier 3, pattern threshold-split, set practice) †
- Budget: q ≤ 5·10^5, values index ≤ 5·10^5 (recalled).
- Idea: (recalled) For moduli x ≤ √N keep a table small[x][y] updated on every add (√N work). For x > √N, sum a[y], a[y + x], … directly (≤ N/x terms).
- Techniques: 5.5
- Needs this topic because: the textbook small/large split.
- Tier reasoning: rating 2100.

## cf-797E Array Queries (tier 3, pattern threshold-split, set practice) †
- Budget: n, q ≤ 10^5 (recalled).
- Idea: (recalled) For k ≤ √n precompute steps[k][p] from right to left (steps[k][p] = 1 + steps[k][p + a_p + k]). For larger k simulate: fewer than n/k ≤ √n jumps.
- Techniques: 5.5, 3.3
- Needs this topic because: precompute small parameters, simulate large ones.
- Tier reasoning: rating 2000.

## cf-1921F Sum of Progression (tier 3, pattern threshold-split, set practice) †
- Budget: Σ n ≤ 10^5, Σ q ≤ 2·10^5 (recalled).
- Idea: (recalled) For d ≤ √n precompute suffix sums with step d of a_i and of a_i · (its index in the progression); a query is a difference of two suffix values. For large d sum directly (≤ n/d terms). 64-bit.
- Techniques: 5.5, 1.2
- Needs this topic because: step-d prefix sums only for small steps.
- Tier reasoning: rating 1900.

## cf-103D Time to Raid Cowavans (tier 4, pattern threshold-split, set practice) †
- Budget: n, p ≤ 3·10^5 (recalled).
- Idea: (recalled) Group queries by step b offline. For b ≤ √n, compute suffix sums with step b once per distinct b (reusing one array) and answer its queries; for large b sum directly. 64-bit.
- Techniques: 5.5, 1.1
- Needs this topic because: offline grouping keeps the small-step tables within memory.
- Tier reasoning: rating 2100.

## cf-1806E Tree Master (tier 4, pattern threshold-split, set practice) †
- Budget: n, q ≤ 10^5 (recalled).
- Idea: (recalled) f(x, y) = a_x·a_y + f(parent x, parent y) on equal depths. Memoise pairs only at depths with at most √n vertices (index pairs by position within the depth); deeper levels with many vertices have few such levels, so total work is O(n√n).
- Techniques: 5.5, 4.6
- Needs this topic because: memoise only where the state space is small.
- Tier reasoning: rating 2200.

## cf-1580C Train Maintenance (tier 4, pattern threshold-split, set reserved, for lookalike) †
- Budget: n, m ≤ 2·10^5 (recalled).
- Idea: (recalled) A train with period x + y ≤ √m is tracked in a table cnt[period][day mod period] (√m work per day to read). Larger periods have ≤ m/(x + y) working intervals: add them to a difference array (and cancel on removal).
- Techniques: 5.5, 1.2
- Needs this topic because: small periods by residue table, large periods by direct ranges.
- Tier reasoning: rating 2200.

## cf-785E Anton and Permutation (tier 4, pattern blocks, set practice) †

- Idea: (recalled) Swapping positions l < r changes inversions by counting values in (l, r) between the two swapped values. Split the array into √ blocks each kept sorted; count with binary search in full blocks and directly in partial ones; re-sort the two affected blocks.
- Techniques: 5.5

- Tier reasoning: rating 2200.

## cf-1619H Permutation and Queries (tier 5, pattern rebuild-batches, set practice) †

- Idea: (recalled) Store jump[i] = p applied √n times to i. A query moves by jumps of √n then single steps. A swap changes p at two points; fix the jump values of the √n predecessors of each (walk p⁻¹ backwards).
- Techniques: 5.5
- Needs this topic because: √-length jumps with local rebuilds.

## cf-342E Xenia and Tree (tier 5, pattern rebuild-batches, set practice) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) Keep dist[] to the nearest red vertex from the last rebuild and a list of reds painted since. A query = min(dist[v], dist via LCA to each pending red). When the pending list reaches √m, rebuild dist with a multi-source BFS.
- Techniques: 5.5, 4.7, 4.1
- Needs this topic because: rebuild every √ operations, brute force in between.
- Tier reasoning: rating 2400.

## cf-438D The Child and Sequence (tier 4, pattern blocks, set reserved, for checkpoint) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) Operations: range sum, range a_i = a_i mod x, point assign. Blocks of size √n keep sum and max. A mod over a full block is skipped when max < x; otherwise touch each element and rebuild sum and max (an element that changes at least halves, so such touches total O(n log A)). Partial blocks and point assignment rebuild one block in O(√n). Queries add full-block sums and partial elements.
- Techniques: 5.5
- Needs this topic because: block summaries with an amortised rebuild; WEAK FIT: a segment tree with max and sum (5.3) also fits, sqrt blocks are the other well-known solution.
- Tier reasoning: rating 2300, a boundary rating kept in tier 4 so it can serve as a checkpoint (877F, also 2300, sits in tier 5 as practice).

## cf-830C Bamboo Partition (tier 4, pattern threshold-split, set reserved, for checkpoint) †
- Budget: n ≤ 100, k ≤ 10^11, a_i ≤ 10^9 (recalled).
- Idea: (recalled) For checking interval d the wasted height is d·S(d) − Σa with S(d) = Σ ⌈a_i/d⌉; find the largest d with d·S(d) − Σa ≤ k (not monotone in d). S is constant on runs of d, and each a_i has O(√a_i) runs, so enumerate the run boundaries of all a_i together. Inside a run with S fixed take d = min(run end, ⌊(k + Σa)/S⌋) when it is at least the run start. Also try d ≥ max a, where S = n. 64-bit.
- Techniques: 5.5
- Needs this topic because: small d are visited one by one and large d fall into few distinct quotient values.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating.

## cf-1654E Arithmetic Operations (tier 4, pattern threshold-split, set reserved, for exam) †
- Budget: n ≤ 10^5, a_i ≤ 10^5 (recalled).
- Idea: (recalled) Minimum changes to make the array an arithmetic progression with integer step d = n − (largest number of indices i with equal a_i − d·i over all d). Take B ≈ √A. For |d| ≤ B, count the values a_i − d·i with an offset array for each d: O(nB). For |d| > B two kept indices i < j satisfy |a_j − a_i| ≤ A, so j − i ≤ A/B; for each i look at the next A/B indices, and when (a_j − a_i) is divisible by (j − i) and the quotient has |d| > B count that quotient; the best count plus 1 is the candidate. O(n·A/B).
- Techniques: 5.5
- Needs this topic because: small slopes by a counting table, large slopes by a short window.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating so it can serve as an exam candidate.

## cf-425D Sereja and Squares (tier 4, pattern threshold-split, set reserved, for drill) †
- Budget: n ≤ 10^5 points, coordinates ≤ 10^5 (recalled).
- Idea: (recalled) Count axis-parallel squares whose four corners are all given points; count each square once from its left column. A column with at most √n points: take every pair (y1 < y2) in it, d = y2 − y1, and test whether (x+d, y1) and (x+d, y2) exist. A heavy column (more than √n points, so at most √n such columns): for every point (x', y) with x' > x set d = x' − x and test (x, y), (x, y+d), (x', y+d). Point lookups by sorted vectors with binary search or a hash set.
- Techniques: 5.5, 1.4
- Needs this topic because: the light and heavy columns need different enumerations; both cost O(n√n) lookups.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating.

## cf-343D Water Tree (tier 3, pattern blocks, set reserved, for drill) †
- Budget: n, q ≤ 5·10^5 (recalled).
- Idea: (recalled) Operations on a rooted tree: fill a subtree, empty a vertex and all its ancestors, ask whether v is filled. Euler tour. fill(u) at time t is a range assign of t on the subtree of u (stored as a tag, a point query takes the maximum tag along the path); empty(u) at time t is a point update at u, and the latest empty time seen by v is the range maximum over the subtree of v. v is filled iff its fill time exceeds its empty time. Segment tree, O(log n) each. Looks like a block-decomposition job because of the range updates, but time stamps make a plain segment tree enough.
- Techniques: 5.5, 4.6, 5.3
- Needs this topic because: NOT this topic: this is an earlier-tool drill item (Euler tour 4.6 and segment tree 5.3).
- Tier reasoning: rating 2100, upper end of tier 3.

## cf-369E Valera and Queries (tier 4, pattern no-blocks, set reserved, for drill) †
- Budget: n, m ≤ 10^5 segments and queries, total points ≤ 3·10^5, coordinates ≤ 10^6 (recalled).
- Idea: (recalled) Each query is a set of points; count the segments that contain at least one of them. A segment contains none exactly when it lies strictly inside a gap between consecutive query points (including the gaps before the first and after the last). Count, for each gap (a, b), the segments with l > a and r < b, offline: sort gaps by b, add segments in order of r into a Fenwick tree at l, and query a suffix count. The answer is n minus the sum over gaps.
- Techniques: 5.5, 5.2, 1.1
- Needs this topic because: NOT this topic: offline Fenwick (5.2). Looks like Mo because of many query sets over the same segments.
- Tier reasoning: rating 2200.

## ac-abc403_g Odd Position Sum Query (tier 4, pattern blocks, set reserved, for drill)
- Budget: Q ≤ 3·10^5, values up to 10^9, queries are encoded with the previous answer (online).
- Idea: Insert a value into a multiset and ask for the sum of the elements at odd ranks in sorted order. Online, so values cannot be compressed in advance: use a dynamic segment tree over [1, 10^9] with nodes created on demand; a node stores cnt, the sum of elements at odd ranks inside it and the sum at even ranks; merge: odd = odd(L) + (cnt(L) odd ? even(R) : odd(R)), even symmetric. Insert is O(log V) with about 3·10^5·30 nodes. The answer is the root's odd sum.
- Techniques: 5.5, 5.3
- Needs this topic because: NOT this topic: segment tree with a parity-aware merge (5.3). Looks like sorted blocks with insertion.
- Tier reasoning: ABC G with AtCoder Problems difficulty 2028; tier 4 as for the other reserved F/G items.

## ac-abc157_e Simple String Queries (tier 4, pattern blocks, set reserved, for drill)
- Budget: N, Q ≤ 5·10^5 (the statement bounds N by 500000).
- Idea: Point change of a character and count of distinct letters in a range. Keep one Fenwick tree per letter (26 trees) with the count of that letter, or a segment tree of 26-bit masks combined with OR; a letter is present iff its range count is positive. Update touches two trees, a query asks 26 prefix sums: O((N + 26Q) log N). It is a string statement but uses no string algorithm.
- Techniques: 5.5, 5.2
- Needs this topic because: NOT this topic: Fenwick or segment tree (5.2/5.3). Looks like blocks with a per-block summary.
- Tier reasoning: ABC E, tier 4 as for the other reserved E items; low AtCoder Problems difficulty 1443.

## cf-641E Little Artem and Time Machine (tier 3, pattern no-blocks, set reserved, for drill) †
- Budget: n ≤ 10^5 operations (recalled).
- Idea: (recalled) Operations come in input order but carry their own time stamp: add x at time t, remove x at time t, ask how many x are present at time t. Group the operations by x (keeping input order). For each group compress its time stamps and use one Fenwick tree over time: add/remove is a ±1 point update, a query is a prefix sum up to t; undo the updates after the group. Total O(n log n).
- Techniques: 5.5, 5.2, 1.1
- Needs this topic because: NOT this topic: offline per-value Fenwick (5.2). Looks like Mo because it is an offline query problem.
- Tier reasoning: rating 2000.

## cf-755D PolandBall and Polygon (tier 3, pattern blocks, set reserved, for drill) †

## cf-961E Tufurama (tier 3, pattern threshold-split, set reserved, for drill) †

## cf-538F A Heap of Heaps (tier 4, pattern threshold-split, set reserved, for review) †
- Budget: n ≤ 2·10^5 (recalled).
- Idea: (recalled) For each k in 1..n−1, count the vertices v ≥ 2 whose value is smaller than their parent's in the k-ary heap layout, parent(v) = ⌊(v−2)/k⌋ + 1. Take B ≈ √n. For k ≤ B compute directly in O(n). For k > B the parent index is at most n/B + 1: for each such parent p build prefix counts c[j] = number of positions ≤ j with a smaller value than a_p (O(n) per p), and for every k > B add c[min(n, kp+1)] − c[k(p−1)+1]. Total O(n√n).
- Techniques: 5.5, 1.2
- Needs this topic because: small k and large k use different loops; neither alone fits in O(n√n).
- Tier reasoning: rating 2200.

## cf-1822G2 Magic Triples (Hard Version) (tier 4, pattern threshold-split, set reserved, for review) †
- Budget: Σ n ≤ 2·10^5, a_i ≤ 10^9 (recalled).
- Idea: (recalled) Count index triples whose values are x, x·b, x·b² for an integer b ≥ 1 (b = 1 gives c(c−1)(c−2) per value with count c). Treat each distinct middle value m with count c_m. If m ≥ 10^6 then m·b ≤ 10^9 forces b ≤ 10^3: try every b ≤ 10^9/m with b | m. If m < 10^6 list its divisors b by trial division up to √m ≤ 10^3 (both d and m/d) and keep those with m·b ≤ 10^9. Add cnt[m/b]·c_m·cnt[m·b]. Counts from a sorted array or hash map; about n·10^3 lookups.
- Techniques: 5.5, 1.1
- Needs this topic because: the value threshold 10^6 splits the enumeration of b into two cheap cases.
- Tier reasoning: rating 2200.

## cf-85D Sum of Medians (tier 4, pattern blocks, set reserved, for lookalike) †

## cf-920F SUM and REPLACE (tier 3, pattern blocks, set reserved, for lookalike) †
- Budget: n, m ≤ 3·10^5, a_i ≤ 10^6 (recalled).
- Idea: (recalled) REPLACE l r sets each a_i in the range to its number of divisors D(a_i); SUM l r asks for a range sum. Sieve D up to 10^6. After about six replacements every value is 1 or 2 and no longer changes. Blocks keep the sum and a flag all ≤ 2; a REPLACE skips flagged full blocks and otherwise recomputes the elements and the sum. Total element work is O(6n) plus O(√n) block steps per operation.
- Techniques: 5.5, 2.1
- Needs this topic because: WEAK FIT: a Fenwick tree plus a next-pointer skip (5.2 and DSU) is the other usual solution.
- Tier reasoning: rating 2000.

## cf-292E Copying Data (tier 3, pattern blocks, set reserved, for review) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) Arrays a and b; operation 1 copies a[x..x+k−1] into b[y..y+k−1]; operation 2 reads b[x]. Number the copy operations. Blocks of b keep a block tag (id of the last operation covering the whole block); partially covered blocks store the id per element. A read takes the larger of the element id and its block tag; if it is 0 return the original b[x], else map back through that copy to a.
- Techniques: 5.5
- Needs this topic because: WEAK FIT: a segment tree with 'latest operation id' tags (5.3) also works, as does an offline reverse pass.
- Tier reasoning: rating 1900.

## ac-abc339_g Smaller Sum (tier 4, pattern blocks, set reserved, for lookalike)
- Budget: N, Q ≤ 2·10^5, queries encoded with the previous answer (online).
- Idea: Sum of the elements ≤ X in A[L..R], online. Blocks of size B keep their elements sorted with prefix sums; a query binary-searches X in every full block and scans the two partial blocks directly. Cost O(Q·(N/B·log B + B)). A choice like B ≈ 1000 keeps it within the limit; cumulative tables per block boundary over compressed values give O(1) per block at the price of memory.
- Techniques: 5.5, 1.4, 1.2
- Needs this topic because: WEAK FIT: a segment tree whose nodes hold sorted lists with prefix sums (merge sort tree, O(log² N) per query) uses only 5.3 and 1.4.

## cf-463E Caisa and Tree (tier 3, pattern rebuild-batches, set reserved, for checkpoint) †
- Budget: n, q ≤ 10^5, a_i ≤ 2·10^6, at most 50 updates (recalled).
- Idea: (recalled) Tree rooted at 1. Query: nearest proper ancestor of v whose value shares a factor with a_v (or −1); update: set a_v. - Techniques: 5.5, 4.1, 2.1

## cf-551E GukiZ and GukiZiana (tier 5, pattern blocks, set practice) †
- Budget: n ≤ 5·10^5, q ≤ 5·10^4, values up to 10^9, 64-bit (recalled).
- Idea: (recalled) Operations "add x to a range" and "largest j − i with a_i = a_j = y". Blocks of about √n positions with a sorted copy and one pending add per block. A whole block of the range gets the note; the ragged ends change one by one and their block's sorted copy is rebuilt. For y, look in each block for y minus its note by binary search; the first block that has it (scanning from the left) and the last block that has it (from the right) give the two positions by a scan inside the block.

## cf-1039D You Are Given a Tree (tier 5, pattern threshold-split, set practice) †
