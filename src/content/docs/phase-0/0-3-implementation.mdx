## 1. Why this topic exists

Here is a small problem. A robot starts at $(0, 0)$ facing north on an infinite grid. It reads a string of commands: `F` moves one cell forward, `L` and `R` turn 90 degrees left or right. After the string ends, print its position.

There is no clever idea to find: the statement says exactly what happens, and the program does it step by step. Yet such problems are where many contest points are lost, because a careless direction table, a wrong boundary, or a missed case gives a Wrong Answer that is hard to find. With $10^5$ commands the direct method costs $10^5$ steps, well inside the budget of topic 0.2; the difficulty is only in writing it correctly.

This topic is about implementing a described process exactly. It gives four habits: count the steps of the process before writing it (and notice when a process repeats, so it need not be followed to the end); handle grids with direction arrays and one bounds check; process strings in one pass with a small amount of remembered state; and split the input into cases that together cover everything.

## 3. Definitions

- A **simulation** is a program that carries out a described process step by step, keeping the process's **state** (all the values that determine what happens next) in variables.
- A process is **deterministic** if the next state depends only on the current state.
- A sequence of states is **eventually periodic** if, from some index $\mu$ on, it repeats with some **period** $\lambda \ge 1$: $x_{i + \lambda} = x_i$ for all $i \ge \mu$. Example: $3, 5, 2, 7, 2, 7, 2, \dots$ has $\mu = 2$ (counting from 0) and $\lambda = 2$.
- The **pigeonhole principle**: if more than $K$ objects are put into $K$ boxes, some box holds at least two. Example: among any 13 people, two share a birth month.
- A **grid** with $H$ rows and $W$ columns has cells $(r, c)$ with $0 \le r < H$ and $0 \le c < W$. Two cells are **4-neighbours** if they share a side and **8-neighbours** if they share a side or a corner.
- A **direction array** lists the row and column changes for each direction, for example `dr = {-1, 0, 1, 0}`, `dc = {0, 1, 0, -1}` for up, right, down, left.
- A **one-pass scan** reads a string or array once from left to right, updating a fixed small set of variables.
- A **case analysis** splits all possible inputs into groups (cases) and solves each group by its own rule.

## 4. Theory and proofs

### 4.1 The cost of a simulation, and processes that repeat

**Theorem 0.3.1 (cost and repetition).**
1. A simulation of $S$ steps, each costing at most $c$ simple steps, costs at most $c \cdot S$ (Theorem 0.2.1).
2. A deterministic process whose state is always one of $K$ possible values repeats a state within its first $K + 1$ states. From the first repeated state on, the sequence of states is periodic: if $x_\mu = x_{\mu + \lambda}$ is the first repeat, then $x_{i + \lambda} = x_i$ for every $i \ge \mu$.
3. So the state after $T$ steps (for any $T$, even $10^{18}$) is $x_T$ if $T < \mu$, and $x_{\mu + (T - \mu) \bmod \lambda}$ otherwise.

*Proof.* 1. Add the costs of the steps. 2. Among $K + 1$ states there are only $K$ possible values, so two are equal (the pigeonhole principle, Section 3): some $x_\mu = x_{\mu + \lambda}$ with $\lambda \ge 1$ and $\mu + \lambda \le K$. Since the next state depends only on the current one, $x_{\mu + 1} = x_{\mu + \lambda + 1}$, and so on by induction: $x_{i} = x_{i + \lambda}$ for all $i \ge \mu$. 3. For $T \ge \mu$, write $T = \mu + q\lambda + r$ with $r = (T - \mu) \bmod \lambda$; applying the periodicity $q$ times gives $x_T = x_{\mu + r}$. $\square$

:::note[This proof needs]
1. The process is deterministic: the next state depends only on the current state, not on the step number.
2. The number of possible states $K$ is small enough to store one mark per state (or to record the step at which each state was first seen).
:::

**Using it.** Record for each state the step at which it first appeared (an array of size $K$ filled with $-1$). Follow the process until a state is seen again: that gives $\mu$ and $\lambda$ in at most $K + 1$ steps. Section 6 has the code.

### 4.2 Grids

**Theorem 0.3.2 (grid scans).** A scan that visits every cell of an $H \times W$ grid and looks at its at most 8 neighbours does at most $9HW$ cell inspections. If every neighbour $(r + \Delta r, c + \Delta c)$ is used only after checking $0 \le r + \Delta r < H$ and $0 \le c + \Delta c < W$, no inspection reads outside the grid.

*Proof.* Each of the $HW$ cells is visited once and inspects itself and at most 8 neighbours, so at most $9HW$ inspections. A cell is inside the grid exactly when its row is in $[0, H)$ and its column in $[0, W)$, which is what the check tests. $\square$

:::note[This proof needs]
1. Each cell is visited a constant number of times.
2. Every neighbour access is guarded by the bounds check (or the grid is padded with a border of dummy cells).
:::

**Direction arrays.** Writing the 4 or 8 directions as arrays turns eight copied `if` blocks into one loop, so a typo in one direction cannot hide. Turning right is moving to the next direction: `d = (d + 1) % 4`; turning left is `d = (d + 3) % 4` (adding 3 instead of subtracting 1 keeps the value non-negative, since `%` of a negative number is negative in C++, Theorem 0.1.4).

### 4.3 One-pass string processing

**Theorem 0.3.3 (one-pass scans).** Suppose the answer for a string $s$ is $g(\mathit{st}_n)$, where $\mathit{st}_0$ is a fixed starting state and $\mathit{st}_{i+1} = \mathrm{update}(\mathit{st}_i, s_i)$. Then the scan

```
st = start
for i = 0 .. n-1: st = update(st, s[i])
answer g(st)
```

computes the answer in $n$ updates, and after step $i$ the variable `st` equals $\mathit{st}_{i+1}$, the state of the prefix $s_0 \dots s_i$.

*Proof.* By induction on $i$: before the loop `st` $= \mathit{st}_0$; if `st` $= \mathit{st}_i$ before step $i$, the update makes it $\mathit{st}_{i+1}$. After the last step it is $\mathit{st}_n$. $\square$

:::note[This proof needs]
1. A state that summarises the prefix read so far: the rest of the answer depends on the prefix only through this state.
2. An update rule that computes the new state from the old state and the next character alone.
:::

**Example: bracket sequences.** For a string of `(` and `)`, the state "current depth" (opens minus closes so far) decides validity: the string is a valid bracket sequence exactly when the depth never goes below 0 and ends at 0. Section 6 has the code and a proof.

### 4.4 Case analysis

**Theorem 0.3.4 (case analysis).** If the cases $C_1, \dots, C_k$ together contain every allowed input, and on each case $C_j$ the rule used for it gives the correct answer, then the program is correct on every input.

*Proof.* Any allowed input lies in some case $C_j$ (the cases cover everything), and the rule for $C_j$ is correct on it. $\square$

:::note[This proof needs]
1. The cases cover every input allowed by the constraints, including the boundaries (equal values, zero, the smallest $n$).
2. Each case's rule is proved for every input in that case.
:::

**In practice.** Write the cases as a list before coding, and check the boundaries between them: does "$x < y$" or "$x \le y$" decide which case an input with $x = y$ falls into, and is that case's rule right for it? A brute force on small inputs (Section 6) is the best check that no case is missing.

### State after T steps, with cycle detection (Theorem 0.3.1)

<Code code={cycleSteps} lang="cpp" title="cycle-steps/solution.cpp" />

**How it works.** `order[i]` records the state after `i` steps and `firstSeen[s]` the step at which state `s` first appeared. The loop follows the process. If it reaches step `t` first, the current state is the answer. Otherwise it meets a state seen before: that is the first repeat $x_\mu = x_{\mu + \lambda}$, with `mu = firstSeen[s]` and `lambda = step - mu`, and Theorem 0.3.1 gives the answer as `order[mu + (t - mu) % lambda]`. At most $K + 1$ steps are taken, whatever $T$ is.

**C++ details explained.**
- `for (long long step = 0;; step++)` has no stopping condition between the semicolons, so it repeats until a `return` inside the body ends the program.
- `vector<long long> firstSeen(k, -1)` fills all `k` entries with $-1$, meaning "not seen yet".

**Tested.** Stress-tested against a brute force that takes all $T$ steps, on 5000 random inputs ($K \le 8$, $T \le 60$, including $T = 0$ and states that point to themselves), plus 4 fixed tests including $T = 10^{18}$ on a cycle of length 3 (checked by hand: $10^{18} \bmod 3 = 1$).

**Alternative formulation.** Instead of storing `order`, after finding $\mu$ and $\lambda$ restart from $x$ and take $\mu + (T - \mu) \bmod \lambda$ steps. Same result and the same $O(K)$ cost, with less memory.

### A robot with a direction array (Theorem 0.3.2)

<Code code={robotWalk} lang="cpp" title="robot-walk/solution.cpp" />

**How it works.** Directions are numbered clockwise: 0 up, 1 right, 2 down, 3 left. Turning right adds 1, turning left adds 3 (both modulo 4). A forward move computes the target cell from `dr[d]` and `dc[d]`, and moves only if the target is inside the grid and not a wall.

**C++ details explained.**
- `const int dr[4] = {-1, 0, 1, 0};` is a fixed array of four values that cannot be changed.
- `vector<string> g(h);` holds the grid as `h` strings; `g[r][c]` is the character in row `r`, column `c`.
- In `nr >= 0 && nr < h && nc >= 0 && nc < w && g[nr][nc] != '#'`, C++ evaluates `&&` from left to right and stops at the first false condition, so `g[nr][nc]` is read only when the cell is inside the grid. The order of the conditions matters.

**Tested.** Stress-tested against a brute force that names every direction and surrounds the grid with a border of walls, on 5000 random grids up to $5 \times 5$ with up to 15 commands, plus 3 fixed tests (walls, a $1 \times 1$ grid, edges).

**Alternative formulation.** Pad the grid with a border of `#` cells (as the brute force does): then every neighbour of a real cell exists, and only the wall check is needed. It costs two extra rows and columns.

### Counting the 8 neighbours (Theorem 0.3.2)

<Code code={neighbourCount} lang="cpp" title="neighbour-count/solution.cpp" />

**How it works.** For each free cell, two loops over `dr` and `dc` from $-1$ to 1 visit the 9 cells of the $3 \times 3$ square around it; the centre is skipped, and every other cell is counted if it is inside the grid and holds a mine. The result is written into a copy `out`, so the counts do not disturb the grid still being read.

**C++ details explained.**
- `vector<string> out = g;` makes an independent copy of the grid.
- `char('0' + mines)` turns a count from 0 to 8 into the digit character, since digit characters have consecutive codes.
- `continue` skips the rest of the current loop iteration.

**Tested.** Stress-tested against a brute force that compares each cell with every mine in the grid, on 5000 random grids up to $5 \times 5$ with random mine density, plus 3 fixed tests (a pattern with mines in the middle, a single free cell, a grid full of mines).

**Alternative formulation.** Loop over the mines instead: for each mine, add 1 to each of its free neighbours. Same $O(HW)$ cost.

### One pass over a bracket string (Theorem 0.3.3)

<Code code={bracketsCode} lang="cpp" title="brackets/solution.cpp" />

**How it works.** The state is `depth`, the number of unmatched `(` so far. The string is valid exactly when `depth` never drops below 0 and ends at 0. *Proof:* if `depth` goes below 0 at some `)`, that `)` has no `(` before it left to match, and nothing later can supply one; if `depth` ends above 0, some `(` is never closed. Conversely, if `depth` stays $\ge 0$ and ends at 0, match each `)` with the nearest unmatched `(` before it, which exists because `depth` was at least 1 just before; every bracket gets matched. The largest value of `depth` is the deepest nesting.

**C++ details explained.** `(ch == '(') ? 1 : -1` is 1 for an opening bracket and $-1$ for a closing one.

**Tested.** Stress-tested against a brute force that repeatedly deletes every adjacent `()` pair (the depth is the number of rounds), on 5000 random strings (half of them valid by construction), plus 4 fixed tests including `)(` (depth returns to 0 but goes negative first) and `(((`.

**Alternative formulation.** Use a stack (topic 0.6) and push each `(`, pop at each `)`. It does the same work; the counter is enough here because there is only one kind of bracket.

### Cases for two intervals (Theorem 0.3.4)

<Code code={intervalCases} lang="cpp" title="interval-cases/solution.cpp" />

**How it works.** Points in both intervals are exactly those in $[\max(a, c), \min(b, d)]$. Three cases cover every input: this shared part is empty ($lo > hi$), a single point ($lo = hi$), or a segment of positive length ($lo < hi$). Each case prints its answer.

**C++ details explained.** None beyond earlier templates.

## 7. Bug catalogue

Each bug was made by changing one line of a template from Section 6 and running `scripts/stress.sh` on the broken copy. The input shown is the first one the script found (for the crash, the first failing input of the same generator).

### Bug: forgetting the part before the cycle

Template: state after T steps.

```cpp
cout << order[t % lambda] << "\n";
```

Input:

```
4 0 37
2 3 3 1
```

Wrong output `2`, correct output `1`. From state 0 the process goes $0 \to 2 \to 3 \to 1 \to 3 \to 1 \dots$: the cycle is $3, 1$ ($\lambda = 2$) and starts after $\mu = 2$ steps. `t % lambda` treats the sequence as if it were periodic from the start.

**Fix:** `order[mu + (t - mu) % lambda]` (Theorem 0.3.1, part 3): count the steps inside the cycle only after the cycle has been entered.

### Bug: turning left with `- 1`

Template: robot with a direction array.

```cpp
else if (ch == 'L') d = (d - 1) % 4;
```

Input:

```
1 5 0 4
##...
FFFRFFLFLFLFL
```

Wrong output `0 4`, correct output `0 3`. After turning right and then left, `d` goes from 1 to 0, and the next left turn computes `(0 - 1) % 4`, which is $-1$ in C++ (the remainder takes the sign of the left side, Theorem 0.1.4). `dr[-1]` reads outside the array: the program's behaviour is undefined, and here the robot never moves left.

**Fix:** `(d + 3) % 4`, which is the same turn and never negative.

### Bug: reading the cell before checking the bounds

Template: robot with a direction array.

```cpp
if (g[nr][nc] != '#' && nr >= 0 && nr < h && nc >= 0 && nc < w) {
```

Input: the same as the previous bug.

Wrong output: the program crashes (segmentation fault). Correct output `0 3`. The robot starts in row 0 facing up, so the first `F` targets row $-1$; `g[-1]` is read before the bounds are checked.

**Fix:** check the bounds first. `&&` stops at the first false condition, so the order of the conditions decides whether the out-of-range read happens (Theorem 0.3.2, condition 2).

### Bug: checking only the final depth

Template: bracket string. The line `if (depth < 0) ok = false;` is removed.

Input: `)(()()))((`

Wrong output `YES 1`, correct output `NO`. The depth ends at 0, but it went negative at the very first character: a `)` with nothing open before it.

**Fix:** keep the state check at every step. The state must capture every condition of validity, including the ones that can fail in the middle (Theorem 0.3.3, condition 1).

### Bug: touching intervals counted as disjoint

Template: cases for two intervals.

```cpp
if (lo >= hi) cout << "DISJOINT\n";
```

Input: `8 11 11 11`

Wrong output `DISJOINT`, correct output `TOUCH`. The second interval is the single point 11, which lies in the first; the shared part is $[11, 11]$ with $lo = hi$, which belongs to the TOUCH case.

**Fix:** `lo > hi`. A boundary input must fall into exactly the case whose rule is right for it (Theorem 0.3.4, condition 1).

### Not a bug: counting the cell itself among its neighbours

Removing `if (dr == 0 && dc == 0) continue;` from the neighbour count passes all 5000 tests. It is not a weak generator: the program counts only free cells, and a free cell is never a mine, so including it adds 0. The line documents the intent; in a variant where mines also get a count, it would matter.

## 8. Worked examples

### Example 1: Cross

[AtCoder Beginner Contest (ABC) 300, problem C: Cross](https://atcoder.jp/contests/abc300/tasks/abc300_c). In short: an $H \times W$ grid ($3 \le H, W \le 100$) of `#` and `.` is made of diagonal crosses. A cross of size $n$ centred at $(a, b)$ is the centre plus the four diagonal arms $(a \pm d, b \pm d)$ for $1 \le d \le n$, all `#`, and at least one of the four cells at distance $n + 1$ is `.` (cells outside the grid count as `.`). Cells of different crosses never share even a corner. Print how many crosses there are of each size $1, \dots, \min(H, W)$.

#### Step 1: Constraints → budget

$HW \le 10^4$ cells, and an arm is at most $\min(H, W)/2 = 50$ cells long. Anything up to $HW \cdot 50 = 5 \cdot 10^5$ cell inspections is far inside the budget. The counts are at most $10^4$, so `int` is fine.

#### Step 2: Question form → candidate tools

The input is a grid of `#` and `.`, and the definition talks about diagonal neighbours and cells outside the grid: grid processing (Theorem 0.3.2). A second candidate is to follow the definition literally: for every cell and every $n$, check all $4n + 1$ cells. It also fits ($10^4 \cdot 50 \cdot 200 = 10^8$ is close, but fine), and it is what the brute force does.

#### Step 3: Property check → decision

For each centre, the size is the number of steps the four arms can be extended together. Growing from $d = 1$ and stopping at the first $d$ where some arm cell is `.` gives exactly $n$, and the cells outside the grid are handled by one helper that returns "not black" for them. The remaining question is how to recognise a centre. A cell that is not a centre is either `.` or an arm cell at distance $d \ge 1$; its four diagonal neighbours are $(a + d \pm 1, b \pm d \pm 1)$-type cells, and at most two of them lie on its own cross (row offset and column offset must be equal in size). Cells of other crosses never touch it. So only a centre has all four diagonal neighbours black. Decision: scan every cell, grow the arms, and count a cross when the size is at least 1.

#### Step 4: Proof for this problem

Take any cell. If it is a centre of a cross of size $n$, the loop extends while all four cells at distance $\text{size} + 1$ are black; by the definition this holds for $\text{size} = 0, \dots, n - 1$ and fails at $\text{size} = n$, so the loop stops with $\text{size} = n$ and the cross is counted once, under $n$. If it is not a centre, Step 3 shows that some diagonal neighbour is not black, so the loop stops at $\text{size} = 0$ and nothing is counted. Every access goes through `black`, which checks the bounds first (Theorem 0.3.2). The loop inspects at most $4 \cdot 51$ cells per cell, about $2 \cdot 10^6$ in total.

#### Step 5: Code

<Code code={example1} lang="cpp" title="example-1/solution.cpp" />

**C++ details explained.** `auto black = [&](int r, int c) { … };` is a *lambda*, a small function written inside `main`; `[&]` lets it read `g`, `h` and `w` from the surrounding code. The `&&` in its body evaluates left to right and stops at the first false condition, so `g[r][c]` is read only after all four bounds checks have passed. Tested on the three samples from the problem page, on a $15 \times 20$ grid with crosses touching the borders (expected counts from the brute force), and on 5000 random grids of non-touching crosses up to size 3 (up to $12 \times 12$) against a brute force that checks the definition literally for every cell and size.

#### Step 6: Alternative approach

Pad the grid with a border of `.` that is as wide as the longest possible arm, so that every access is inside the array and no bounds check is needed (the padding variant of Theorem 0.3.2). It works, but the border must be 50 cells wide here, and an off-by-one in the padding width brings back the out-of-range read. The lambda with the check is shorter and safer.

### Example 2: String Delimiter

[AtCoder Beginner Contest (ABC) 282, problem C: String Delimiter](https://atcoder.jp/contests/abc282/tasks/abc282_c). In short: a string $S$ ($N \le 2 \cdot 10^5$) of lowercase letters, commas and an even number of double quotes. The characters from the 1st to the 2nd quote, from the 3rd to the 4th, and so on, are *enclosed*. Replace every comma that is not enclosed by a dot.

#### Step 1: Constraints → budget

$N = 2 \cdot 10^5$. One pass is $2 \cdot 10^5$ steps. Counting the quotes before each comma separately is $O(N^2) = 4 \cdot 10^{10}$ in the worst case: too slow.

#### Step 2: Question form → candidate tools

A string is transformed character by character, and whether a comma changes depends on what came before it: a one-pass scan (Theorem 0.3.3). The other candidate is the definition taken literally (count the quotes before each comma), which is the brute force.

#### Step 3: Property check → decision

What do we need to know about the prefix before a comma? Only whether an odd number of quotes has been read, that is whether we are between an opening and a closing quote. That is one boolean, and it changes only at a quote. Decision: one pass with a flag `inside`.

#### Step 4: Proof for this problem

Let $\mathit{st}_i$ be "the number of quotes among the first $i$ characters is odd". Then $\mathit{st}_0$ is false and $\mathit{st}_{i+1}$ is $\mathit{st}_i$ flipped when $s_i$ is a quote, unchanged otherwise. A comma at position $i$ is enclosed exactly when it lies between the $(2k-1)$-th and $(2k)$-th quote for some $k$, that is when an odd number of quotes comes before it, that is when $\mathit{st}_i$ is true. The scan keeps exactly $\mathit{st}_i$ when it reaches position $i$ (Theorem 0.3.3), so it changes exactly the commas that are not enclosed. It runs in $O(N)$.

#### Step 5: Code

<Code code={example2} lang="cpp" title="example-2/solution.cpp" />

**C++ details explained.** `'"'` is the character literal for a double quote; inside single quotes it needs no backslash. `for (char& ch : s)` takes each character *by reference*, so `ch = '.'` changes the string itself; without the `&`, it would change a copy. `inside = !inside` flips a boolean. Tested on the three samples from the problem page and on 5000 random strings of up to 13 characters against a brute force that counts the quotes before each comma.

#### Step 6: Alternative approach

Find the positions of all quotes first, then for each pair $(q_{2k-1}, q_{2k})$ mark the characters between them as enclosed, and finally replace the unmarked commas. Each character is marked at most once, so this is also $O(N)$, but it needs an extra array and two passes where one flag is enough.
