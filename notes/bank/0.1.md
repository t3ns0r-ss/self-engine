Solution notes for every bank problem (bank plan Section 7.4). Not shown on the site. † = Codeforces problem checked through the official API only (title, rating, tags); the statement could not be opened from the build environment, so the idea below needs a spot-check on the page.

## cses-1068 Weird Algorithm (tier 1, pattern overflow-64bit, set practice)
- Budget: n ≤ 10^6; the sequence is short, so plain simulation is fine.
- Idea: Loop while n ≠ 1, printing n; even → n/2, odd → 3n+1. Store n in long long: intermediate values for starting values below 10^6 pass 2^31.
- Techniques: 0.1
- Needs this topic because: the only trap is the 32-bit overflow of 3n+1.
- Tier reasoning: first problem of CSES Introductory; warm-up.

## cses-1083 Missing Number (tier 1, pattern overflow-64bit, set practice)
- Budget: n ≤ 2·10^5 → O(n).
- Idea: Answer = n(n+1)/2 − (sum of the given numbers). n(n+1)/2 reaches 2·10^10, so compute it in long long.
- Techniques: 0.1
- Needs this topic because: the sum overflows int.
- Tier reasoning: CSES Introductory, very high solve count.

## ac-abc079_b Lucas Number (tier 1, pattern overflow-64bit, set practice)
- Budget: N ≤ 86 → a direct loop.
- Idea: Iterate L_i = L_{i−1} + L_{i−2} from L_0 = 2, L_1 = 1 in long long; the answer is below 10^18.
- Techniques: 0.1
- Needs this topic because: values pass 2^31 long before N = 86.
- Tier reasoning: ABC B.

## ac-abc149_b Greedy Takahashi (tier 1, pattern overflow-64bit, set practice)
- Budget: A, B, K ≤ 10^12 → O(1) (a loop of K steps is too slow).
- Idea: Takahashi loses min(A, K); the rest r = K − min(A, K) comes from Aoki: he loses min(B, r). All in long long.
- Techniques: 0.1
- Needs this topic because: values up to 10^12 need 64-bit; reading into int silently corrupts them.
- Tier reasoning: ABC B.

## ac-abc158_b Count Balls (tier 1, pattern overflow-64bit, set practice)
- Budget: N, A + B ≤ 10^18 → O(1).
- Idea: Full blocks q = N / (A+B) give q·A blue balls; the partial block adds min(N mod (A+B), A). q·A ≤ N fits in long long.
- Techniques: 0.1
- Needs this topic because: 64-bit arithmetic plus integer division and remainder.
- Tier reasoning: ABC B.

## lc-arranging-coins Arranging Coins (tier 2, pattern overflow-64bit, set practice)
- Budget: n ≤ 2^31 − 1; k rows use k(k+1)/2 coins, so k ≤ about 65536: a loop is fine.
- Idea: Increase k while (k+1)(k+2)/2 ≤ n, computing in long long. In int, k(k+1)/2 overflows near the top of the range.
- Techniques: 0.1
- Needs this topic because: the product overflows 32-bit near n = 2^31 − 1.
- Tier reasoning: LeetCode Easy, but the overflow at the top of the range catches many.

## cses-1094 Increasing Array (tier 2, pattern overflow-64bit, set practice)
- Budget: n ≤ 2·10^5 → O(n).
- Idea: Scan left to right keeping the running maximum m; add m − x_i whenever x_i < m. The total can reach about 2·10^14: long long.
- Techniques: 0.1
- Needs this topic because: the answer overflows int; the scan itself is direct.
- Tier reasoning: CSES Introductory, high solve count; the one-pass idea is a small step above tier 1.

## lc-reverse-integer Reverse Integer (tier 3, pattern overflow-64bit, set practice)
- Budget: one 32-bit integer → O(number of digits).
- Idea: Pop digits with x % 10 and x / 10 (C++ truncates toward zero, so negatives work digit by digit). Before r = 10r + d, check r > INT_MAX/10 or r < INT_MIN/10 (and the last-digit edge) and return 0.
- Techniques: 0.1
- Needs this topic because: the whole problem is detecting 32-bit overflow before it happens, without a wider type.
- Tier reasoning: LeetCode Medium.

## cf-1613A Long Comparison (tier 3, pattern overflow-64bit, set practice) †
- Budget: t test cases, x ≤ 10^6 and p ≤ 10^6 (recalled) → O(1) per test.
- Idea: x·10^p overflows any type. Move zeros so both numbers have the same digit count (subtract the smaller p from both, then pad x with zeros only while the length is ≤ 7), then compare; if digit counts (len(x) + p) differ, the longer is larger.
- Techniques: 0.1
- Needs this topic because: the naive product overflows; the fix is reasoning about magnitude instead.
- Tier reasoning: rating 900, Phase 0 tier 3 (800–1000).

## ac-abc239_b Integer Division (tier 1, pattern integer-rounding, set practice)
- Budget: |X| ≤ 10^18 → O(1).
- Idea: C++ `/` truncates toward zero, so for negative X with nonzero remainder subtract 1: floor = X/10 − (X % 10 < 0 ? 1 : 0). Doubles are wrong near 10^18.

- Needs this topic because: floor of negatives is the classic integer-division trap.
