## lc-repeated-dna-sequences Repeated DNA Sequences (tier 2, pattern distinct-by-hash, set reserved, for lookalike)
- Budget: length ≤ 10^5, fixed length 10.
- Idea: Encode each length-10 window in 20 bits (2 bits per letter) with a rolling update; count windows in a hash map and report those seen twice.
- Techniques: 6.1
- Needs this topic because: look-alike partner of Longest Duplicate Substring: the length is fixed, so a set of window codes suffices, with no search over lengths.
- Tier reasoning: LeetCode Medium.

## lc-longest-duplicate-substring Longest Duplicate Substring (tier 4, pattern hash-length-search, set reserved, for lookalike)
- Budget: length ≤ 3·10^4.
- Idea: If a duplicate of length L exists, one of length L − 1 does. Binary search L; check with rolling hashes of all windows in a hash set (two moduli or a 64-bit modulus).
- Techniques: 6.1, 1.4
- Needs this topic because: look-alike partner of Repeated DNA Sequences: the length is unknown, so binary search over lengths with hash checks.
- Tier reasoning: LeetCode Hard.

## cf-271D Good Substrings (tier 2, pattern distinct-by-hash, set practice) †
- Budget: |s| ≤ 1500 (recalled).
- Idea: (recalled) For each start, extend the end while the number of bad letters ≤ k, adding each substring's hash (rolling) to a set. Answer = set size. O(n²) substrings; double hashing to avoid collisions (or a trie).
- Techniques: 6.1
- Needs this topic because: count distinct substrings by hash.
- Tier reasoning: rating 1800.

## cf-514C Watto and Mechanism (tier 3, pattern distinct-by-hash, set practice) †
- Budget: total length ≤ 6·10^5, letters a–c (recalled).
- Idea: (recalled) Store the hash of every memory string in a set. For a query, try changing each position to each of the other two letters, updating the hash in O(1) (subtract old c·p^i, add new); YES if any variant is in the set.
- Techniques: 6.1
- Needs this topic because: O(1) hash updates for one-character edits.
- Tier reasoning: rating 2000.

## lc-distinct-echo-substrings Distinct Echo Substrings (tier 4, pattern distinct-by-hash, set reserved, for review)
- Budget: length ≤ 2000.
- Idea: For each start and each half length L, compare the two halves by hash in O(1); insert the hash of qualifying substrings (a + a) into a set. O(n²).
- Techniques: 6.1
- Needs this topic because: O(1) substring comparison plus distinct counting by hash.
- Tier reasoning: LeetCode Hard.

## cf-154C Double Profiles (tier 4, pattern distinct-by-hash, set practice) †
- Budget: n, m ≤ 10^6 (recalled).
- Idea: (recalled) Hash each vertex's neighbour set (sum of random 64-bit values per neighbour). Doubles are pairs with equal hashes (non-adjacent), or equal hashes after adding the vertex itself (adjacent). Count equal values by sorting.
- Techniques: 6.1, 1.1
- Needs this topic because: hashing sets to group equal ones.
- Tier reasoning: rating 2300.

## cses-1110 Minimal Rotation (tier 3, pattern substring-compare, set practice)
- Budget: n ≤ 10^6.
- Idea: Double the string. Compare two rotations by binary search on their longest common prefix with hashes, then one character; keep the smallest start. (Booth's algorithm also works.)
- Techniques: 6.1
- Needs this topic because: lexicographic comparison of substrings via hash + binary search.
- Tier reasoning: CSES string section.

## lc-count-beautiful-splits-in-an-array Count Beautiful Splits in an Array (tier 3, pattern substring-compare, set practice)
- Budget: n ≤ 5000.
- Idea: For each split (i, j), check whether nums1 is a prefix of nums2 or nums2 a prefix of nums3 by O(1) hash comparison of the relevant blocks. O(n²).
- Techniques: 6.1
- Needs this topic because: O(1) block equality checks inside a double loop.
- Tier reasoning: LeetCode Medium.

## cf-1200E Compress Words (tier 3, pattern substring-compare, set practice) †
- Budget: total length ≤ 10^6 (recalled).
- Idea: (recalled) Merging word w into the result, try overlaps from min(|w|, |result|) down: the longest k with result's last k = w's first k, compared by hashes (only the last |w| characters of the result matter). Append the rest.
- Techniques: 6.1
- Needs this topic because: prefix/suffix equality by hash, total work O(total length).
- Tier reasoning: rating 2000.

## cf-1056E Check Transcription (tier 3, pattern substring-compare, set practice) †
- Budget: |s| ≤ 10^5, |t| ≤ 10^6 (recalled).
- Idea: (recalled) Choose the length of r0 (r1's length follows). For each, walk s checking that all 0-blocks equal and all 1-blocks equal by hashes, and r0 ≠ r1. The number of valid lengths times |s| is about |t|.
- Techniques: 6.1
- Needs this topic because: many equality checks between substrings.
- Tier reasoning: rating 2100.

## cf-1003F Abbreviation (tier 4, pattern substring-compare, set practice) †
- Budget: n ≤ 300 words (recalled).
- Idea: (recalled) Map words to ids. lcp[i][j] = number of equal consecutive words from i and j (DP from the end). For each segment [i, i + len), count non-overlapping repeats greedily using lcp; saving = count·(total letters − 1 per word ...) and take the best.
- Techniques: 6.1, 3.2
- Needs this topic because: comparing word sequences quickly (ids act as a hash).
- Tier reasoning: rating 2200.

## lc-find-substring-with-given-hash-value Find Substring With Given Hash Value (tier 4, pattern substring-compare, set practice)
- Budget: length ≤ 2·10^4.
- Idea: The hash weights powers from the left, so roll from the right end: h = h·p + s[i], dropping s[i + k]·p^k. Keep the leftmost window with the target value.
- Techniques: 6.1
- Needs this topic because: rolling hash direction matters when division is not available.
- Tier reasoning: LeetCode Hard.

## lc-longest-chunked-palindrome-decomposition Longest Chunked Palindrome Decomposition (tier 4, pattern substring-compare, set practice)
- Budget: length ≤ 1000.
- Idea: Greedy from both ends: take the shortest prefix that equals the suffix of the remaining string (hash comparison), count 2, and continue inside; the middle counts 1.
- Techniques: 6.1, 1.5
- Needs this topic because: repeated prefix/suffix equality checks.
- Tier reasoning: LeetCode Hard.

## lc-maximum-deletions-on-a-string Maximum Deletions on a String (tier 4, pattern substring-compare, set reserved, for review)
- Budget: length ≤ 4000.
- Idea: dp[i] = max operations on s[i..]. dp[i] = 1 + max dp[i + L] over L with s[i..i+L) = s[i+L..i+2L), checked in O(1) via an LCP table (lcp[i][j] from the end) or hashes. O(n²).
- Techniques: 6.1, 3.2
- Needs this topic because: O(1) equality checks inside a DP.
- Tier reasoning: LeetCode Hard.

## cf-898F Restoring the Expression (tier 4, pattern substring-compare, set practice) †
- Budget: length ≤ 10^6 (recalled).
- Idea: (recalled) The length of c is close to max(|a|, |b|): try the few lengths around |s|/3 positions. Use a polynomial hash with base 10 so the hash is the number mod p; check hash(a) + hash(b) = hash(c) and no leading zeros.
- Techniques: 6.1
- Needs this topic because: base-10 hashing checks a numeric identity.
- Tier reasoning: rating 2300.

## ac-abc284_f ABCBAC (tier 5, pattern substring-compare, set practice)
- Budget: N ≤ 10^6.
- Idea: For each i, f_i(S) = T requires T[0..i) + T[i+N..2N) to equal S and T[i..i+N) to equal reverse(S). With hashes of T and of reversed T, check each i in O(1).
- Techniques: 6.1
- Needs this topic because: O(1) comparisons with forward and reverse hashes.
- Tier reasoning: ABC F.

## cf-580E Kefa and Watch (tier 5, pattern substring-compare, set practice) †

- Idea: Binary search len; for each window hash remember its first start, and check whether a later start is ≥ first + len (non-overlapping). An O(N²) LCP DP also works.

## lc-longest-common-subpath Longest Common Subpath (tier 4, pattern hash-length-search, set reserved, for review)
- Budget: Σ path lengths ≤ 10^5, n ≤ 10^5 cities.
- Idea: Binary search L. For each path collect the set of hashes of its length-L windows; intersect across paths; feasible if non-empty. Use double hashing (anti-hash tests exist).
- Techniques: 6.1, 1.4
- Needs this topic because: length search over many sequences.
- Tier reasoning: LeetCode Hard.

## cf-1326D2 Prefix-Suffix Palindrome (Hard version) (tier 2, pattern palindrome-hash, set practice) †
- Budget: Σ |s| ≤ 10^6 (recalled).
- Idea: (recalled) Strip the longest k with s[0..k) = reverse of s's last k characters. In the middle, take the longer of its longest palindromic prefix and longest palindromic suffix (check by forward/reverse hashes, or prefix function).
- Techniques: 6.1

## cses-1111 Longest Palindrome (tier 3, pattern palindrome-hash, set practice)
- Budget: n ≤ 10^6.
- Idea: For odd and even centres separately, palindrome existence is monotone in length: binary search the longest; check by comparing a substring's forward hash with the reverse hash. (Manacher is the O(n) alternative.)
- Techniques: 6.1, 1.4
- Needs this topic because: palindrome test as a hash comparison.

## cses-3138 All Palindromes (tier 3, pattern palindrome-hash, set reserved, for drill)

- Idea: The longest palindrome ending at i is at most 2 longer than the one ending at i − 1. Try lengths from ans[i − 1] + 2 downward with O(1) hash checks; the total number of checks is O(n).
- Techniques: 6.1
- Needs this topic because: amortised palindrome checks by hash.
- Tier reasoning: CSES string section.

## cses-2420 Palindrome Queries (tier 4, pattern palindrome-hash, set reserved, for review)
- Budget: n, m ≤ 2·10^5.
- Idea: Keep forward and reverse polynomial hashes in Fenwick trees (point update = add the change times the power). A substring is a palindrome iff its forward hash equals its reverse hash after aligning powers.
- Techniques: 6.1, 5.2
- Needs this topic because: palindrome checks under updates.
- Tier reasoning: CSES string section, later.

- Idea: (recalled) deg(i) = deg(i/2) + 1 if prefix i is a palindrome, else 0. Check each prefix with a forward hash and a reverse hash maintained incrementally (no arrays of powers needed beyond one running power).
- Techniques: 6.1, 3.2
- Needs this topic because: palindrome-prefix test in O(1) each.

- Budget: n ≤ 10^5.
- Idea: A post-order DFS writes each subtree's string as one contiguous block. Build the full post-order string once; each node's string is a range, tested by forward vs reverse hash (or Manacher).
- Techniques: 6.1, 4.5

- Idea: Segment tree (or Fenwick) of forward and reverse hashes; a point update changes both; [L, R] is a palindrome iff the two hashes agree after aligning powers.
- Techniques: 6.1, 5.3

## lc-shortest-palindrome Shortest Palindrome (tier 4, pattern palindrome-hash, set reserved, for checkpoint)
- Budget: length ≤ 5·10^4.
- Idea: Find the longest palindromic prefix: maintain forward and reverse rolling hashes of s[0..i] and record the last i where they match. Prepend the reverse of the remaining suffix. (The prefix function on s + '#' + reverse(s) also works.)
- Techniques: 6.1
- Needs this topic because: palindromic-prefix test via forward/reverse hashes.
- Tier reasoning: LeetCode Hard.
