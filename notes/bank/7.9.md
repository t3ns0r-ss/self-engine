## cses-1694 Download Speed (tier 1, pattern flow-cut, set practice)
- Budget: n ≤ 500, m ≤ 1000, c ≤ 10^9: Dinic runs in well under a second; the flow can reach 10^12, so 64-bit.
- Idea: Directed edges with capacity c; the maximum flow from 1 to n is the answer (Theorem 7.9.1). Dinic (Theorem 7.9.4). Repeated edges between the same pair are fine: add each as its own edge.
- Techniques: 7.9, 4.1
- Needs this topic because: The base case of the card: the value of a maximum flow.
- Tier reasoning: CSES graph section, the first flow problem; tier 1.

## cses-1695 Police Chase (tier 2, pattern flow-cut, set practice)
- Budget: n ≤ 500, m ≤ 1000: one maximum flow with unit capacities.
- Idea: Each two-way street becomes two directed edges of capacity 1. After the maximum flow, the source side is the set reachable from 1 in the residual graph; the streets between the source side and the rest form a minimum cut (Theorem 7.9.1). Print their number and the streets.
- Techniques: 7.9, 4.1
- Needs this topic because: Recovering the cut, not only its size.
- Tier reasoning: CSES graph section; needs the residual reachability step; tier 2.

## cses-1711 Distinct Routes (tier 2, pattern flow-cut, set practice)
- Budget: n ≤ 500, m ≤ 1000: unit capacities.
- Idea: Each teleporter is used at most once, so every edge has capacity 1 and the maximum flow from 1 to n is the number of days (Theorem 7.9.8, edge version). To print the routes, follow edges that carry flow from 1; a flow may contain cycles, which are skipped (the decomposition of the proof).
- Techniques: 7.9, 4.1
- Needs this topic because: Edge-disjoint paths and reading the paths back from a flow.
- Tier reasoning: CSES graph section; the paths must be printed; tier 2.

## cf-546E Soldier and Traveling (tier 3, pattern flow-cut, set practice) †
- Budget: n ≤ 100 cities, m ≤ 200 roads, counts ≤ 100: the network has about 200 vertices and 500 edges.
- Idea: (recalled) Every soldier stays in his city or moves along one road. Build source → city copy i (capacity a_i), copy i → target copy i and copy i → target copy j for each road i–j (capacity infinity), target copy j → sink (capacity b_j). The answer is YES exactly when the maximum flow equals the sum of a_i and the sum of b_j. The matrix of moves is read from the middle edges.
- Techniques: 7.9, 4.1
- Needs this topic because: A transport network with a feasibility check (flow equals both totals).
- Tier reasoning: Rating 2100, tier 3.

## ac-abc318_g Typical Path Problem (tier 4, pattern flow-cut, set practice)
- Budget: N, M ≤ 2·10^5: a unit-capacity network; Dinic is fast on it.
- Idea: A simple path from A through B to C exists exactly when two paths from B, one to A and one to C, share no vertex except B. Split every vertex into an entry and an exit with an edge of capacity 1 (Theorem 7.9.8), let the source be B and add a new sink with edges from A and from C of capacity 1; the answer is Yes when the flow is 2. Undirected edges are two directed edges.
- Techniques: 7.9, 4.1
- Needs this topic because: Vertex-disjoint paths by splitting, with a two-unit source.
- Tier reasoning: ABC G; tier 4.

## ac-abc259_g Grid Card Game (tier 4, pattern flow-cut, set practice)
- Budget: H, W ≤ 100: about 200 items and 10^4 pair edges; values up to 10^9, sums up to 10^13, 64-bit.
- Idea: Choose each row and each column, or not. A card with A ≥ 0 is lost exactly when neither its row nor its column is chosen; a card with A < 0 forbids choosing both and costs |A| for every chosen line through it. Rows: source side means chosen. Columns: source side means not chosen. Then a lost positive card is an edge column → row of capacity A, a forbidden pair is an edge row → column of infinite capacity, and each negative card adds |A| on the row to the sink and from the source to the column (Theorem 7.9.2). Answer = (sum of positive cards) − (minimum cut).
- Techniques: 7.9, 4.1
- Needs this topic because: Choose a side for every row and column; the flip of the meaning for the columns makes every interaction a cut edge.
- Tier reasoning: ABC G; tier 4.

## ac-abc193_f Zebraness (tier 4, pattern flow-cut, set practice)
- Budget: N ≤ 100: 10^4 cells and about 2·10^4 neighbour pairs; Dinic is fast.
- Idea: Flip the colour of every cell with i + j odd, so that 'different colours' becomes 'same colour'. Maximising the neighbouring pairs of different colours now means minimising the neighbouring pairs of different flipped colours: a minimum cut with black cells tied to the source and white cells tied to the sink (infinite capacity) and capacity 1 in both directions between neighbouring cells (Theorem 7.9.2). Answer = number of neighbouring pairs − minimum cut.
- Techniques: 7.9, 4.1
- Needs this topic because: Pay for separated pairs: the labelling form of the cut.
- Tier reasoning: ABC F, rated 2475; tier 4.

## cses-1709 Coin Grid (tier 2, pattern matching, set practice)
- Budget: n ≤ 100: a graph with 200 vertices and at most 10^4 edges.
- Idea: Every coin is an edge between its row and its column; a move removes a row or a column, so the moves must form a vertex cover. The minimum vertex cover of a bipartite graph equals the maximum matching (Theorem 7.9.7), and the cover is built from the alternating search; print it as the moves.
- Techniques: 7.9, 4.1
- Needs this topic because: König's theorem used to produce the cover itself.
- Tier reasoning: CSES graph section; the cover must be recovered; tier 2.

## cf-1423B Valuable Paper (tier 2, pattern matching, set practice) †
- Budget: n ≤ 10^4 airports and factories, m ≤ 10^5 roads, d ≤ 10^9: binary search over the sorted road lengths (about 17 steps), each a matching on up to 10^5 edges, so Kuhn is too slow and Dinic on the unit network is used.
- Idea: (recalled) Every factory must be joined to a different airport and the largest day count of the chosen roads is to be minimised. Binary search on D (topic 1.4): keep the roads with d ≤ D and test whether a perfect matching exists (Theorem 7.9.5, with Dinic). Print −1 when even all roads do not give one.
- Techniques: 7.9, 4.1, 1.4
- Needs this topic because: A matching test inside a binary search on the answer.
- Tier reasoning: Rating 1900, tier 2.

## cf-2026E Best Subsequence (tier 4, pattern matching, set practice) †
- Budget: n ≤ 100, a_i < 2^60: a bipartite graph of 100 elements and 60 bits.
- Idea: (recalled) The value of a subsequence is its size minus the number of set bits of its OR, which is its size plus the number of bits that are 0 in all chosen elements, minus 60. Join each element to the bits it has: a set of chosen elements and unused bits with no edge between them is an independent set, so the answer is the largest independent set minus 60. By König (Theorem 7.9.7) it is (n + 60) − (maximum matching) − 60 = n − maximum matching.
- Techniques: 7.9, 4.1, 1.7
- Needs this topic because: König's theorem applied to a bit-and-element graph.
- Tier reasoning: Rating 2500, tier 4.

## cf-1139E Maximize Mex (tier 4, pattern matching, set reserved, for lookalike) †
- Budget: n ≤ 5000 students, potion values ≤ 5000, d ≤ n days.
- Idea: (recalled) Each day one student per club may be picked; the values 0, 1, 2, … are matched to clubs, each value to a club that still has a student with that value. The answer for a day is the length of the longest prefix of values that can be matched. Process the days backwards, adding students, so that the matching only grows (Theorem 7.9.6).
- Techniques: 7.9, 4.1
- Needs this topic because: Items (clubs) with arbitrary lists of allowed slots (values): a matching, not a greedy.
- Tier reasoning: Rating 2400; reserved look-alike, tier 4.

- Idea: Colour the grid like a chessboard. A domino covers one black and one white cell, so the empty cells form a bipartite graph and the maximum number of dominoes is its maximum matching (Theorem 7.9.5); the placed tiles are the middle edges that carry flow.

## cf-1082G Petya and Graph (tier 4, pattern flow-cut, set reserved, for checkpoint) †
- Budget: n, m ≤ 1000: a network with n + m + 2 vertices.
- Idea: (recalled) Choose edges to take (gain w) and pay a_v for every endpoint vertex used. An edge may be taken only if both endpoints are bought: a maximum-weight closure (project selection). Source → edge item (capacity w), edge item → both endpoint items (infinite), endpoint item → sink (capacity a_v); answer = (sum of w) − (minimum cut) (Theorem 7.9.2).
- Techniques: 7.9, 4.1
- Needs this topic because: Project selection: choose a set closed under dependencies, maximising profit.

## cf-1198E Rectangle Painting 2 (tier 4, pattern matching, set reserved, for checkpoint) †
- Budget: n ≤ 10^9 but only m ≤ 50 black rectangles: compress the coordinates to at most 100 rows and 100 columns of cells.
- Idea: (recalled) Painting a rectangle white costs max(h, w); the cheapest cover of all black cells by rectangles is a set of full rows and full columns. Compressing the coordinates, each black rectangle joins its rows to its columns, and the cheapest choice is a minimum weighted vertex cover of a bipartite graph, a minimum cut (Theorem 7.9.2) whose weights are the lengths of the compressed lines.
- Techniques: 7.9, 4.1, 1.1
- Needs this topic because: A weighted bipartite vertex cover: König with weights is a cut.
- Tier reasoning: Rating 2500, tier 4.

## cf-311E Biologist (tier 3, pattern flow-cut, set reserved, for review) †

Dogs are items on side S (one type) or T (the other), a group is a closure item that needs all its dogs on its side, and pairs of dogs that must agree give infinite edges (Theorem 7.9.2). ## cf-387D George and Interesting Graph (tier 3, pattern matching, set reserved, for review) †

- Idea: (recalled) A graph is 'interesting' when one centre vertex is joined in both directions to every vertex and the rest has exactly one other out-edge and one other in-edge at every vertex. For each possible centre, count the edges that must be added or removed for the centre edges, then find the largest set of existing edges among the other vertices that can stay (each out-slot to at most one in-slot): a bipartite matching (Theorem 7.9.6); all other edits are paid one by one.

## cf-498C Array and Operations (tier 3, pattern flow-cut, set reserved, for drill) †
- Budget: n ≤ 100, m ≤ 100, a_i ≤ 10^9: factorise, then a network over prime factors.
- Idea: (recalled) An operation takes a given pair (i, j) with i + j odd, a common divisor v > 1 of both values, and divides both by v. Treat each prime separately: the pairs join an odd-position item and an even-position item, each with a stock of that prime (its exponent), and an operation moves one unit from both. A flow per prime with source → odd item (capacity exponent), pair edge (infinite), even item → sink (exponent); the answer is the sum of the flows over all primes (topic 2.1 for the factorisation).
- Techniques: 7.9, 4.1, 2.1
- Needs this topic because: Pairs between two sides with limited stock: a flow, repeated for each prime.
- Tier reasoning: Rating 2100, tier 3.

## cf-510E Fox And Dinner (tier 3, pattern flow-cut, set reserved, for drill) †
- Budget: n ≤ 200 foxes: a bipartite network of 200 vertices.
- Idea: (recalled) Seat the foxes at round tables of at least 3 so that every two neighbours have a prime sum of ages. A prime sum of two numbers means one is even and one is odd (as all ages are at least 1, the sum is at least 2, prime sums larger than 2 are odd). Every fox needs exactly two neighbours: a flow with source → even fox (2), even fox → odd fox when the sum is prime (1), odd fox → sink (2); it must saturate; the tables are the cycles of the chosen edges.
- Techniques: 7.9, 4.1, 2.1
- Needs this topic because: Every vertex has degree 2 in the chosen edges: a flow with capacity 2 at the ends.
- Tier reasoning: Rating 2300, tier 3.

## cf-808F Card Game (tier 4, pattern flow-cut, set reserved, for exam) †
- Budget: n ≤ 100 cards with power up to 1000, c up to 10^5 and level up to n (recalled); a sieve up to 2·10^5.
- Idea: (recalled) Find the smallest level limit L such that some set of cards of level at most L, with no two cards whose values c add up to a prime, has total power at least k. Binary search on L (topic 1.4); for a fixed L the question is the heaviest set with no conflicting pair. Two numbers have a prime sum only if one is odd and the other even (or both are 1, whose sum 2 is prime, so keep only the strongest card with c = 1). So the conflict graph is bipartite by parity of c, and the heaviest conflict-free set is the total power minus a minimum cut: source to every odd card and every even card to the sink with capacity equal to the power, and an edge of infinite capacity for every conflicting pair (Theorem 7.9.2). Compare with k; print −1 if even the largest L fails.
- Techniques: 7.9, 4.1, 1.4, 2.1
- Needs this topic because: Choosing a side for every item with a penalty for each conflicting pair, here the heaviest independent set of a bipartite graph.
- Tier reasoning: Rating 2400, the boundary of tiers 3 and 4; placed in tier 4. Recalled, so the exact rule of the statement (which pairs conflict, the role of level) should be spot-checked.
