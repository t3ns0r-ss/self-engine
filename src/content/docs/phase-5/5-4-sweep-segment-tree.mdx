## 1. Why this topic exists

Here is a small problem. A map shows $n = 50\,000$ rectangular fields with sides along the axes. The corners have coordinates up to $10^9$, and some fields overlap. How much land is there in all?

Adding the areas counts an overlap more than once. Marking every unit cell of the map needs up to $10^{18}$ cells. Taking away the overlaps by inclusion and exclusion needs a term for every set of fields, $2^{50\,000}$ of them. Checking every vertical strip against every field is about $2n \cdot n = 5 \cdot 10^9$ steps, which is about 50 seconds at $10^8$ steps per second.

The way out is to let a vertical line sweep across the map from left to right and to stop it only at the edges of the fields, at most $2n = 10^5$ places. Between two neighbouring stops nothing starts and nothing ends, so the land in that strip is its width times the covered height, and the covered height is the total length of the stretches of the $y$-axis that at least one active field covers. A tree over the $y$-axis, with a counter on its nodes, keeps that length up to date in $O(\log n)$ steps per stop. This is a **sweep line** over rectangles, and the tree makes each step cheap: $O(n \log n)$ in all.

The same sweep answers other questions: the point covered by the most rectangles (or by the largest total weight), and where it is; and, with a Fenwick tree in place of the counted tree, how many points lie in each of many rectangles, or how many horizontal and vertical segments cross. The skill of the topic is to decide what the tree must remember at each stop, and to get the ties right when several things happen at the same coordinate.

## 3. Definitions

- A **sweep line** is an imaginary vertical line that moves from left to right. The $x$-values where something starts or stops are the **events** of [topic 1.1](../../phase-1/1-1-sorting/); the sweep processes them in sorted order and keeps the current state of the thing that they change.
- Rectangles are written **half-open**: $[x_1, x_2) \times [y_1, y_2)$ contains the points with $x_1 \le x < x_2$ and $y_1 \le y < y_2$. A closed rectangle on integer points, $[x_1, x_2] \times [y_1, y_2]$, is the half-open $[x_1, x_2 + 1) \times [y_1, y_2 + 1)$.
- A **gap** is the half-open stretch $[Y_g, Y_{g+1})$ between two neighbouring values of the sorted, distinct $y$-values of all rectangle ends ([coordinate compression](../../phase-1/1-1-sorting/)). Every rectangle then covers whole gaps, and a gap is a leaf of the tree.
- The **counted-cover tree** is a segment tree over the gaps ([topic 5.3](../5-3-segment-tree/)) in which every node holds a counter and a covered length (Theorem 5.4.2).
- The **prefix count** $G(X, Y)$ of a set of points is the number of points with $x \le X$ and $y \le Y$.

In code, an area, a sum of weights or a count of crossings can pass $2 \cdot 10^9$, so it is a `long long` ([topic 0.1](../../phase-0/0-1-cpp-for-cp/)); a tree over $m$ gaps is kept in arrays of size $4m$.

## 4. Theory and proofs

### 4.1 The area of a union is a sum over strips

**Theorem 5.4.1 (area by sweep).** Let $R_1, \dots, R_n$ be rectangles $[x_1, x_2) \times [y_1, y_2)$ with $x_1 < x_2$ and $y_1 < y_2$. Let $X_0 < \dots < X_k$ be the distinct values among all $x_1$ and $x_2$, and let $Y_0 < \dots < Y_m$ be the distinct values among all $y_1$ and $y_2$; the gap $g$ is $[Y_g, Y_{g+1})$. For a strip $i$ (the range $X_i \le x < X_{i+1}$) let $c_i(g)$ be the number of rectangles with $x_1 \le X_i$, $X_{i+1} \le x_2$ and $y_1 \le Y_g$, $Y_{g+1} \le y_2$. Then the area of the union is
$$\sum_{i=0}^{k-1} (X_{i+1} - X_i) \cdot L_i, \qquad L_i = \sum_{g \,:\, c_i(g) > 0} (Y_{g+1} - Y_g),$$
and $c_i$ comes from $c_{i-1}$ by adding 1 to the gaps covered by every rectangle with $x_1 = X_i$ and subtracting 1 for every rectangle with $x_2 = X_i$, all of these events at $X_i$ applied before $L_i$ is read.

:::tip[In plain words]
Cut the picture into vertical strips at every edge. Inside one strip each rectangle either crosses it completely or not at all, so the covered height is the same everywhere in the strip, and the area is the sum of strip width times covered height.
:::

**A tiny instance.** Take the squares $[0,2) \times [0,2)$ and $[1,3) \times [1,3)$. The $x$-values are $0, 1, 2, 3$ and the $y$-values are $0, 1, 2, 3$, so there are three gaps. Strip $[0,1)$: only the first square is active, covering gaps 0 and 1, so $L = 2$. Strip $[1,2)$: both are active and cover gaps 0 to 2, so $L = 3$. Strip $[2,3)$: only the second, gaps 1 and 2, so $L = 2$. The area is $1 \cdot 2 + 1 \cdot 3 + 1 \cdot 2 = 7$.

**Proof.**
1. Between two neighbouring values $X_i < x < X_{i+1}$ no rectangle starts or stops, because every $x_1$ and $x_2$ is one of the $X$ values. So the rectangles that contain a point with that $x$ are the same for the whole strip: those with $x_1 \le X_i$ and $X_{i+1} \le x_2$.
2. A point $(x, y)$ of the strip with $y$ in gap $g$ lies in an active rectangle if and only if $y_1 \le y < y_2$. Every $y_1$ and $y_2$ is one of the $Y$ values, so this holds exactly when the rectangle contains the whole gap: $y_1 \le Y_g$ and $Y_{g+1} \le y_2$.
3. So the point is in the union if and only if $c_i(g) > 0$, and the covered part of the strip is a set of full gaps of total length $L_i$ for every $x$ of the strip.
4. The strip has width $X_{i+1} - X_i$, so the part of the union in it has area $(X_{i+1} - X_i) L_i$. The strips are disjoint, and no rectangle holds a point with $x < X_0$ or $x \ge X_k$, so the areas add up to the formula.
5. A rectangle is active in strip $i$ exactly when $x_1 \le X_i < x_2$. It is therefore added when the strip index reaches $x_1$ and removed when it reaches $x_2$, which gives $c_i = c_{i-1} + (\text{additions at } X_i) - (\text{removals at } X_i)$.
6. The counts $c_i$ describe the whole of strip $i$, so $L_i$ is read after every event at $X_i$ is applied, and not in the middle of them. This proves both statements of the theorem. $\square$

:::note[This proof needs]
1. Every rectangle covers whole gaps: the gaps are made from all $y_1$ and all $y_2$ (compress with both ends, not with one).
2. Rectangles are half-open in $x$ ($[x_1, x_2)$), and all events at one $x$ are applied before the covered length is read.
3. The quantity wanted in a strip depends only on the counts $c_i(g)$ (here, the covered length).
:::

<TheoremCode unit="5.4/thm-1" />

The first example is the tiny instance (steps 3 and 4). In the second, one square stops and the other starts at $x = 1$; the strip between those two events has width 0, so the order of the two events does not change the area (step 6). In the third, both copies add 1 to the same gaps, so the counts are 2, and the covered length is the same as for one copy.

**Why this is not yet fast.** The implementation above finds $L_i$ by looking at every gap, which is $O(n)$ for each of $2n$ events and $O(n^2)$ in all. For $n \le 2000$ that is fine; for $n = 5 \cdot 10^4$ it is $5 \cdot 10^9$ steps. The next theorem makes each event cost $O(\log n)$.

### 4.2 A counter on tree nodes gives the covered length

**Theorem 5.4.2 (counted-cover tree).** A segment tree over the gaps $0, \dots, m-1$ (gap $g$ has length $w_g$) holds, for every node $v$, a counter $\mathrm{count}_v$ and a length $\mathrm{inside}_v$, and $\mathrm{whole}_v$ is the total length of the gaps below $v$. The rule is
$$\mathrm{inside}_v = \begin{cases} \mathrm{whole}_v & \text{if } \mathrm{count}_v > 0, \\ 0 & \text{if } v \text{ is a leaf and } \mathrm{count}_v = 0, \\ \mathrm{inside}_{\text{left}} + \mathrm{inside}_{\text{right}} & \text{otherwise.} \end{cases}$$
An update $\mathrm{add}(l, r, d)$ with $d = +1$ or $-1$ changes $\mathrm{count}$ by $d$ on the $O(\log m)$ nodes into which the range of gaps $l, \dots, r-1$ is split, and then recomputes $\mathrm{inside}$ on every node it visited, children first. If every removal repeats exactly the range of an earlier insertion, then at all times $\mathrm{inside}_{\text{root}}$ is the total length of the gaps covered by at least one active interval, and an update takes $O(\log m)$ steps.

:::tip[In plain words]
Put a counter on tree nodes instead of passing tags to the children. A node with a counter above 0 is covered completely; otherwise its covered length is the sum of its two children. To remove a rectangle, undo exactly the range you added.
:::

**A tiny instance.** Four gaps of lengths $1, 2, 3, 4$. Adding gaps 0 and 1 puts a counter on the node that holds exactly those two gaps, so its $\mathrm{inside}$ is $1 + 2 = 3$ and the root gives $3 + 0 = 3$. Adding gaps 1 and 2 puts a counter on the leaf of gap 1 and on the leaf of gap 2; now gap 0, 1 and 2 are covered and the root gives $6$. Removing gaps 0 and 1 lowers the counter of the first node only; its value is now the sum of its leaves, $0 + 2 = 2$, and the root gives $2 + 3 = 5$.

**Proof.**
1. The split of a range $[l, r)$ into nodes (take a node when its range lies inside $[l, r)$, otherwise split it) depends only on $l$ and $r$. A removal that repeats the range of an insertion lowers exactly the counters the insertion raised, so $\mathrm{count}_v$ is always the number of active intervals whose split contains $v$, and never below 0.
2. The nodes of the split of one interval cover exactly its gaps, once each. So an interval covers the gap $g$ if and only if its split contains a node on the path from the root to the leaf of $g$. Hence $g$ is covered by an active interval if and only if some node on that path has a counter above 0.
3. Say that $g$ is *covered from $v$ down* when some node on the path from $v$ to the leaf of $g$ has a counter above 0. *Claim:* $\mathrm{inside}_v$ is the total length of the gaps below $v$ that are covered from $v$ down.
4. The claim holds for a leaf: its only gap is covered from it exactly when its counter is above 0, and then $\mathrm{inside}$ is its whole length.
5. Let $v$ have two children and assume the claim for them. If $\mathrm{count}_v > 0$, every gap below $v$ is covered from $v$ down, and $\mathrm{inside}_v = \mathrm{whole}_v$.
6. If $\mathrm{count}_v = 0$, a gap below $v$ is covered from $v$ down if and only if it is covered from its child down, and the two children hold disjoint gaps, so the lengths add: $\mathrm{inside}_v = \mathrm{inside}_{\text{left}} + \mathrm{inside}_{\text{right}}$. The claim holds by induction on the height.
7. For the root, step 2 and the claim give that $\mathrm{inside}_{\text{root}}$ is the length of the gaps covered by an active interval. An update visits $O(\log m)$ nodes and recomputes $\mathrm{inside}$ only from the counter and the children, so the rule keeps holding. $\square$

:::note[This proof needs]
1. Every removal repeats the range of an earlier insertion, so no counter goes below 0 and each counter counts active intervals.
2. A counter is never pushed down to the children, and the length $\mathrm{whole}_v$ of every node is stored.
3. The quantity wanted is the length of the gaps with a count of at least 1.
:::

<TheoremCode unit="5.4/thm-2" />

The lines after the first give the tiny instance: the covered lengths 3, 6 and 5 (steps 1 and 4 to 6), where the 3 comes from the counter of one node and the 5 from the two leaves below it. The last line removes the second interval and the covered length returns to 0, because a removal undoes exactly the nodes that its insertion raised (step 1). The tree does not need a push-down because a counter is never copied to a child: a parent with a counter above 0 ignores its children, and when its counter goes back to 0 the children are still exactly right.

### 4.3 Range addition, the maximum and where it is

**Theorem 5.4.3 (range addition and maximum).** Let positions $0, \dots, m-1$ start with the value 0. A tree over the positions holds at each node $v$ the number $\mathrm{here}_v$ (the sum of everything added to the whole range of $v$) and $\mathrm{best}_v$, the largest value, over the positions $p$ below $v$, of the sum of $\mathrm{here}_u$ over the nodes $u$ from $v$ down to the leaf of $p$. For a leaf, $\mathrm{best}_v = \mathrm{here}_v$; for a node with two children,
$$\mathrm{best}_v = \mathrm{here}_v + \max(\mathrm{best}_{\text{left}}, \mathrm{best}_{\text{right}}).$$
An update $\mathrm{add}(l, r, d)$ adds $d$ to $\mathrm{here}$ and to $\mathrm{best}$ on the $O(\log m)$ nodes of the split of $[l, r)$, and recomputes $\mathrm{best}$ on the nodes above them. Then (a) the value at $p$ is the sum of $\mathrm{here}$ on the path from the root to $p$; (b) $\mathrm{best}_{\text{root}}$ is the largest value; (c) the leftmost position with the largest value is found by going down from the root, to the left child when $\mathrm{best}_{\text{left}} = \mathrm{best}_v - \mathrm{here}_v$ and to the right child otherwise. Each of these takes $O(\log m)$ steps.

:::tip[In plain words]
At each node keep what was added to everything below it and the best value below it. The root tells the largest value; walking down from the root, always to the left when it holds the best value, tells the leftmost place where it happens.
:::

**A tiny instance.** Positions $0$ to $7$ and the additions of 1 to $[0,4)$, $[2,6)$ and $[3,5)$. The values are $1, 1, 2, 3, 2, 1, 0, 0$, so the largest value is 3 and it is first at position 3.

**Proof.**
1. The nodes of the split of $[l, r)$ lie on the root path of exactly the positions $l, \dots, r-1$ (they cover those positions once each and no others). So adding $d$ to $\mathrm{here}$ on them adds $d$ to the sum along the path of $p$ if and only if $p \in [l, r)$. This is (a).
2. For a node $v$ with two children, the sum from $v$ down to a leaf below it equals $\mathrm{here}_v$ plus the sum from the child down. Taking the maximum over the positions below $v$ gives the rule $\mathrm{best}_v = \mathrm{here}_v + \max(\mathrm{best}_{\text{left}}, \mathrm{best}_{\text{right}})$.
3. After an update, a node of the split has $\mathrm{here}$ raised by $d$ and every position below it gains $d$, so its $\mathrm{best}$ rises by $d$. A node above the split is recomputed by the rule of step 2 from its children, which are correct by induction on the height. A node that is neither is unchanged and still correct.
4. For the root, the sum from the root down to $p$ is the value at $p$, so $\mathrm{best}_{\text{root}}$ is the largest value. This is (b).
5. At a node $v$, the positions below $v$ that reach $\mathrm{best}_v$ are those below the left child whose sum from the left child is $\mathrm{best}_v - \mathrm{here}_v$, together with those below the right child with the same sum. If $\mathrm{best}_{\text{left}}$ equals $\mathrm{best}_v - \mathrm{here}_v$, the leftmost such position is below the left child; otherwise the right child must reach it, and the leftmost such position is below the right child. Repeating this from the root reaches a leaf, which is (c). $\square$

:::note[This proof needs]
1. Additions are given as half-open ranges $[l, r)$ of positions, and the values start at 0 (or at known numbers stored in the leaves).
2. The quantity asked for is a maximum, which merges as $\mathrm{here}_v + \max$ of the children without the children ever being changed.
3. When ties matter, they are broken to the left, and the sweep reads the maximum only after all events at one $x$ (Theorem 5.4.1, step 6).
:::

<TheoremCode unit="5.4/thm-3" />

The first example is the tiny instance (step 4). In the second, two disjoint ranges have the same largest value 5, and the answer is the left one (step 5, ties go left). In the third, an addition and its negative leave all values at 0, and the leftmost position is 0.

The tree of [topic 5.3](../5-3-segment-tree/) pushes a tag to the children before it descends (Theorem 5.3.3). Here nothing is pushed down, because the maximum only needs $\mathrm{here}_v$ added at the node; this is shorter to write and the same speed.

### 4.4 Counting points in rectangles with a Fenwick tree

**Theorem 5.4.4 (counting sweep).** Let $P$ be a set of $n$ points with integer coordinates. For a rectangle $[a, b] \times [c, d]$ (closed, $a \le b$, $c \le d$), the number of points of $P$ inside it is
$$G(b, d) - G(a-1, d) - G(b, c-1) + G(a-1, c-1),$$
where $G(X, Y)$ is the prefix count (the number of points with $x \le X$ and $y \le Y$). If the points are added to a Fenwick tree over the ranks of $y$ in order of $x$, and the prefix counts are asked in order of $X$, then $G(X, Y)$ is the prefix sum of the tree up to the rank of $Y$ at the moment when all points with $x \le X$ are in the tree. A set of $q$ rectangles is answered in $O((n + q) \log n)$ steps.

:::tip[In plain words]
The points in a rectangle are four prefix counts added and subtracted. Sort the points by x, answer the prefix counts in order of x, and let a Fenwick tree over y say how many of the points added so far are low enough.
:::

**A tiny instance.** The points $(1,1)$, $(2,3)$, $(3,2)$, $(3,3)$ and the rectangle $1 \le x \le 3$, $2 \le y \le 3$. The prefix counts are $G(3,3) = 4$, $G(0,3) = 0$, $G(3,1) = 1$, $G(0,1) = 0$, so the number inside is $4 - 0 - 1 + 0 = 3$: the points $(2,3)$, $(3,2)$ and $(3,3)$.

**Proof.**
1. For one point $(x, y)$ write $[x \le b]$ for 1 when the condition holds and 0 otherwise. The four terms for this point sum to $[x \le b][y \le d] - [x \le a-1][y \le d] - [x \le b][y \le c-1] + [x \le a-1][y \le c-1]$, which equals $([x \le b] - [x \le a-1]) \cdot ([y \le d] - [y \le c-1])$.
2. Since $a - 1 < b$, we have $[x \le b] - [x \le a-1] = 1$ exactly when $a \le x \le b$, and it is 0 otherwise; the same for $y$ with $c$ and $d$. So the term is 1 exactly when the point is inside the rectangle. Summing over the points gives the formula.
3. Each $G(X, Y)$ is asked at a moment when the tree holds exactly the points with $x \le X$. This is true if the points are added in order of $x$ and all points with $x \le X$, ties included, are added before the question at $X$.
4. At that moment the Fenwick tree over the ranks of $y$ holds one mark per point at the rank of its $y$, and the prefix sum up to the rank of $Y$ (the number of distinct $y$ values that are at most $Y$) is the number of points among them with $y \le Y$, by Theorem 5.2.1. That is $G(X, Y)$.
5. Each point is added once and each of the $4q$ prefix questions is answered once, at a cost of $O(\log n)$ each. Sorting costs $O((n + q) \log (n + q))$. $\square$

:::note[This proof needs]
1. The points do not change while the questions are answered, and all the questions are known before the sweep starts (offline).
2. Points with $x$ equal to $X$ are added before the question at $X$, because the condition is "$x$ at most $X$".
3. The rank used for $Y$ counts the distinct $y$ values that are at most $Y$ (an upper bound), so that equal $y$ values are on the right side.
:::

<TheoremCode unit="5.4/thm-4" />

The first example is the tiny instance (steps 1 and 2). The second asks for a single point at $x = 3$ and $y = 3$: it is counted only because the point with $x = 3$ was added before the question at $X = 3$ (step 3). The third finds no points at all, and the fourth is the whole box, with all four points.

The same sweep counts crossings of segments. A horizontal segment is added to the tree at its left end and removed after its right end, and a vertical segment asks for the number of live horizontals with $y$ in its range. For closed segments the order at one $x$ is: add, ask, remove (template 3 below).

## 6. Templates

Four templates. The program around each reads the input; the shown function is what matters. Each has a brute force that uses a different method (marking the cells of a small grid, trying every integer point, testing every pair of segments, testing every point for every rectangle) and a generator, and passed 5000 random small cases.

### Area of the union of rectangles (Theorems 5.4.1 and 5.4.2)

<CodeSnippet unit="5.4/union-area" />

**How it works.** `ys` holds the $y$ values of both ends of every rectangle, sorted and without repeats, so the leaves are the `gaps = ys.size() - 1` stretches between neighbouring values, each with its width in `width`. An event is `{x, first gap, end gap, +1 or -1}` and `lower_bound` turns a $y$ value into its index. Sorting the events puts equal $x$ together. After each event the tree's `add` updates the counters; only when the next event has a different $x$ is the covered length `tree.inside[1]` (the root) multiplied by the distance to it. In `add`, a call returns at once when its node lies outside $l \dots r-1$, takes the counter when the node lies inside, and otherwise splits; the last line of `add` is the rule of Theorem 5.4.2. The area is a `long long`, because it can reach $10^{18}$.

**Alternative formulation.** For $n \le 2000$, count gaps with a plain array and loop over all gaps at every event, as in Theorem 5.4.1; it is $O(n^2)$ and shorter.

### The heaviest spot (Theorems 5.4.1 and 5.4.3)

<CodeSnippet unit="5.4/heaviest-spot" />

**How it works.** Rectangles are closed on integer points, so the range of $y$ is $[y_1, y_2 + 1)$ (that is why `ys` takes `r[3] + 1`) and the rectangle is removed at $x_2 + 1$. After all events at one $x$, `tree.best[1]` is the largest total weight on that column of integer points; a weight is kept only when it is strictly larger than the best so far, so the smallest $x$ wins ties. `leftmostMaximum` walks down to the leftmost gap holding the maximum, and `ys[...]` is the smallest $y$ in it. Weights add up beyond $2 \cdot 10^9$, so they are `long long`.

**Alternative formulation.** The lazy tree of [topic 5.3](../5-3-segment-tree/) with tags pushed down gives the same answers with more code.

### Crossings of horizontal and vertical segments (Theorem 5.4.4)

<CodeSnippet unit="5.4/crossings" />

**How it works.** Only the heights of horizontal segments are compressed into `ys`; `change(y, d)` adds $d$ to the Fenwick tree at the rank of $y$, and `aliveUpTo(y)` counts the live horizontals with height at most $y$. A horizontal segment is an `OPEN` event at its left end and a `CLOSE` event at its right end; a vertical segment is an `ASK` event. The tuples are sorted by $x$ and then by the kind, so at one $x$ the order is open, ask, close: a vertical segment at the exact end of a horizontal one still touches it. The answer counts pairs, up to $(n/2)^2$, so it is a `long long`.

**Alternative formulation.** Swap the roles of the axes (sweep $y$, tree over $x$); the answer is the same.

### Points in many rectangles (Theorem 5.4.4)

<CodeSnippet unit="5.4/count-in-rects" />

**How it works.** `rank(y)` is the number of distinct $y$ values at most `y`, which is the Fenwick index of the largest rank that is at most `y`. Each rectangle gives four queries `{X, Y, sign, rectangle}`; sorting puts them in order of `X`, and the inner `for` adds every point with `x <= X` first, so ties are counted. A query adds `sign * sum` to its rectangle. The counts fit an `int` because there are at most $n$ points.

**Alternative formulation.** Sort by $y$ and let the tree index $x$; the answer is the same, and it may be shorter when the $x$ values are already ranks.

## 7. Bug catalogue

Each bug below was made by changing a template from Section 6 and caught by `scripts/stress.sh` on 5000 random inputs, except the third, which a random test cannot reach and is caught by a fixed test. The inputs shown are small failing inputs checked against the brute force.

### Bug: leaving the top ends out of the compression

Template: area of the union.

```cpp
for (auto& r : rects) ys.push_back(r[1]);   // instead of both r[1] and r[3]
```

Input: `2`, then the rectangles `4 3 5 5` and `1 4 3 5`.

Wrong output `1`, correct output `4`. The two rectangles do not overlap, so the area is $2 + 2$. A top end that is not in `ys` is turned into the index of the next larger value, or the end of the list, so a rectangle covers the wrong gaps (Theorem 5.4.1, precondition 1).

**Fix:** push both $y_1$ and $y_2$ of every rectangle.

### Bug: removing a different range from the one added

Template: area of the union.

```cpp
events.push_back({r[2], lo, hi - 1, -1});   // instead of lo, hi
```

Input: the same two rectangles as above.

Wrong output `5`, correct output `4`. The removal lowers one gap fewer than the insertion raised, so the last gap of the rectangle stays covered for ever (Theorem 5.4.2, precondition 1).

**Fix:** use the same pair of gap indices for the insertion and the removal.

### Bug: the area in 32 bits

Template: area of the union.

```cpp
int area = 0;   // instead of long long
```

Input: `1`, then the rectangle `0 0 1000000000 1000000000`.

Wrong output `-1486618624`, correct output `1000000000000000000`. Random small inputs never reach $2 \cdot 10^9$, so `stress.sh` passes; the fixed test with a rectangle of side $10^9$ catches it (topic 0.1).

**Fix:** keep the area in a `long long`.

### Bug: reading the maximum after every single event

Template: the heaviest spot.

```cpp
// the line "if (... events[i + 1][0] == events[i][0]) continue;" removed
```

Input: `2`, then the rectangles `0 1 0 1 2` and `1 0 1 1 3`.

Wrong output `5 1 1`, correct output `3 1 0`. The rectangle with weight 3 starts at $x = 1$, and the rectangle with weight 2 stops at $x = 1$. Sorted by gap, the start comes first, so after it the tree shows $3 + 2 = 5$ at $y = 1$: a value that no point has (Theorem 5.4.1, step 6).

**Fix:** read the maximum only after the last event at the same $x$.

### Bug: stopping a closed rectangle at x2

Template: the heaviest spot.

```cpp
events.push_back({r[2], lo, hi, -r[4]});   // instead of r[2] + 1
```

Input: `2`, then the rectangles `3 3 4 4 1` and `4 3 4 4 1`.

Wrong output `1 3 3`, correct output `2 4 3`. The first rectangle contains the column $x = 4$, but it is removed at $x = 4$, before the column is read, so the point $(4, 3)$ is counted for one rectangle only (Theorem 5.4.1, precondition 2: rectangles are half-open in $x$, so a closed rectangle stops at $x_2 + 1$).

**Fix:** remove the rectangle at $x_2 + 1$.

### Bug: taking the rightmost maximum

Template: the heaviest spot.

```cpp
if (best[2 * v + 1] == best[v] - here[v]) v = 2 * v + 1, lo = mid;   // right child first
else v = 2 * v, hi = mid;
```

Input: `2`, then the rectangles `0 0 0 0 5` and `0 3 0 3 5`.

Wrong output `5 0 3`, correct output `5 0 0`. Both points have weight 5. The task wants the smallest $y$, which is the leftmost gap (Theorem 5.4.3, step 5).

**Fix:** go to the left child whenever it reaches the maximum.

### Bug: closing before asking

Template: crossings.

```cpp
enum { OPEN = 2, ASK = 1, CLOSE = 0 };   // instead of OPEN = 0, ASK = 1, CLOSE = 2
```

Input: `2`, then the segments `0 0 3 0` and `3 0 3 3`.

Wrong output `0`, correct output `1`. The horizontal segment ends at $x = 3$ and the vertical one stands at $x = 3$, so they share the point $(3, 0)$. With the closing event first, the horizontal segment is gone when the vertical one asks. Segments are closed, so the order must be open, ask, close.

**Fix:** use `OPEN = 0`, `ASK = 1`, `CLOSE = 2`.

### Bug: leaving out the fourth term

Template: points in many rectangles.

```cpp
{a - 1, c - 1, 0, i}   // instead of the sign +1
```

Input: `1 1`, then the point `2 2`, then the rectangle `3 3 3 3`.

Wrong output `-1`, correct output `0`. The points with $x \le a-1$ and the points with $y \le c-1$ were both taken away, and the point $(2, 2)$ is in both groups, so it was taken away twice. The fourth term gives it back (Theorem 5.4.4, step 1).

**Fix:** add $G(a-1, c-1)$ back.

## 8. Worked examples

The problem bank of this topic is small (see the note at the end of this section), so there is no separate worked-example problem. The templates of Section 6 are the worked examples: each is shown with a short walk through its steps and checked against a brute force on thousands of random inputs. The problem ladder (Section 9) gives three hints for every rung, in the order of the steps of the theorems: say what the sweep line moves along, say what the tree holds, say what is read when.

Why the bank is small: the topic needs problems where a rectangle, a segment or a range is added to a tree during a sweep, and offline. The searches (the Codeforces API tags, the AtCoder Problems list, LeetCode and CSES) found about 19 such problems; 8 are rungs, and the rest are in the checkpoint, the review set and the look-alike pairs. The perimeter of a union has no problem on the four sites that could be read, so it has no card.
