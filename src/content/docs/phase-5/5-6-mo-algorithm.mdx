## 1. Why this topic exists

Here is a small problem. An array has $n = 2 \cdot 10^5$ numbers. There are $q = 2 \cdot 10^5$ questions $(l, r)$, and for each you must print the sum, over every value $v$ that occurs in $a_l, \dots, a_r$, of $v \cdot c_v^2$, where $c_v$ is how many times $v$ occurs in the range. Nothing changes between the questions.

A sparse table needs an operation that tolerates overlap, and a Fenwick tree or a segment tree needs the answer of a range to be a combination of the answers of its halves. Here it is not: the halves can hold the same value, and the cross terms $2 c_v c'_v$ appear. Counting the values of each range separately costs up to $4 \cdot 10^{10}$ steps.

The key idea: if the window $a_l, \dots, a_r$ is known together with its answer, then moving the right end by one place changes the answer by an amount that takes one step to compute: adding a value $v$ that already occurs $c$ times changes $v c^2$ into $v (c+1)^2$, so the answer grows by $v (2c + 1)$. So answer the questions in a good *order*, moving the window from one question to the next: group the questions by the block of about $n / \sqrt q$ positions that holds $l$, and inside a group sort by $r$. Then the left end moves at most one block per question and the right end at most $n$ places per group, about $n \sqrt q \approx 9 \cdot 10^7$ steps in all. This is **Mo's algorithm**.

The plain form needs a fixed array, ranges, and a window that can both grow and shrink. This topic also treats the three ways that this fails and how to repair each: the array may change between the questions (time becomes a third coordinate), the questions may be paths in a tree (the tree is written as a list in which a path is a range), and the answer may be a maximum that cannot be repaired when an element leaves (the window only grows, and the short left part of each question is added and then undone).

### What this topic does not cover

- Questions whose answer is a combination of the answers of the two halves of the range (minimum, sum, greatest common divisor): the tables and trees of topics 5.1 to 5.3 answer them in $O(1)$ or $O(\log n)$ steps with no order of questions.
- Offline questions on a line answered by sorting them by one end and keeping a Fenwick tree ([topic 5.2](../5-2-fenwick/)): when one mark per value is enough, that sweep is faster than moving a window.
- Questions that depend on earlier answers (online questions): they cannot be sorted, and no order of questions applies.
- Sorting the questions along a space-filling curve to save a constant factor, and Mo's order in more than three dimensions (several kinds of changes at once): not part of this course.
- Divide and conquer over time (offline processing in which changes and questions are split by their time): not part of this course.

## 3. Definitions

- Mo's algorithm keeps a **window** $[l, r]$ of the array and a value that describes it; the operations **add** and **remove** move the right or left end by one place and update the value. The questions are answered **offline**: all are read first, and the order of answering is chosen.
- The **Mo order** of questions $(l, r)$ with block size $B$: sort by the block $\lfloor l / B \rfloor$; inside a block of even number sort by $r$ ascending, inside a block of odd number by $r$ descending.
- A **change** is a pair (position, new value). In the version with changes every question carries the number $t$ of changes that happened before it, and a **time pointer** moves one change at a time: applying a change puts the new value in the array and keeps the old one, so applying it a second time puts the old value back.
- The **Euler order** of a rooted tree is the list of $2n$ entries in which every vertex is written when a depth-first search enters it (position $\text{tin}$) and again when it leaves it (position $\text{tout}$). Example: for the edges $0-1$, $0-2$, $1-3$ the list is $0, 1, 3, 3, 1, 2, 2, 0$.
- A **rollback** undoes the last additions to a structure that cannot remove: it lowers the counts by the same amounts and restores the answer that was saved before the additions.

## 4. Theory and proofs

### 4.1 The cost of Mo's order

**Theorem 5.6.1 (Mo's order).** Let the questions $(l_i, r_i)$ on an array of $n$ positions be visited in the Mo order with block size $B$. Then the total number of one-step moves of the two ends of the window, starting from the empty window ($l = 0$, $r = -1$), is at most $qB + 2n \lceil n / B \rceil + 4n + 2B$. For $B \approx n / \sqrt q$ this is about $3 n \sqrt q + 4n$, so $O(n \sqrt q + q)$.

:::tip[In plain words]
Group the questions by the block of their left end. Inside a group the left end hops around within one block (less than $B$ steps for each question) while the right end only goes one way, up or down, so it moves at most $n$ for the whole group. Going from one group to the next costs at most $n$ for the right end and about $2B$ for the left. Count: $q$ questions times $B$, plus $n / B$ groups times about $2n$.
:::

**A tiny instance.** $n = 10$, six questions numbered 0 to 5: $(5,9)$, $(0,3)$, $(6,7)$, $(1,8)$, $(4,4)$, $(0,9)$, and $B = \lfloor 10 / \sqrt 6 \rfloor = 4$. Block 0 of the left end (positions 0 to 3) holds the questions 1, 3 and 5, sorted by $r$ ascending: $1, 3, 5$. Block 1 (positions 4 to 7) holds the questions 0, 2 and 4, sorted by $r$ descending: $0, 2, 4$. The window moves $4 + 6 + 2 + 5 + 3 + 5 = 25$ steps in this order, against 58 in the order of the input.

**Proof.**
1. *Left end, inside a group.* Two consecutive questions of one group have their left ends in the same block of $B$ places, so the left end moves fewer than $B$ steps: at most $qB$ in all.
2. *Left end, between groups.* The block number of the left end only goes up, so the sum of the jumps between groups is at most $\lceil n / B \rceil \cdot B$ for the block starts plus $\lceil n / B \rceil \cdot B$ for the positions inside blocks, which is at most $2n + 2B$. The first move from the start is at most $n$.
3. *Right end, inside a group.* The right ends of a group are sorted (up for an even block, down for an odd one), so the right end moves in one direction through the group, at most $n$ steps in all.
4. *Right end, between groups.* One jump of at most $n$ steps from the last right end of a group to the first of the next; at most $\lceil n / B \rceil$ groups. The first move from the start is at most $n$.
5. Adding up: $qB + (2n + 2B + n) + (n \lceil n/B \rceil + n \lceil n/B \rceil + n) = qB + 2n \lceil n/B \rceil + 4n + 2B$. With $B = n / \sqrt q$ the first term is $n \sqrt q$ and the second is about $2 n \sqrt q$. $\square$

:::note[This proof needs]
1. All the questions are known beforehand (offline): the order is chosen by the algorithm.
2. $B$ is about $n / \sqrt q$, not $\sqrt n$; the two agree only when $q \approx n$. For $q$ much smaller than $n$ the block must be larger; for $q$ larger than $n$ at least 1.
3. Going down in odd blocks (the "snake" order) halves the right-end movement between groups; the proof above works with or without it, but the snake order is the common practice.
:::

The check generates random questions for several $n$ and $q$ and compares the real movement with the bound of the theorem, and checks that the order is a permutation of the questions.

### 4.2 Answering questions in that order

**Theorem 5.6.2 (Mo's algorithm).** Let the questions be sorted in the Mo order, and let `add(i)` and `remove(i)` change the value for the window when position $i$ enters or leaves it. Then the following loop, which moves the window to each question $(q_l, q_r)$ by: grow to the left while $l > q_l$; grow to the right while $r < q_r$; shrink from the left while $l < q_l$; shrink from the right while $r > q_r$, leaves the window equal to $[q_l, q_r]$ and the value equal to the answer of the question. The total number of calls to `add` and `remove` is the number of moves of Theorem 5.6.1, and each call takes $O(1)$ steps when the answer changes by an amount computed from a count array.

:::tip[In plain words]
Keep a window and its answer. To go to the next question, move each end until it is where the question wants it, adding or removing one element at a time and repairing the answer after each step. Grow before shrinking, so that the window is never "negative" and a removed element was really added before.
:::

**A tiny instance.** $a = [1, 2, 1, 3, 2, 2, 4, 1]$, the question $[0, 3]$: from the empty window ($l = 0$, $r = -1$) grow the right end: add positions 0, 1, 2, 3; the counts are $c_1 = 2$, $c_2 = 1$, $c_3 = 1$, and the number of different values is 3. Then the question $[1, 4]$: grow right (add position 4, $c_2 = 2$), shrink left (remove position 0, $c_1 = 1$): the window is $[1, 4]$ with the values 2, 1, 3, 2 and 3 different values.

**Proof.**
1. *Invariant:* the count array $c$ holds the number of occurrences of each value in the window $a_l, \dots, a_r$, and the stored answer is the answer for this window.
2. The initial window is empty and the answer is that of the empty window. The invariant holds.
3. `add(i)` raises $c[a_i]$ by one and `remove(i)` lowers it by one; the stored answer is repaired by the change this makes to the answer of the window (for the number of different values: +1 when $c$ goes from 0 to 1, $-1$ when it goes from 1 to 0). The invariant is preserved by each call.
4. With the order of the four loops, growing first, a position is only removed after it was added: the left end never passes $r + 1$, because it moves right only after the right end has reached $q_r \ge q_l$.
5. After the four loops $l = q_l$ and $r = q_r$, so by the invariant the stored answer is the answer of the question. The number of calls is the number of moves of the two ends. $\square$

:::note[This proof needs]
1. The answer of a window can be repaired in $O(1)$ steps after one element enters or leaves (maintaining counts, sums, or a count of counts). If it cannot, the algorithm is as slow as the repairs.
2. The array does not change between the questions, and the questions are known beforehand.
3. The order of the loops: growing first is required whenever `remove` would break on an empty window.
:::

### 4.3 Changes between the questions

**Theorem 5.6.3 (Mo's algorithm with changes).** Let an array of $n$ positions have $U$ changes (position, new value) in time order, and let each of $q$ questions $(l, r, t)$ ask about $a_l, \dots, a_r$ of the array after the first $t$ changes ($0 \le t \le U$). Let $B$ be a block size, $G = \lceil n / B \rceil$, and sort the questions by $(\lfloor l / B \rfloor, \lfloor r / B \rfloor, t)$. Start from the window $(l, r) = (0, -1)$ at time 0 and move to each question: apply or undo changes until the time pointer is $t$ (a change at a position inside the window removes the old value and adds the new one), then move $l$ and $r$ as in Theorem 5.6.2. The window then holds $a_l, \dots, a_r$ after $t$ changes, and the three pointers move at most $2(q + 1)B + 2(G + 1)(n + B) + 2 U G^2$ steps in all. For $B \approx n^{2/3}$ and $q, U \approx n$ this is $O(n^{5/3})$.

:::tip[In plain words]
Add time as a third coordinate. Group the questions by the block of their left end, then the block of their right end, then by time, with blocks of about $n^{2/3}$ positions. Then the three pointers move about $n^{5/3}$ steps in all. Moving the time pointer applies or undoes one change, and repairs the window if the changed position is inside it.
:::

**A tiny instance.** $a = [1, 2, 1, 3, 2]$ and the changes $c_1$: position 1 becomes 3, $c_2$: position 3 becomes 1. The question $(0, 3, 0)$ sees $1, 2, 1, 3$: 3 different values. Moving to $(0, 3, 1)$ applies $c_1$; position 1 is inside the window, so the 2 is removed and a 3 added: the window is $1, 3, 1, 3$ with 2 different values. Moving to $(0, 3, 2)$ applies $c_2$: the 3 at position 3 leaves and a 1 enters, so the window is $1, 3, 1, 1$ with 2 different values.

**Proof.**
1. *Invariant:* the array holds the values after $t$ changes, the count array holds the counts of the window $a_l, \dots, a_r$ of this array, and the stored answer is the answer for it. It holds at the start (empty window, $t = 0$).
2. Moving $l$ or $r$ by one place adds or removes one element of the current array, as in Theorem 5.6.2, so the invariant is kept.
3. Applying change $k$ puts the new value at its position and keeps the old one; if the position is inside the window, the old value is removed and the new one added first and last, so the invariant is kept. Applying it again swaps the values back, which undoes it.
4. *Left end.* Questions in the sorted order have a non-decreasing block of $l$. If the blocks are $b \le b'$, the left ends differ by less than $(b' - b + 1)B$. Over the $q + 1$ moves (including the start) the "$+1$" parts add up to $(q + 1)B$ and the differences $b' - b$ add up to at most $G$, so $l$ moves at most $(q + 1)B + GB \le (q + 1)B + n + B$ steps.
5. *Right end.* Inside one block of $l$ the block of $r$ does not decrease, so the same count gives at most $(q + 1)B + G(n + B)$ steps in all. When the block of $l$ changes, $r$ jumps by at most $n + 1$, at most $G + 1$ times. Adding steps 4 and 5: $l$ and $r$ move at most $2(q + 1)B + 2(G + 1)(n + B)$ steps.
6. *Time.* Inside a group with the same pair of blocks the times are sorted, so the time pointer moves at most $U$ inside the group and at most $U$ to enter it; there are at most $G^2$ groups: at most $2 U G^2$ steps.
7. With $B = n^{2/3}$ we have $G \approx n^{1/3}$: the terms are about $2 q n^{2/3}$, $2 n^{4/3}$ and $2 U n^{2/3}$, so $O(n^{5/3})$ for $q, U \approx n$. $\square$

:::note[This proof needs]
1. Every change touches one position, the changes are known and in time order, and every question says how many changes come before it.
2. Adding, removing and applying a change each repair the answer in $O(1)$ steps.
3. The number of changes is about $n$ or less: with $U \gg n$ the term $2 U n^{2/3}$ dominates and the method is too slow.
:::

The example runs the five questions $(2, 4, 1)$, $(0, 3, 2)$, $(0, 3, 0)$, $(1, 4, 2)$, $(0, 3, 1)$ and prints $3\ 2\ 3\ 3\ 2$; the last three questions of the tiny instance are the third, second and fifth answers. The check recomputes every range after applying the first $t$ changes, on three thousand random inputs, and checks the bound on the moves of the three pointers.

### 4.4 Paths of a tree

**Theorem 5.6.4 (Mo's algorithm on a tree).** Root a tree at vertex 0 and let $E$ be its Euler order, with $\text{tin}[x] < \text{tout}[x]$ the two positions of vertex $x$. For two vertices $u, v$ with $\text{tin}[u] \le \text{tin}[v]$ and $w$ their lowest common ancestor: if $w = u$, the vertices that appear exactly once in $E[\text{tin}[u] .. \text{tin}[v]]$ are exactly the vertices of the path from $u$ to $v$; otherwise the vertices that appear exactly once in $E[\text{tout}[u] .. \text{tin}[v]]$ are exactly the vertices of the path except $w$. So a window over $E$ in which a vertex is switched on at its first appearance and off at its second, with $w$ switched on by hand for the question, answers path questions, and the moves are those of Theorem 5.6.1 for an array of $2n$ entries.

:::tip[In plain words]
Walk the tree and write each vertex down when you enter it and when you leave it. A path becomes a range of this list. A vertex that is not on the path appears twice in the range or not at all, so switching a vertex on at its first appearance and off at its second leaves exactly the path, and the lowest common ancestor is added by hand when it is not in the range.
:::

**A tiny instance.** The tree with the edges $0-1$, $0-2$, $1-3$, $1-4$, $2-5$, $2-6$ has $E = 0, 1, 3, 3, 4, 4, 1, 2, 5, 5, 6, 6, 2, 0$. The path from 3 to 6: vertex 3 is not an ancestor of 6, so the range is $E[\text{tout}[3] .. \text{tin}[6]] = E[3 .. 10] = 3, 4, 4, 1, 2, 5, 5, 6$; the vertices that appear once are $1, 2, 3, 6$, and the common ancestor 0 is added by hand: the path $3, 1, 0, 2, 6$. The path from 1 to 4 has $w = 1 = u$ and the range $E[1 .. 4] = 1, 3, 3, 4$: once are 1 and 4.

**Proof.**
1. Let $I(x) = [\text{tin}[x], \text{tout}[x]]$. Two intervals are nested or disjoint, and $x$ is an ancestor of $y$ (or $y$ itself) exactly when $I(y) \subseteq I(x)$.
2. A vertex appears once in a range of $E$ if exactly one of its two positions is inside, twice if both, never if none.
3. *Case $w = u$, range $[\text{tin}[u], \text{tin}[v]] \subseteq I(u)$.* A vertex $x$ of the path is an ancestor of $v$ inside $I(u)$: $\text{tin}[x]$ is in the range and $\text{tout}[x] \ge \text{tout}[v] > \text{tin}[v]$ is not, so $x$ appears once. A vertex in $I(u)$ that is not an ancestor of $v$ has $I(x)$ before $\text{tin}[v]$ (both positions inside) or after it (both outside): zero or twice. A vertex outside $I(u)$ has both positions outside.
4. *Case $w \ne u$, range $[\text{tout}[u], \text{tin}[v]]$.* The subtree of the child of $w$ above $u$ ends before the subtree of the child above $v$ begins. A path vertex $x \ne w$ on the side of $u$ is an ancestor of $u$: $\text{tin}[x] \le \text{tin}[u] < \text{tout}[u]$ is outside, and $\text{tout}[u] \le \text{tout}[x] <$ the start of the other child's subtree $\le \text{tin}[v]$ is inside: once. On the side of $v$ the vertex $x$ is an ancestor of $v$ below $w$: $\text{tin}[x] \ge$ the start of its child's subtree $> \text{tout}[u]$ is inside, and $\text{tout}[x] \ge \text{tout}[v] > \text{tin}[v]$ is outside: once.
5. In that case $w$ and its ancestors have $\text{tin} < \text{tin}[u]$ and $\text{tout} > \text{tout}[v]$, so both positions are outside: they never appear, and $w$ must be added by hand. Any other vertex has no position on the boundary of the range (otherwise it would be an ancestor of $u$ or $v$), so both positions are inside or both outside.
6. Switching a vertex on at the first appearance and off at the second leaves on exactly the vertices that appear an odd number of times in the window, that is, once. So the window is the path (without $w$ in the second case), and the answer is repaired in $O(1)$ steps per flip. $\square$

:::note[This proof needs]
1. The tree is rooted and the Euler order is built by one depth-first search; the lowest common ancestor ([topic 4.6](../../phase-4/4-6-lca/)) is known for every question.
2. A flip repairs the answer in $O(1)$ steps (counts of colours, counts of counts).
3. The second appearance of a vertex is a removal, so the order of the loops of Theorem 5.6.2 must grow before it shrinks.
:::

### 4.5 When the answer can only be added to

**Theorem 5.6.5 (Mo's algorithm that only adds).** Let $B$ be a block size and let `add(i)` repair the answer in $O(1)$ steps when position $i$ enters a window (no removal is needed). Group the questions $(l, r)$ by the block of $l$, and let $e$ be the last position of that block. Inside a group sort by $r$. Keep a window $a[e + 1 .. r_{	ext{now}}]$, which starts empty with $r_{	ext{now}} = e$ and only grows. For a question, move $r_{	ext{now}}$ up to $r$ if it is below, save the answer, add $a[l .. \min(r, e)]$ one by one, read the answer, and undo exactly these additions (lower the counts, restore the saved answer). The answer read is the answer for $a_l, \dots, a_r$, and the total number of additions and undos is at most $2qB + (n + V)\lceil n / B \rceil$, where $V$ is the size of the value range that is cleared for every group; for $V \le n$ and $B \approx n / \sqrt q$ this is $O(n \sqrt q)$.

:::tip[In plain words]
When the answer cannot be repaired after a removal, never remove. For the questions whose left ends lie in one block, grow a window to the right only, add the short left part for each question, read the answer, and undo exactly that part. The left part is shorter than a block, so the cost is the same as for plain Mo.
:::

**A tiny instance.** $a = [2, 1, 2, 2, 1]$, $B = 2$ (blocks $0..1$, $2..3$, $4..4$), the question is the largest $x \cdot (\text{number of times } x \text{ occurs})$, and the questions are $(0, 4), (1, 3), (3, 4), (0, 0)$. Group of block 0 ($e = 1$), sorted by $r$: $(0, 0)$, $(1, 3)$, $(0, 4)$. For $(0, 0)$ add $a_0 = 2$: best 2; undo. For $(1, 3)$ grow the window to $a_2, a_3 = 2, 2$ (best 4), add $a_1 = 1$: best 4; undo $a_1$ and keep the window. For $(0, 4)$ grow to $a_4 = 1$, add $a_0 = 2$ (three 2s: 6) and $a_1 = 1$: best 6; undo. Group of block 1 ($e = 3$): $(3, 4)$: grow to $a_4 = 1$ (best 1), add $a_3 = 2$ (best 2); undo. The answers in the order of the questions are $6, 4, 2, 2$.

**Proof.**
1. *Invariant:* before each question of a group, the window holds exactly $a[e + 1 .. r_{\text{now}}]$, the count array holds its counts, and `best` is its answer, built by additions only. It holds when a group starts (empty window, counts cleared).
2. Inside a group the questions are sorted by $r$, so $r_{\text{now}}$ only goes up; moving it is additions only, and the invariant is kept.
3. The left part $a[l .. \min(r, e)]$ is added to a copy of the state in the sense that it is undone later. After these additions the structure holds $a[l .. e]$ together with $a[e + 1 .. r]$ if $r > e$, which is $a[l .. r]$; if $r \le e$ the window is still empty (because $r_{\text{now}} \ge r$ has not been moved above $e$) and the structure holds $a[l .. r]$. So `best` is the answer.
4. The undo lowers the count of every added element by one, which restores the counts exactly, and `best` is set back to the saved value, so the invariant holds again.
5. Each question adds and undoes fewer than $B$ elements: at most $2qB$ steps. For each group, $r_{\text{now}}$ moves at most $n$ steps and the clearing of the counts costs $V$: at most $(n + V)\lceil n / B \rceil$ in all. $\square$

:::note[This proof needs]
1. `add` repairs the answer in $O(1)$ steps and the answer of a window is a function of its counts only, so that an undo of the counts and a saved answer restore the state.
2. The questions are all known first, to be grouped by block.
3. The array of counts is cleared for every group, which costs $V$ per group; the values should be compressed to at most about $n$ different numbers.
:::

## 6. Templates

Six templates. Each shows only the structure or function that matters; the program around it reads the input. The three plain templates use the function `moOrder` of Theorem 5.6.1 and say so. Each is checked against a brute force that follows the statement directly (recount the range, walk the path), on thousands of random small inputs and on fixed tests with a single element, equal values and the largest numbers.

### Sum of the squares of the counts, in many ranges (Theorems 5.6.1 and 5.6.2)

<CodeSnippet unit="5.6/mo-power" />

**How it works.** The window is the range $[l, r]$ and `power` is the sum of $v \cdot c_v^2$ over its values. Taking a value $v$ with count $c$ into the window changes $v c^2$ into $v (c + 1)^2$, so `power` grows by $v (2c + 1)$; taking one out lowers it by $v (2c' + 1)$ where $c'$ is the count after the removal. The questions are visited in the order `moOrder`, and each is answered after the four loops have moved the window onto it (grow first, then shrink, Theorem 5.6.2). The answer can be as large as $10^6 \cdot (2 \cdot 10^5)^2 = 4 \cdot 10^{16}$, so it is `long long`; the counts and the loop indices are `int`.

**Alternative formulation.** There is no tree solution; the answer of a range is not a combination of the answers of its halves. Splitting the array into blocks and storing the answer for each pair of block ends costs $O(n \sqrt n)$ memory and the same time, and is harder to write.

### Pairs of positions with a given XOR, in many ranges (Theorems 5.6.1 and 5.6.2)

<CodeSnippet unit="5.6/mo-xor-pairs" />

**How it works.** Let $p_0 = 0$ and $p_i = a_1 \oplus \dots \oplus a_i$. The XOR of $a_i, \dots, a_j$ is $p_{i-1} \oplus p_j$, so a question $(l, r)$ asks for the pairs of prefix indices $x < y$ in the window $l - 1, \dots, r$ with $p_x \oplus p_y = k$ (this is the same as $p_x \oplus k = p_y$). The window is over the *prefix indices*, so the question $(l, r)$ becomes the window $(l - 1, r)$ in the array of $n + 1$ values. Taking index $i$ in adds `cnt[p[i] ^ k]` new pairs (one for each index already in the window whose prefix value is $p_i \oplus k$) and then counts $p_i$; taking it out undoes both steps in the opposite order. The count array has $2^{20}$ entries.

**Alternative formulation.** If $k = 0$, the pairs are equal prefix values and the answer is the number of equal pairs (the next template). Without the ranges, a map of counts of prefix values counts the pairs in one pass ([topic 1.7](../../phase-1/1-7-bits/)).

### Pairs of equal values in many ranges (Theorems 5.6.1 and 5.6.2)

<CodeSnippet unit="5.6/mo-pairs" />

**How it works.** A value that occurs $c$ times in the window makes $c(c-1)/2$ pairs. Taking in one more copy adds $c$ pairs (one with each copy already there), and `pairs += cnt[v]++` does exactly that: it adds the old count and then raises it. Taking one out first lowers the count to $c - 1$ and then subtracts it: `pairs -= --cnt[v]`. The answers are stored by the number of the question, not by the position in the sorted order, so that they can be printed in the order of the input.

**Alternative formulation.** For the number of *disjoint* pairs of equal values, change the update to depend on whether the new count is even. For the number of pairs with the order of the positions or with a difference condition, a count array is not enough.

### Sum of the squares of the counts, with changes between the questions (Theorem 5.6.3)

<CodeSnippet unit="5.6/mo-changes" />

**How it works.** A question is $(l, r, t)$, with $t$ the number of changes before it. The questions are sorted by the block of $l$, the block of $r$ and $t$, with blocks of $\lfloor n^{2/3} \rfloor$ positions. `apply(k)` swaps the new value of change $k$ with the value in the array; if the position is inside the window it removes the old value and adds the new one around the swap, so the counts and `power` stay correct, and calling it a second time undoes the change. The loops move $t$ first, then $l$ and $r$ (grow before shrink). `power` can be as large as $10^6 \cdot (2 \cdot 10^5)^2$, so it is `long long`; the number of different values is found from the array and the changes before the count array is made.

**Alternative formulation.** When no change is made between questions, the plain order of Theorem 5.6.1 has fewer moves. When each change is a single value and the question is a sum, a Fenwick tree ([topic 5.2](../5-2-fenwick/)) is shorter and faster.

### Colours that occur exactly once on a path of a tree (Theorem 5.6.4)

<CodeSnippet unit="5.6/mo-tree" />

**How it works.** Each question is turned into a range of the Euler order and, when the first vertex is not an ancestor of the second, the lowest common ancestor `w` that must be switched on for the question. `flip(x)` switches vertex `x` on if it is off and off if it is on, and repairs `once`, the number of colours with exactly one vertex in the window: a colour with 0 vertices becomes 1 (up), one with 1 becomes 2 (down), and in reverse. The questions are ordered by `moOrder` over the $2n$ entries. After the loops the answer is read with `w` flipped on, and `w` is flipped off again so that the window is still the range. The depth-first search is written with a stack so that a deep tree does not overflow the call stack.

**Alternative formulation.** If the question is about a vertical path (from a vertex to an ancestor) and the quantity is a sum, prefix values from the root and subtraction ([topic 4.6](../../phase-4/4-6-lca/)) answer in $O(1)$ steps and need no order of questions.

### The most frequent value in many ranges, with only additions (Theorem 5.6.5)

<CodeSnippet unit="5.6/mo-rollback" />

**How it works.** The questions are sorted by the block of $l$ and then by $r$. For a new block the counts are cleared, `best` is 0, and the right pointer `r` and `end` (the last position of the block) are set; positions after `end` are added as `r` grows. For a question, `saved` keeps `best`, the part $a[l .. \min(r, \text{end})]$ is added, the answer is `best`, then the same part is undone by lowering the counts and `best` returns to `saved`. A question that lies inside one block never moves `r`. The counts are `int` and the answer is at most $n$.

**Alternative formulation.** The most frequent value of a range can also be kept with the count of counts and a plain window, because lowering the best count after a removal is possible when the count of counts is stored; the rollback version does not need it and also works for maxima that cannot be repaired at all.

## 7. Bug catalogue

Each bug below was made by changing one line of a template and running the random stress test against the brute force; the input shown is the smallest one found.

### Bug: the new copy is counted with the pairs it has not made yet

Template: pairs of equal values.

```cpp
auto add = [&](int i) { pairs += ++cnt[a[i]]; };        // instead of pairs += cnt[a[i]]++
```

Input: `1 1`, then `1`, then the question `1 1`.

Wrong output `1`, correct output `0`. A single element makes no pair. The new copy forms a pair with each copy that was already in the window, that is, with `cnt` copies *before* it is counted; the wrong line adds the count after the increase, which includes the element itself (Theorem 5.6.2, step 3: the answer is repaired by the change the step makes).

**Fix:** add first, increase afterwards.

### Bug: the answers are written in the order of the sorted questions

Template: pairs of equal values.

```cpp
answer[cntq++] = pairs;                                 // instead of answer[q] = pairs
```

Input: `5 3`, then `1 1 2 2 2`, then the questions `2 5`, `1 2` and `1 1`.

Wrong output `0`, `1`, `3`, correct output `3`, `1`, `0`. Mo's order visits the questions in a different order from the input (here the last one first), and the answers must go to the places of the questions they belong to. The sorted order is only a way to move the window.

**Fix:** store the answer at the index `q` of the question.

### Bug: the window starts at the question's left end, not one before

Template: pairs with a given XOR.

```cpp
win[i] = {queries[i][0], queries[i][1]};                // instead of {queries[i][0] - 1, queries[i][1]}
```

Input: `4 1 2`, then `0 2 1 3`, then the question `2 4`.

Wrong output `1`, correct output `2`. The XOR of $a_l, \dots, a_r$ is $p_{l-1} \oplus p_r$, so the window must start at the prefix index $l - 1$. Starting at $l$ leaves out the prefix value just before the range. Here $a = [0, 2, 1, 3]$ and $k = 2$: the subarrays of positions 2 to 4 with XOR 2 are $[2]$ and $[1, 3]$, but the one that starts at position 2 needs the prefix value $p_1$, which the wrong window never counts.

**Fix:** use $l - 1$ for the left end of the window over the prefix values.

### Bug: a change is applied without repairing the window

Template: the sum of the squares of the counts, with changes.

```cpp
swap(a[pos], value);                                    // instead of removing and adding when pos is inside the window
```

Input: `1 1 2`, then `1`, then the change `1 3`, then the questions `1 1 1` and `1 1 0`.

Wrong output `1`, `1`, correct output `3`, `1`. The window is $[0, 0]$ when the change is applied, and the line writes the new value into the array but leaves the old value in the counts, so the answer for time 1 still describes the old array (Theorem 5.6.3, step 3: a change inside the window removes the old value and adds the new one).

**Fix:** remove the old value before the swap and add the new one after it, when the position is inside the window.

### Bug: the common ancestor is never added

Template: colours that occur exactly once on a path.

```cpp
answer[q] = once;                                       // instead of flipping extra[q] on, reading, and flipping it off
```

Input: `3 1`, then the colours `3 3 4`, then the edges `1 2` and `1 3`, then the question `2 3`.

Wrong output `2`, correct output `1`. The path is $2, 1, 3$ with the colours $3, 3, 4$, so only the colour 4 occurs once. The range holds the vertices 2 and 3 but not the vertex 1, which appears only outside it, so the colour 3 is counted once instead of twice (Theorem 5.6.4, step 5).

**Fix:** switch the lowest common ancestor on for the question when it is not inside the range.

### Bug: the common ancestor stays switched on

Template: colours that occur exactly once on a path.

```cpp
answer[q] = once;                                       // the second  if (extra[q] >= 0) flip(extra[q]);  is missing
```

Input: `3 2`, then the colours `2 4 2`, then the edges `1 2` and `1 3`, then the questions `2 3` and `2 3`.

Wrong output `1`, `2`, correct output `1`, `1`. After the first question the vertex 1 is still counted in the window, so the next question starts from a window that holds an extra vertex and the answer changes. The window must be exactly the range between questions (Theorem 5.6.4, step 6).

**Fix:** flip the vertex off again after reading the answer.

### Bug: the saved best value is not restored after the rollback

Template: the most frequent value, with only additions.

```cpp
(void)saved;                                            // instead of best = saved;
```

Input: `6 2`, then `3 3 3 2 1 3`, then the questions `4 5` and `1 4`.

Wrong output `3`, `3`, correct output `1`, `3`. Both questions are in the block $0..3$ and the question $(1, 4)$ has the smaller right end, so it runs first: it adds the three 3s and the best count is 3. After the undo the counts are zero again, but `best` is still 3, so the question $(4, 5)$, which sees only the values 2 and 1, reports 3 (Theorem 5.6.5, step 4: the saved answer must be put back so that the window is the same as before the question).

**Fix:** set `best = saved` after the undo.

### Bug: the counts are not cleared for a new block

Template: the most frequent value, with only additions.

```cpp
best = 0;                                               // instead of fill(cnt.begin(), cnt.end(), 0), best = 0;
```

Input: `2 2`, then `3 3`, then the questions `1 2` and `2 2`.

Wrong output `2`, `2`, correct output `2`, `1`. With $B = 1$ every position is its own block. The window of the first block leaves the count of the value 3 at 1 (the position 2 was added to the window and stays), and the second block starts from that count instead of from zero, so its single element makes a count of 2 (Theorem 5.6.5, step 1: a group starts with an empty window).

**Fix:** clear the counts at the start of every group.
