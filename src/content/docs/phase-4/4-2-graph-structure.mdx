## 1. Why this topic exists

Here is a small problem. A university offers $n = 2 \cdot 10^5$ courses, and there are $m = 2 \cdot 10^5$ rules of the form "course $a$ must be taken before course $b$". Can a student take all the courses, one at a time, obeying every rule? If so, in which order?

Trying the orders one by one ([topic 0.5](../../phase-0/0-5-brute-force/)) means $n!$ of them; already $20! \approx 2.4 \cdot 10^{18}$. A greedy choice such as "always take the course with the smallest number" fails when that course has an unmet rule.

The key idea: if a good order exists, its first course has no rule pointing at it. So take any course that no remaining rule points at, cross it off together with the rules it started, and repeat. If at some moment every remaining course is still waiting for another remaining course, then following the "waits for" rules from any course can never stop, so it must come back to a course it has already visited: the rules contain a **cycle**, and no order exists. This costs one pass over the courses and rules, $n + m = 4 \cdot 10^5$ steps.

That is one of four questions about the *shape* of a graph that this lesson answers by a walk: is there a cycle (in a two-way graph, or in a graph of arrows), can the vertices be split into two sides with every edge going from one side to the other, in what order can the vertices be listed so that all arrows go forward, and can one trip use every edge exactly once.

The last question is about edges, not vertices. A postman has to drive along each of $m = 2 \cdot 10^5$ streets exactly once. Trying all orders of the streets costs $m!$ ($10! = 3\,628\,800$ already for ten streets). The key idea is again a count: each time the route passes through a crossing it uses two streets there, one to arrive and one to leave, so every crossing that is not the start or the end must have an even number of streets. If these counts are right and all streets lie in one piece, walking along unused streets with a stack builds the route in $m$ steps.

## 3. Definitions

- An undirected graph is **simple** if it has no edge from a vertex to itself and no two edges between the same two vertices.
- A **cycle** is a path $v_0, v_1, \dots, v_k$ with $v_k = v_0$ and $k \ge 3$ in which the vertices $v_0, \dots, v_{k-1}$ are all different; its length is $k$. In a directed graph a **directed cycle** is the same with arrows $v_0 \to v_1 \to \dots \to v_k = v_0$, and $k \ge 1$ (a vertex with an arrow to itself is a directed cycle of length 1). A cycle is **odd** if its length is odd. A graph without a cycle is a **forest**.
- A **two-colouring** of an undirected graph gives each vertex colour 0 or 1 so that every edge joins vertices of different colours. A graph that has one is **bipartite**: the vertices split into two sides, and every edge goes from one side to the other.
- When a walk (Theorem 4.1.1) reaches a new vertex $w$ along an edge from $u$, $u$ is the **parent** of $w$ and that edge is a **tree edge**. Every other edge is a **non-tree edge**. The **depth** of a vertex is its distance from the start of its walk.
- In a directed graph, the **in-degree** of a vertex is the number of arrows that point to it; the **out-degree** is the number of arrows that leave it.
- A **topological order** of a directed graph is a list of all its vertices in which every arrow goes from an earlier vertex to a later one. A **directed acyclic graph (DAG)** is a directed graph without a directed cycle. "Sorting the vertices in a topological order" is called **topological sort**.
- During a depth-first search each vertex is in one of three **states**: not entered yet, **on the stack** (entered but not finished: the search is still working below it), or **finished** (all its arrows have been tried).
- The **lexicographic order** of two sequences (topic 1.1) compares them at the first position where they differ.
- A **multigraph** may have several edges between the same two vertices and loops (an edge from a vertex to itself). The **degree** of a vertex in an undirected multigraph is the number of edge ends at it, so a loop counts twice; a vertex is **odd** or **even** by its degree. Example: in the path $1\!-\!2\!-\!3$ the degrees are $1, 2, 1$.
- A **trail** is a list of vertices in which every two neighbours in the list are joined by an edge, and no edge is used twice (a vertex may repeat). An **Euler trail** is a trail that uses every edge of the graph exactly once; it is an **Euler circuit** if it starts and ends at the same vertex. For arrows, a trail follows the arrows. Example: in the triangle $1\!-\!2\!-\!3$ the list $1, 2, 3, 1$ is an Euler circuit; in the path $1\!-\!2\!-\!3$ the list $1, 2, 3$ is an Euler trail that is not a circuit.
- In the removal process of Theorem 4.2.3, the vertices that have no unused arrow into them at one moment, taken together, form one **round**. Example: for the arrows $1 \to 2$ and $1 \to 3$ the first round is $\{1\}$ and the second is $\{2, 3\}$.

## 4. Theory and proofs

### 4.1 Two sides, and odd cycles

**Theorem 4.2.1 (two-colouring).** Let $G$ be an undirected graph without loops. In every component pick a start vertex $s$ and give each vertex $v$ of the component the colour $d(s, v) \bmod 2$ (its distance from $s$, taken modulo 2). The following three statements are equivalent:

(a) $G$ has a two-colouring;

(b) in this distance-parity colouring no edge joins two vertices of the same colour;

(c) $G$ has no cycle of odd length.

The walk of Theorem 4.1.3 produces the parity colouring: a vertex reached from $u$ gets the colour opposite to $u$. Time $O(n + m)$.

:::tip[In plain words]
Walk out from a vertex and give every vertex the colour opposite to the one it was reached from. The vertices split into two sides if and only if this never gives two neighbours the same colour, and that happens exactly when the graph contains a cycle with an odd number of edges.
:::

**A tiny instance.** The path $1\!-\!2\!-\!3\!-\!4$ gets the colours $0, 1, 0, 1$: it is bipartite. The triangle $1\!-\!2\!-\!3$ gets $0$ for vertex 1 and $1$ for vertices 2 and 3 (both are one step from 1), but 2 and 3 are joined: the edge $2\!-\!3$ lies inside one colour, and the triangle is a cycle of length 3.

**Proof.**
1. *(a) implies (c).* In a two-colouring the colours alternate along every path. After going once around a cycle of length $k$ we are back at the first vertex, so its colour has changed $k$ times and returned: $k$ is even. So no cycle is odd.
2. *(c) implies (b), by contraposition.* Suppose an edge $uv$ joins two vertices of the same colour, that is, $d(s, u)$ and $d(s, v)$ have the same parity. A shortest path from $s$ to $u$, the edge $uv$, and a shortest path from $v$ back to $s$ form a closed walk of length $d(s, u) + 1 + d(s, v)$, which is odd.
3. *Lemma: a closed walk of odd length contains a cycle of odd length.* We use induction on the length $L$. If the walk repeats no vertex (except that it ends where it starts), it is a cycle ($L \ge 3$ because there are no loops and $L = 2$ is even). Otherwise some vertex $x$ occurs twice inside it, and cutting the walk at $x$ gives two shorter closed walks whose lengths add up to the odd number $L$, so one of them is odd; it contains an odd cycle by induction.
4. By steps 2 and 3, an edge inside one colour yields an odd cycle: if (b) fails, (c) fails. So (c) implies (b).
5. *(b) implies (a).* If no edge joins two vertices of the same colour, the parity colouring is a two-colouring.
6. The walk gives each vertex the colour opposite to its parent, which is the parity of its distance (Theorem 4.1.3(a)), and it looks at every edge from at least one end, so it reports a conflict exactly when (b) fails. Every vertex and edge is handled once: $O(n + m)$. $\square$

:::note[This proof needs]
1. The edges are undirected. For a graph of arrows, "two sides" is asked about the graph with the directions forgotten.
2. The graph has no loops. A loop (an edge from a vertex to itself) would join a vertex to its own colour, so a graph with a loop cannot be two-coloured; the code reports this at once.
3. Each component is coloured on its own, from any start vertex.
:::

<TheoremCode unit="4.2/thm-1" />

The first two examples are the tiny instance: on the path, the parities of distance from vertex 1 are the colours (steps 5 and 6); on the triangle, vertices 2 and 3 get the same colour, which is the edge inside one colour of step 2. The third example has two components and an isolated vertex, each coloured from its own start.

### 4.2 Cycles in an undirected graph

**Theorem 4.2.2 (cycles and non-tree edges).** Let $G$ be a simple undirected graph with $n$ vertices, $m$ edges and $c$ components, and let a walk (Theorem 4.1.3) record for every vertex its parent and depth. Then:

(a) there are exactly $n - c$ tree edges;

(b) every non-tree edge $uw$ closes a cycle: climb from $u$ and from $w$ along the parents to the first vertex $x$ they have in common; the two climbs together with the edge $uw$ form a cycle;

(c) $G$ has a cycle if and only if it has a non-tree edge, if and only if $m > n - c$.

Time $O(n + m)$.

:::tip[In plain words]
A walk reaches each vertex by one edge, and uses $n - c$ edges to do so. Any other edge leads to a vertex that is already reached, and together with the two routes back to their common start it closes a cycle. So extra edges beyond $n - c$ are exactly the cycles.
:::

**A tiny instance.** Edges $1\!-\!2$, $2\!-\!3$, $1\!-\!3$, $3\!-\!4$, walked from 1: the tree edges are $1\!-\!2$, $1\!-\!3$ and $3\!-\!4$ ($n - c = 4 - 1 = 3$). The edge $2\!-\!3$ is a non-tree edge; climbing from 2 and from 3 both reach 1, giving the cycle $2, 1, 3$. And $m = 4 > 3$.

**Proof.**
1. Every vertex that is not a start gets exactly one parent edge when it is first reached, and every component has exactly one start. So there are $n - c$ tree edges, which is (a).
2. Take a non-tree edge $uw$. Both ends are in one component, so their parent chains end at the same start, and climbing the deeper end first (as the code does) they reach a first common vertex $x$.
3. The chain from $u$ to $x$ and the chain from $w$ to $x$ share only $x$, and neither contains the edge $uw$, so together with $uw$ they are a closed path with different vertices. It has at least 3 edges: a total of 2 would mean one chain has length 0 and the other length 1, and then $uw$ would be the parent edge of one end, a tree edge. So it is a cycle, which is (b).
4. Conversely, suppose every edge is a tree edge and there were a cycle. Consider its vertex $y$ that the walk reached last; both cycle neighbours of $y$ were reached earlier. But the only tree edge from $y$ to an earlier vertex is its parent edge (every other tree edge at $y$ leads to a child, reached later), so $y$ has two different tree edges to earlier vertices: impossible. So a graph whose edges are all tree edges has no cycle.
5. The $m$ edges are the $n - c$ tree edges plus the non-tree edges, so there is a non-tree edge if and only if $m > n - c$. With steps 3 and 4 this is (c). Every vertex and edge is handled once: $O(n + m)$. $\square$

:::note[This proof needs]
1. The graph is simple. With a repeated edge the formula $m > n - c$ still counts it (a cycle of length 2), but the test "an edge to a marked vertex other than the parent" skips it, because both copies lead to the parent.
2. Edges are undirected. For arrows, a marked neighbour does not mean a cycle (Theorem 4.2.4).
3. The walk stores the parent and the depth of every vertex.
:::

<TheoremCode unit="4.2/thm-2" />

The first example is the tiny instance: the non-tree edge $2\!-\!3$ gives the cycle $2, 1, 3$ (steps 2 and 3). The path has $m = 2 = n - c$ and no non-tree edge (step 5). In the square, the walk from 1 reaches 2 and 4 first, then 3 from 2; the edge $4\!-\!3$ is the non-tree edge, and the two climbs meet at vertex 1 (the cycle $4, 1, 2, 3$).

### 4.3 An order for the arrows

**Theorem 4.2.3 (topological order).** Let $G$ be a directed graph. Compute the in-degree of every vertex and put all vertices of in-degree 0 into a queue. While the queue is not empty, remove a vertex $u$, output it, and for every arrow $u \to w$ decrease the in-degree of $w$ by 1, putting $w$ into the queue when it reaches 0. Then:

(a) every output vertex comes after all vertices that have an arrow to it;

(b) all $n$ vertices are output if and only if $G$ has no directed cycle;

(c) if fewer than $n$ vertices are output, the vertices not output contain a directed cycle.

Hence a topological order exists if and only if there is no directed cycle. Time $O(n + m)$.

:::tip[In plain words]
Keep taking a vertex that nothing unfinished points at. If you can take them all, the order you took them in is the answer. If you get stuck, every vertex left is pointed at by another vertex left, and going backwards among them must eventually run in a circle.
:::

**A tiny instance.** Arrows $1 \to 2$, $1 \to 3$, $2 \to 4$, $3 \to 4$: only 1 has in-degree 0. Taking 1 frees 2 and 3; taking 2 leaves the in-degree of 4 at 1; taking 3 frees 4. The order is $1, 2, 3, 4$. If we add the arrow $4 \to 1$, nothing has in-degree 0 and nothing can be taken: the cycle $1 \to 2 \to 4 \to 1$ blocks everything.

**Proof.**
1. A vertex enters the queue only when its in-degree has dropped to 0, which means every arrow into it came from a vertex that was already removed. So each vertex is output after all vertices with an arrow to it: (a).
2. Suppose $G$ has a directed cycle, and suppose some vertex $v$ on it is output; take the first such. The cycle vertex $u$ with an arrow $u \to v$ has not been output yet (as $v$ is the first), so the in-degree of $v$ is still at least 1: contradiction. So no vertex of a cycle is output, and fewer than $n$ vertices come out.
3. Suppose fewer than $n$ vertices are output. Each vertex $z$ not output has in-degree at least 1 at the end (otherwise it would have entered the queue), and the arrows still counted come from vertices that were not output either (arrows from output vertices were subtracted). So every vertex not output has an in-neighbour that is not output.
4. Start at a vertex not output and repeatedly step to such an in-neighbour. There are finitely many vertices, so a vertex repeats; the steps between its two visits, read backwards, are a directed cycle among the vertices not output. This is (c), and with step 2, (b).
5. Each vertex enters the queue at most once and each arrow decreases one counter once: $O(n + m)$. $\square$

:::note[This proof needs]
1. The arrows point from the thing that must come first to the thing that depends on it ("a before b" is the arrow $a \to b$).
2. The in-degrees are computed before the loop, counting a repeated arrow as many times as it occurs (and subtracting it as many times).
3. Any ready vertex may be taken; the proof never used which one (Theorem 4.2.5 uses this).
:::

<TheoremCode unit="4.2/thm-3" />

The first example is the tiny instance (step 1: 4 is output last, after both of its predecessors). In the second, the vertex 5 is output, but 1, 2, 3 form a cycle and 4 is reachable from it, so none of them is output (steps 2 to 4). The third has an arrow $3 \to 1$ and $3 \to 2$, $1 \to 2$: the only order is $3, 1, 2$.

### 4.4 Cycles of arrows, found by a search

**Theorem 4.2.4 (directed cycles by a depth-first search).** Run a depth-first search on a directed graph with an explicit stack: the top vertex tries its arrows one by one, entering a vertex that has not been entered, and is finished when all its arrows have been tried. Then $G$ has a directed cycle if and only if the search meets an arrow $u \to w$ where $w$ is on the stack. In that case the stack from $w$ up to $u$ is a directed cycle. Time $O(n + m)$.

:::tip[In plain words]
Follow arrows as far as you can, remembering the route you are on. If an arrow leads back to a vertex on your current route, you have gone around a circle. If every arrow leads to places already finished or new, there is no circle.
:::

**A tiny instance.** Arrows $1 \to 2$, $2 \to 3$, $3 \to 2$, $3 \to 4$ with the search started at 1: the stack grows $1, 2, 3$. The first arrow of 3 leads to 2, which is on the stack: the stack from 2 up to 3 is the cycle $2 \to 3 \to 2$. In the graph with arrows $1 \to 2$, $1 \to 3$, $2 \to 3$ the search enters 2 and 3 and finishes them, and only then tries the arrow $1 \to 3$, which leads to a finished vertex and not to one on the stack: no cycle.

**Proof.**
1. *An arrow into the stack gives a cycle.* The stack holds a path from $w$ to $u$ (each vertex was entered by an arrow from the vertex below it), and the arrow $u \to w$ closes it into a directed cycle.
2. *Claim:* if a vertex $v$ is entered at a moment when there is a path $v = x_0 \to x_1 \to \dots \to x_k$ in which $x_1, \dots, x_k$ have not been entered, then every $x_i$ is entered before $v$ is finished.
3. Suppose not, and let $x_j$ ($j \ge 1$) be the first on the path that is not entered before $v$ finishes. Then $x_{j-1}$ is $v$ or was entered after $v$ and before $v$ finished, so it finishes no later than $v$.
4. Before $x_{j-1}$ finishes it tries its arrow to $x_j$. At that moment $x_j$ is either already entered or is entered right then. It was not entered when $v$ was, so in both cases it is entered after $v$ and before $x_{j-1}$ finishes, hence before $v$ finishes: a contradiction. The claim holds.
5. *A cycle gives an arrow into the stack.* Let $v$ be the first vertex of a directed cycle that the search enters. At that moment the other cycle vertices have not been entered, and the cycle gives a path from $v$ through them to the vertex $u$ with the arrow $u \to v$. By the claim, $u$ is entered before $v$ finishes, that is, while $v$ is on the stack; when $u$ tries its arrow to $v$, the vertex $v$ is on the stack.
6. Each vertex is entered once and each arrow is tried once: $O(n + m)$. $\square$

:::note[This proof needs]
1. Arrows have directions that are followed only forwards. In an undirected graph, an arrow back to the parent is not a cycle (Theorem 4.2.2).
2. The three states are kept apart: "on the stack" and "finished" must not be mixed, because an arrow to a finished vertex is not a cycle.
3. The stack stores the route, so that the cycle can be read from it.
:::

<TheoremCode unit="4.2/thm-4" />

The first example is a triangle of arrows, found as soon as the arrow $3 \to 1$ is tried (step 1). The second has no arrow into the stack (step 5 fails to apply). The third is the tiny instance: the cycle $2, 3$ is found while vertex 4 has not even been entered.

### 4.5 The smallest order

**Theorem 4.2.5 (smallest topological order).** Replace the queue in Theorem 4.2.3 by a priority queue that always gives the smallest vertex number (a min-heap, topic 0.6). If $G$ has no directed cycle, the output is the smallest of all topological orders, comparing orders as sequences of vertex numbers (lexicographically). Time $O((n + m) \log n)$.

:::tip[In plain words]
When several vertices are free to be taken, take the one with the smallest number. This never blocks a later choice, and at every position it puts the smallest number that any valid order could put there.
:::

**A tiny instance.** Three vertices and the arrow $2 \to 1$. Free at the start: 2 and 3. The smallest is 2; taking it frees 1, so now 1 and 3 are free. The order is $2, 1, 3$. The queue of Theorem 4.2.3 would give $2, 3, 1$, which is also valid but larger as a sequence.

**Proof.**
1. The output is a topological order, because the proof of Theorem 4.2.3 never used which ready vertex is taken.
2. Let $P = (p_1, \dots, p_n)$ be any topological order and $H = (h_1, \dots, h_n)$ the output; suppose $H \ne P$ and let $i$ be the first position where they differ, so $h_j = p_j$ for $j < i$.
3. In $P$ every vertex with an arrow to $p_i$ stands before position $i$, that is, among $p_1, \dots, p_{i-1} = h_1, \dots, h_{i-1}$. So after those vertices have been taken, the in-degree of $p_i$ is 0: $p_i$ is among the ready vertices when the heap chooses $h_i$.
4. The heap chooses the smallest ready vertex, so $h_i \le p_i$, and $h_i \ne p_i$ gives $h_i < p_i$. Then $H$ is smaller than $P$ at the first position where they differ, so $H < P$. $\square$

:::note[This proof needs]
1. "Smallest" refers to the order of the vertex numbers as sequences. A different aim, such as putting vertex 1 as early as possible and then vertex 2, needs Theorem 4.2.6; the two orders can differ.
2. The graph has no directed cycle, so that all $n$ vertices come out (Theorem 4.2.3).
3. Ties do not exist: vertex numbers are different.
:::

<TheoremCode unit="4.2/thm-5" />

The first example is the tiny instance (steps 3 and 4: vertex 3 is ready from the start but 1 becomes ready first and is smaller). In the second, vertices 1 and 4 are ready at first and 1 is taken; then 4 is the only one ready, then 2, then 3. The third example has a single valid order.

### 4.6 The earliest places for the small numbers

The smallest *sequence* of Theorem 4.2.5 is not the same as the order that puts vertex 1 as early as possible. With the single rule "3 before 1" on three vertices, the smallest sequence is $2, 3, 1$ (vertex 2 is free and smallest at the start), which puts vertex 1 last; the order $3, 1, 2$ puts vertex 1 second. When a problem asks to finish item 1 as soon as possible, then item 2, and so on, the right order is built from the back.

**Theorem 4.2.6 (earliest places for the small numbers).** Let $G$ be a directed graph without a directed cycle. For a topological order $P$, let $\text{pos}_P(v)$ be the place of $v$ in $P$. Call $P$ **best** if the list $(\text{pos}_P(1), \text{pos}_P(2), \dots, \text{pos}_P(n))$ is lexicographically smallest among all topological orders. Fill the places $n, n-1, \dots, 1$ in this order: give the place to the largest vertex that has no arrow to a vertex still waiting for a place, and remove that vertex. The result is the best order. Time $O((n + m) \log n)$.

:::tip[In plain words]
To get vertex 1 as early as possible, then vertex 2, and so on, build the order from the back: put into the last free place the largest vertex that nothing remaining has to follow.
:::

**A tiny instance.** The rule "3 before 1" on three vertices. The vertices with no arrow out are 1 and 2 (vertex 3 has an arrow to 1). The largest is 2: it takes place 3. Without 2, the only vertex with no arrow out is 1: it takes place 2. Then 3 takes place 1. The order is $3, 1, 2$, with $\text{pos}(1) = 2$; the smallest sequence $2, 3, 1$ has $\text{pos}(1) = 3$.

**Proof.**
1. *The result is a topological order.* A vertex takes a place only when it has no arrow to a vertex that is still waiting, so every vertex that follows it in a rule already has a later place. This is Theorem 4.2.3 on the reversed arrows, written from the back.
2. Let $P$ be a best order and let $s$ be the largest vertex with no arrow out of it in $G$. We show $s$ is last in $P$. Suppose not, and let $t$ be the last vertex of $P$. Nothing can follow $t$, so $t$ has no arrow out, hence $t \le s$, and $t \ne s$, so $t < s$.
3. Move $s$ to the end of $P$. The order stays valid: $s$ has no arrow out, and the arrows into $s$ still come from earlier vertices. Every vertex that stood after $s$ now stands one place earlier (among them $t$), $s$ itself moves later, and all other vertices keep their places.
4. The vertices whose places changed are $s$ and the vertices that stood after $s$. The smallest of them is at most $t < s$ and its place became smaller. So the new order has a lexicographically smaller list of places than $P$, contradicting that $P$ is best. Hence $s$ is last in every best order.
5. Fixing $s$ in the last place, the places of the other vertices in $P$ are the places in an order of $G$ without $s$, and $P$ is best exactly when that order is best for $G$ without $s$. By induction on $n$, taking the largest vertex without an arrow out of it for each place from the back builds a best order. $\square$

:::note[This proof needs]
1. The graph has no directed cycle, so that a vertex without an arrow to a waiting vertex always exists (Theorem 4.2.3 on the reversed arrows).
2. The aim is the early places of small numbers, compared from vertex 1 upwards. For the smallest *sequence* use Theorem 4.2.5.
3. Vertex numbers are different, so that "largest" and "smallest" are unambiguous.
:::

<TheoremCode unit="4.2/thm-6" />

The first example is the tiny instance (steps 2 to 4: the vertex 2 is the largest vertex without an arrow out, and goes last). In the second, vertex 2 has arrows to 1 and 3, so it stands first; the vertices without an arrow out are 1, 3 and 4, and they take the places 4, 3 and 2 in the order 4, 3, 1. The third is a chain, which has a single valid order.

### 4.7 A trail through every edge

Sections 4.1 to 4.6 asked about vertices. A different question is about edges: can one trip use every road exactly once? Trying all orders of the roads costs $m!$ ($10! = 3\,628\,800$ already). Counting the roads at each crossing answers it.

**Theorem 4.2.7 (Euler trails).** Let $G$ be an undirected multigraph with $m \ge 1$ edges, all lying in one connected piece (every vertex that has an edge can be reached from every other by edges). Then:

(a) $G$ has an Euler circuit if and only if every vertex has even degree;

(b) $G$ has an Euler trail from $s$ to a different vertex $t$ if and only if $s$ and $t$ are the only vertices of odd degree.

The same holds for a directed multigraph whose arrows are connected once the directions are forgotten: in (a) every vertex has as many arrows in as out, and in (b) $s$ has one more arrow out than in, $t$ has one more in than out, and every other vertex has as many in as out.

The **stack method** builds the trail. Put the start $s$ on a stack ($s$ in (b); any vertex with an edge in (a)). While the stack is not empty, look at its top vertex $v$: if $v$ has an unused edge (an unused arrow out of $v$), mark it used and put its other end on the stack; otherwise take $v$ off the stack and write it at the end of a list. The list read backwards is the trail, and it has $m + 1$ vertices exactly when every edge was used. Time $O(n + m)$.

:::tip[In plain words]
A trail that uses every edge exactly once exists when the edges form one connected piece and at most two vertices have an odd number of edges (for arrows: as many in as out everywhere, except one start and one end). Walk along unused edges with a stack and write a vertex down when it is stuck; the list, read backwards, is the trail.
:::

**A tiny instance.** The roads $1\!-\!2$, $2\!-\!3$, $3\!-\!1$ and $3\!-\!4$ have degrees $2, 2, 3, 1$: only the crossings 3 and 4 are odd, and the roads form one piece, so a trail from 3 to 4 exists. The stack method starts at 3 and goes $3, 2, 1, 3, 4$, where 4 has no unused road. Vertices leave the stack in the order $4, 3, 1, 2, 3$, and read backwards this is $3, 2, 1, 3, 4$, which uses every road once. In the star with centre 1 and leaves 2, 3, 4 (degrees $3, 1, 1, 1$) four vertices are odd, so no trail exists: each leaf has one road, so a trail can pass through it only if it starts or ends there, and there are only two ends.

**Proof.** Write $p_1, p_2, \dots, p_k$ for the vertices in the order they leave the stack. Every stack entry except the bottom one ($s$) was put there by using an edge; call $e_i$ the edge that put $p_i$ on the stack and $u_i$ the entry just below $p_i$, so $e_i$ joins $u_i$ and $p_i$. Let $t = s$ in (a).
1. *Only if.* A trail uses two edges at a vertex each time it passes through, one to arrive and one to leave, so a closed trail gives even degrees, and an open trail from $s$ to $t$ leaves exactly $s$ and $t$ with an unpaired edge, so they are the odd vertices. (For arrows, count arrivals and departures separately: a pass adds one of each, the start has one more departure, the end one more arrival.)
2. *Lemma.* Let $H$ be a graph in which every degree is even (put $b = a$), or exactly the vertices $a$ and $b$ are odd. A trail that starts at $a$ and takes an unused edge whenever it can is stuck only at $b$. Reason: a trail that ends at $v \ne a$ has used an odd number of the edges at $v$, and one that ends at $a$ an even number; stuck means all edges at $v$ are used, so $\deg v$ is odd for $v \ne a$ and even for $v = a$. In the even case this forces $v = a$; in the odd case $a$ is odd, so $v \ne a$ and $v = b$. (For arrows, compare the arrows out of $v$ with those into it.)
3. *The first vertex to leave the stack is $t$.* Before that the stack is a trail from $s$ that always took an unused edge, so step 2 with $H = G$ and $a = s$ gives $p_1 = t$.
4. *Claim, by induction on $i$: the vertex that leaves after $p_i$ is $u_i$, and $e_i$ joins $p_i$ to it.* Just after $p_i$ leaves, the used edges are the stack (a trail from $s$ to $u_i$), then $e_i$, $e_{i-1}$, …, $e_1$, which by the claim for smaller $i$ continue the trail through $p_i, p_{i-1}, \dots$ to $p_1 = t$. So the used edges form a trail from $s$ to $t$, and the unused edges have all degrees even.
5. *Continuing the claim.* If $u_i$ has no unused edge, it leaves next. Otherwise the method goes on from $u_i$; the unused degrees are even (step 4), so by step 2 with $a = b = u_i$ it is stuck again only at $u_i$, and that copy leaves next. In both cases the next vertex is $u_i$, joined to $p_i$ by $e_i$.
6. *The reversed list is a trail.* By step 5 the list $p_k, p_{k-1}, \dots, p_1$ goes from each vertex to the next along $e_{k-1}, \dots, e_1$, which are different edges because each edge is used once. The bottom entry leaves last, so $p_k = s$ and $p_1 = t$: a trail from $s$ to $t$ that uses exactly the edges that were used (for arrows, $e_i$ points from $u_i$ to $p_i$, so reading the list backwards follows the arrows).
7. *Every edge is used when the edges are one piece.* A vertex that was on the stack has no unused edge at the end: it had none when it left, and used edges stay used (for arrows, the used arrows form a trail from $s$ to $t$, so all arrows into a vertex are also used once all arrows out of it are). If an edge were unused, follow edges from $s$ to it; the first vertex on this path that was never on the stack is joined to an earlier one that was, but that edge is used, which put the later vertex on the stack: a contradiction.
8. *Conclusion.* The list has $m + 1$ entries exactly when all $m$ edges were used (the bottom entry plus one per used edge), so under the conditions of (a) or (b) steps 3 to 7 build the trail, and step 1 shows the conditions are needed. Each edge is used once and each vertex scans its edges once with a pointer: $O(n + m)$. $\square$

:::note[This proof needs]
1. All the edges lie in one connected piece. If they do not, the method writes down fewer than $m + 1$ vertices, which is the test for it.
2. The degree condition: no odd vertex, or exactly two (for arrows: balanced everywhere except one start with one more arrow out and one end with one more in), and in the second case the method starts at the odd vertex (the start of the arrows).
3. Every edge is used exactly once. Visiting every vertex once is a different question.
:::

<TheoremCode unit="4.2/thm-7" />

The first example is the tiny instance: the method starts at the odd vertex 3 and gives $3, 2, 1, 3, 4$ (steps 3 to 6). In the second example the roads $1\!-\!2$ appear twice. The first trail goes $1, 2, 1$ and is stuck at 1 after two of five roads; going back, the method finds the triangle $2, 3, 4$ at vertex 2 and splices it in, giving $1, 2, 3, 4, 2, 1$ (steps 4 and 5). In the third example every degree is even, but the second triangle is a different piece: only 4 of the 7 vertices are written, so there is no trail (step 7).

### 4.8 Rounds, and when the order is unique

Sometimes any number of tasks can be done at the same moment, and the question is how many rounds are needed, or whether the order is forced at all. The removal process of Theorem 4.2.3 answers both when all vertices that are free at one moment are taken together, as one **round**.

**Theorem 4.2.8 (rounds and unique orders).** Let $G$ be a directed graph without a directed cycle and let $n$ be its number of vertices. Run the removal process in rounds: round 1 takes all vertices with in-degree 0; after they are removed, round 2 takes all vertices that now have in-degree 0, and so on. Let $L(v)$ be the number of vertices on a longest path that ends at $v$. Then:

(a) vertex $v$ is taken in round $L(v)$, so the number of rounds is the number of vertices on a longest path of $G$;

(b) no arrow joins two vertices of the same round;

(c) $G$ has exactly one topological order if and only if there are $n$ rounds, that is, every round holds one vertex; and this happens exactly when $G$ has a path through all $n$ vertices.

Time $O(n + m)$.

:::tip[In plain words]
Take all free vertices together, round after round: the number of rounds is the number of vertices on a longest chain of arrows, and the order is unique exactly when there are as many rounds as vertices.
:::

**A tiny instance.** The arrows $1 \to 2$, $1 \to 3$, $2 \to 4$, $3 \to 4$ give the rounds $\{1\}$, $\{2, 3\}$, $\{4\}$: 3 rounds, and the longest path $1, 2, 4$ has 3 vertices. Round 2 holds two vertices, so there are two orders, $1, 2, 3, 4$ and $1, 3, 2, 4$. The chain $1 \to 2 \to 3$ has 3 rounds of one vertex each, and $1, 2, 3$ is its only order.

**Proof.**
1. *Induction on $L(v)$ shows that $v$ is taken in round $L(v)$.* If $L(v) = 1$, no arrow enters $v$ and it is taken in round 1. If $L(v) = k > 1$, every in-neighbour $u$ has $L(u) \le k - 1$ (otherwise a path through $u$ to $v$ would have more than $k$ vertices), so it is taken in round $k - 1$ or earlier; and the vertex before $v$ on a longest path has $L = k - 1$, so it is taken in round exactly $k - 1$.
2. *Continuing step 1.* The in-degree of $v$ reaches 0 when its last in-neighbour has been removed, at the end of round $k - 1$, so $v$ is taken in round $k$. The largest $L(v)$ is the number of vertices on a longest path, which is the number of rounds: (a).
3. For an arrow $u \to w$ we have $L(w) \ge L(u) + 1$ (extend a longest path that ends at $u$ by $w$), so $w$ is in a later round than $u$: (b).
4. *Two vertices in one round give two orders.* Suppose round $r$ holds $x$ and $y$. List the vertices round by round, with $x$ and $y$ next to each other, once as $x, y$ and once as $y, x$. By (b) every arrow goes to a later round, so both lists are topological orders, and they differ.
5. *One vertex per round gives one order.* Let $v_1, \dots, v_n$ be the vertices in round order. By (a), $L(v_k) = k$, so for $k \ge 2$ some in-neighbour of $v_k$ has $L = k - 1$, and the only vertex of round $k - 1$ is $v_{k-1}$: the arrows $v_1 \to v_2 \to \dots \to v_n$ exist. A topological order must list the vertices of a path in the order of the path, and this path has all $n$ vertices, so $v_1, \dots, v_n$ is the only order.
6. Steps 4 and 5 give the first part of (c). For the second part: $n$ rounds mean a longest path with $n$ vertices (step 2), and a path through all vertices makes $L(v) = n$ for its last vertex, so there are $n$ rounds. The process handles each vertex and each arrow once: $O(n + m)$. $\square$

:::note[This proof needs]
1. The graph has no directed cycle; with a cycle the process stops before all vertices are taken (Theorem 4.2.3).
2. Any number of vertices may be taken in one round. With a limit on how many can be done at the same time, the number of rounds is not the length of a longest path.
3. Every round counts as one step. Rounds that take different amounts of time are not covered by this theorem.
:::

<TheoremCode unit="4.2/thm-8" />

The first example is the tiny instance (steps 1 to 4: round 2 holds the vertices 2 and 3, so two orders exist). The second is a chain through all four vertices, one vertex per round, so its order is the only one (steps 5 and 6). In the third, vertex 1 is taken in round 1, but 2 and 3 wait for each other and the process stops (Theorem 4.2.3(c)).

## 6. Templates

Eight templates: five for the first four cards and the early places, and three more for the Euler trails (two) and the unique order. Each shows only the function that matters; the program around it reads the input and builds `adj` as in [topic 4.1](../4-1-graph-traversal/) (the vertices are numbered from 1, so `adj` has `n + 1` entries; for arrows, `adj[a]` gets `b` only). The theorem units of Section 4 print a cycle; the templates answer the questions that contests ask about the same ideas. Each is checked against a brute force with a different method (all splits, all sets of removed edges, all orders, following every arrow `n` times) on thousands of random small inputs and on fixed tests with isolated vertices, self-loops of arrows and several components. The three newer templates answer yes or no and a length, because a route has many correct forms: the program around the function checks that the route uses every edge once and prints only its length, and the brute force tries every order of the edges.

### Two sides (Theorem 4.2.1)

<CodeSnippet unit="4.2/two-sides" />

**How it works.** `colour[v]` is $-1$ until the walk reaches $v$. The outer loop starts a walk in every component that is still uncoloured, and gives the start colour 0. A vertex reached from `u` gets the opposite colour `1 - colour[u]`; a neighbour that already has a colour must differ from `colour[u]`, otherwise two neighbours would share a colour and the function returns an empty list. The returned list is the colouring, and the program checks every edge against it before it prints YES.

**Alternative formulation.** A stack in place of the queue colours each vertex by the parity of its depth in the walk instead of its distance. The proof of Theorem 4.2.1 works for any walk: if an edge joins two vertices of the same colour, the two paths along the parents and that edge form a closed walk of odd length (steps 2 to 4), so the answer is the same.

### Edges that close cycles (Theorem 4.2.2)

<CodeSnippet unit="4.2/forest-surplus" />

**How it works.** The walk only counts the components. The lists hold every edge twice, so the sum of their sizes (`entries`) is $2m$ and `m = entries / 2` is exact. The result $m - (n - c)$ is the number of edges that are not tree edges; deleting exactly those leaves a forest (Theorem 4.2.2(a)), and fewer deletions cannot, since a forest on $n$ vertices and $c$ components has at most $n - c$ edges.

**Alternative formulation.** If the program has read `m` already, there is no need to sum the list sizes. To print a cycle instead of counting, use the function of Theorem 4.2.2.

### The smallest order (Theorems 4.2.3 and 4.2.5)

<CodeSnippet unit="4.2/smallest-order" />

**How it works.** `indegree[w]` is the number of arrows into `w` that have not been used yet; the double loop fills it. `ready` holds the vertices with no unused arrow into them. A `priority_queue` normally gives its largest element, so the third template argument `greater<int>` turns it into a min-heap: the smallest free vertex comes out first. When `u` is taken, the arrows out of it are used up: `--indegree[w]` lowers the count first and then compares, and `w` joins `ready` the moment its count reaches 0. If fewer than `n` vertices came out, a directed cycle blocks the rest and the function returns an empty list.

**Alternative formulation.** When any valid order is acceptable, a plain `queue` does the same job in $O(n + m)$ time without the logarithm of the heap (Theorem 4.2.3).

### Vertices on cycles when each has one arrow (Theorem 4.2.4)

<CodeSnippet unit="4.2/cycle-vertices" />

**How it works.** Each vertex has at most one arrow, `next[v]` (0 if none), so a "search" is just following arrows. From an untouched start the walk adds vertices to `route` and marks them 1 (on the route) until it reaches the end of the arrows (`v == 0`) or a vertex that is already known. If the vertex it stops at is itself on the current route (state 1), the route ran into itself, and the cycle is the part of the route from that vertex on, whose length is counted. In every case the route is then marked 2 (finished), so no later walk follows it again: each vertex is entered once, $O(n)$ in total.

**Alternative formulation.** For a graph with several arrows per vertex, use the search with an explicit stack and three states from Theorem 4.2.4.

### Early places for small numbers (Theorem 4.2.6)

<CodeSnippet unit="4.2/earliest-labels" />

**How it works.** The order is written from the back: `place` counts down from `n - 1`. `outDegree[v]` is the number of rules that put another course after `v`, and `sinks` holds the courses with none left; being a `priority_queue<int>`, it gives the largest first (the default is exactly what is wanted here). The course taken gets the place, and for every course `u` that must come before it, `--outDegree[u]` lowers the count, and `u` joins `sinks` when it reaches 0. If `sinks` runs dry before all places are filled, a cycle is left and the function returns an empty list.

**Alternative formulation.** Run the process of Theorem 4.2.3 on the reversed arrows with a max-heap and reverse the output; it is the same computation read forwards.

### A route through every street (Theorem 4.2.7)

<CodeSnippet unit="4.2/mail-route" />

**How it works.** `adj[v]` holds, for every street at crossing `v`, its other end and its street number; a street is in the lists of both its ends, and the number lets the program mark it used from both sides at once. An odd number of streets at any crossing rules out a closed route (step 1 of the proof), so the function returns an empty list at once. `next[v]` is the first entry of `adj[v]` that may still be unused: the inner `while` skips entries whose street is already used. The `stack` is the route being built. When its top crossing has no unused street, that crossing is final and goes to `route`; otherwise the street is marked used and its other end is pushed. If `route` has fewer than $m + 1$ crossings, some streets lie in another piece (step 7). The program around the function checks the route before it prints its length.

**Alternative formulation.** The same method can be written as a recursive function: for every unused street at `v`, mark it and call the function on its other end, and write `v` into `route` after the loop. It builds the same list, but $2 \cdot 10^5$ nested calls can overflow the call stack, which is why the template keeps its own stack.

### A route through every teleporter (Theorem 4.2.7, arrows)

<CodeSnippet unit="4.2/teleporter-path" />

**How it works.** `balance[v]` is the number of teleporters that leave level `v` minus the number that enter it. The route must start at level 1, so level 1 needs balance $+1$, level $n$ needs $-1$, and every other level $0$; any other value returns an empty list. A teleporter works in one direction only, so using it is just moving the pointer `next[v]` forward, and no used marks are needed. The levels are finished from the end of the route backwards, so the list is reversed at the end; without the reversal it reads from level $n$ to level 1. If the list has fewer than $m + 1$ entries, some teleporters cannot be reached from level 1.

**Alternative formulation.** For a closed route in a directed graph (all balances 0), start at any level that has a teleporter and skip the check on level $n$.

### The only order (Theorem 4.2.8)

<CodeSnippet unit="4.2/unique-order" />

**How it works.** This is the removal process of Theorem 4.2.3 with the free vertices kept in a list, `ready`. Whenever one vertex is taken, the list must hold no other: two free vertices can be taken in either order (step 4 of Theorem 4.2.8), so as soon as `ready.size() > 1` the function returns an empty list. When the loop ends with fewer than $n$ vertices taken, a directed cycle blocks every order and the list is cleared too. The program prints Yes and the position of each vertex in the order only when the list is not empty.

**Alternative formulation.** Compute the rounds with the function of Theorem 4.2.8 and compare their number with $n$: the order is unique exactly when there are $n$ rounds.

**Fix:** clear the order when fewer than $n$ vertices were taken.

### Bug: looking at the free list only at the start

Template: the only order.

```cpp
if (order.empty() && ready.size() > 1) return {};   // instead of if (ready.size() > 1)
```

Input: `3 2`, then `1 2` and `1 3`.

Wrong output `Yes` and `1 3 2`, correct output `No`. Vertex 1 is the only free vertex at first, so the test at the start passes. After 1 is taken, vertices 2 and 3 are both free and can be taken in either order: two orders exist (Theorem 4.2.8, step 4).

**Fix:** test the size of `ready` before every vertex that is taken.

### Bug: allowing two free vertices

Template: the only order.

```cpp
if (ready.size() > 2) return {};          // instead of > 1
```

Input: `2 0` (two items, no facts).

Wrong output `Yes` and `2 1`, correct output `No`. Both items are free at the start, so either can come first: two permutations fit. The bound is off by one: the order is unique only when at most one vertex is free at every step.

**Fix:** return as soon as the free list holds more than one vertex.

### Example 1: Building Teams

[CSES 1668: Building Teams](https://cses.fi/problemset/task/1668). In short: $n \le 10^5$ pupils and $m \le 2 \cdot 10^5$ friendships are given; put every pupil into one of two teams so that no two friends are in the same team, or say it is impossible.

#### Step 1: Constraints → budget

$n = 10^5$: trying all $2^n$ assignments is impossible. One pass over the pupils and friendships is $n + m = 3 \cdot 10^5$ steps.

#### Step 2: Question form → candidate tools

- Try every assignment of the two teams ([topic 0.5](../../phase-0/0-5-brute-force/)): $2^{100000}$ of them.
- Treat each friendship as an edge that must join different sides: the card "Two sides (two-colouring)".

#### Step 3: Property check → decision

Each friendship forbids "same team", there are exactly two teams, and the friendships are listed. That is the card's property. Decision: colour by walking, and answer IMPOSSIBLE on a conflict.

#### Step 4: Proof for this problem

By Theorem 4.2.1, the pupils can be split exactly when no friendship joins two pupils of the same colour in the walk's colouring, and in that case the colours are a valid split (every friendship joins different colours). If the walk finds a friendship inside a colour, the pupils cannot be split at all, because the friendship, together with the paths along the parents, is an odd cycle, and no two-colouring has an odd cycle.

### Example 2: Don't be cycle

[AtCoder Beginner Contest (ABC) 288 C: Don't be cycle](https://atcoder.jp/contests/abc288/tasks/abc288_c). In short: a simple undirected graph with $N \le 2 \cdot 10^5$ vertices and $M \le 2 \cdot 10^5$ edges is given; find the fewest edges to delete so that no cycle remains.

#### Step 1: Constraints → budget

$M = 2 \cdot 10^5$ edges: trying every set of edges to delete is $2^{200000}$ sets. One walk is $N + M = 4 \cdot 10^5$ steps.

#### Step 2: Question form → candidate tools

- Try every set of edges to delete and test for a cycle ([topic 0.5](../../phase-0/0-5-brute-force/)): $2^M$ sets.
- Count the edges beyond a forest from $n$, $m$ and the components: the card "Cycles in an undirected graph".

#### Step 3: Property check → decision

The graph is simple and undirected, so the card applies. Decision: count the components $c$ with one walk and print $m - (n - c)$.

#### Step 4: Proof for this problem

Deleting edges never joins components, so afterwards there are $c' \ge c$ components, and a graph without a cycle has exactly $n - c'$ edges (Theorem 4.2.2(c)), which is at most $n - c$. So at most $n - c$ edges can stay, and at least $m - (n - c)$ must be deleted. And that many suffice: keep the $n - c$ tree edges of the walk. They leave every component connected and contain no cycle, because a graph all of whose edges are tree edges has no cycle (Theorem 4.2.2, step 4).

### Example 3: Find Eventual Safe States

[LeetCode 802: Find Eventual Safe States](https://leetcode.com/problems/find-eventual-safe-states/). In short: a directed graph with up to $10^4$ nodes is given as a list of out-neighbours per node; a node is safe if every path from it ends at a terminal node (a node with no arrows out). List the safe nodes in increasing order.

#### Step 1: Constraints → budget

$n \le 10^4$ nodes and at most $4 \cdot 10^4$ arrows. A search from every node that checks for cycles costs up to $n (n + m) = 10^4 \cdot 5 \cdot 10^4 = 5 \cdot 10^8$ steps, too many to be comfortable. One pass is $n + m = 5 \cdot 10^4$.

#### Step 2: Question form → candidate tools

- A depth-first search from every node, asking whether it reaches a cycle ([topic 4.1](../4-1-graph-traversal/)): $5 \cdot 10^8$ steps.
- Take away, again and again, the nodes whose arrows all lead to nodes already taken away: the card "Order that respects dependencies", on the reversed arrows.

#### Step 3: Property check → decision

A node is safe exactly when no path from it reaches a cycle; the card's process takes away nodes that have no unfinished dependency. Here "dependency" means "an arrow out of the node to a node that is not yet taken away". Decision: reverse the arrows, start from the terminal nodes, and count each node's remaining out-arrows.

#### Step 4: Proof for this problem

Let $R$ be the set of nodes that the process takes away. *Every node of $R$ is safe:* terminal nodes enter first, and a node enters only when all its out-neighbours have been taken away, so by induction on the order of removal every path from it ends at a terminal node. *Every safe node is in $R$:* if a node is not taken away, then (as in step 3 of the proof of Theorem 4.2.3, on the reversed arrows) it has an out-neighbour that is not taken away, and so on; following these arrows gives a path that never ends at a terminal node, so the node is not safe.
