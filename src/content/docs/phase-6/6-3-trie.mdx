## 1. Why this topic exists

Here is a small problem. A dictionary has $n = 2 \cdot 10^5$ words with $10^6$ letters in total. You get $q = 2 \cdot 10^5$ questions, and each gives a string $u$ and asks: "how many words of the dictionary begin with $u$?" The dictionary does not change.

Scanning the dictionary for every question costs up to $10^6$ letter comparisons, and $q$ such questions cost $2 \cdot 10^{11}$ comparisons, about 2000 seconds. Sorting the words ([topic 1.1](../../phase-1/1-1-sorting/)) and finding the first and the last word that begin with $u$ by binary search ([topic 1.4](../../phase-1/1-4-binary-search/)) does answer this question, in about $|u| \log n$ steps per question. But the questions that come next in this topic have no such shortcut: "what is the longest common prefix of a word with all the other words?", "which dictionary words begin at this place of the text?", "how many allowed words are left after this string is forbidden?" For these, the words are put into a tree in which **words with the same beginning share the same path**. A word is read from the root one letter at a time, so a question about a prefix is a walk of $|u|$ steps; a count, a best value or a flag can be kept on every node of the walk, and it can change when a word is stored, removed or blocked.

That tree is the **trie** (the name comes from the word "retrieval"). The same tree built on the binary digits of numbers is the binary trie of topic 5.7.

## 3. Definitions

- A **trie** stores a set of strings $W$ (a word may be stored several times). It is a rooted tree whose edges carry letters. The **root** stands for the empty string, and a node stands for the string of letters on the path from the root to it. Two edges leaving one node never carry the same letter. For every stored word there is a node that stands for it, and strings that begin the same way share their nodes. Example: the words ab, abc, abd, b are stored in a trie with 6 nodes: the root, a, ab, abc, abd and b.
- For a node $v$, $\text{pass}[v]$ is the number of stored words (with repeats) that begin with the string of $v$, and $\text{end}[v]$ is the number of stored words equal to the string of $v$. Example: in the trie above $\text{pass}[\text{a}] = 3$, $\text{pass}[\text{ab}] = 3$, $\text{end}[\text{ab}] = 1$, $\text{end}[\text{a}] = 0$. The root has $\text{pass} = |W|$. The **depth** of a node is the length of its string.
- The **longest common prefix** of two strings $a$ and $b$ is the longest string that begins both; $\text{lcp}(a, b)$ is its length. Example: $\text{lcp}(\text{abc}, \text{abd}) = 2$.
- A node of the trie is **blocked** when no word may be stored below it any more: every word that began with its string was removed and later words with that beginning are refused. Example: after blocking ab, the words ab and abc are gone and abd is refused.
- In the code a node is a number (its place in a vector), the children of a node are an array with one entry per letter, and the entry 0 means "no such child" (the root, node 0, is never a child). `array<int, 26>` is a fixed-size array of 26 integers; `array<int, 26>{}` is such an array with all entries 0. A member written with `= value` inside a `struct` gets that starting value when an object is made.

## 4. Theory and proofs

### 4.1 Words that share beginnings

**Theorem 6.3.1 (the trie).** Insert the words $w_1, \dots, w_k$ with total length $S$ one letter at a time: start at the root; for each letter, follow the edge with this letter if it exists and otherwise make a new node and a new edge; add 1 to $\text{pass}$ of every node reached (and of the root); at the last letter add 1 to $\text{end}$ of the node. Then (a) the trie has at most $S + 1$ nodes and building it takes $O(S)$ time; (b) following the letters of a string $u$ from the root ends in a node exactly when some inserted word begins with $u$, and then $\text{pass}[v]$ is the number of inserted words that begin with $u$ and $\text{end}[v]$ is the number equal to $u$; (c) both numbers for a string $u$ are found in $O(|u|)$ time.

:::tip[In plain words]
Words that begin the same way walk down the same path, so the tree has no more nodes than the words have letters, and often far fewer. A string $u$ is a prefix of some stored word exactly when its walk from the root does not fall off the tree, and the counter on the node where it ends says how many words pass through.
:::

**A tiny instance.** Insert ab, abc, abd, b. The first word makes the nodes a and ab. The second follows a and ab and makes abc. The third follows a and ab and makes abd. The fourth makes b. The trie has 6 nodes (the root, a, ab, abc, abd, b), at most $S + 1 = 2 + 3 + 3 + 1 + 1 = 10$. The walk of "ab" ends in the node with $\text{pass} = 3$ and $\text{end} = 1$; the walk of "c" falls off at the first letter.

**Proof.**
1. *Claim (a).* A word of length $\ell$ makes at most $\ell$ new nodes (one for each of its letters, at most), so after all words there are at most $S$ nodes besides the root. Each letter costs one step (following or making an edge, with the children in an array indexed by the letter), so building costs $O(S)$.
2. *Invariant for (b).* After the insertions, every node stands for a string that is a prefix of some inserted word, and every prefix of every inserted word has a node. Reason: a node is made only while a word is inserted and stands for a prefix of that word; the insertion of a word walks or makes a node for each of its prefixes.
3. So the walk of $u$ ends in a node exactly when $u$ is a prefix of some inserted word. (Two edges from one node never share a letter, so the walk of $u$ is unique.)
4. The node $v$ of $u$ is reached by exactly the insertions of words that begin with $u$: an insertion adds 1 to $\text{pass}$ of each node on the path of its word, and the path of a word goes through $v$ exactly when the word begins with $u$. So $\text{pass}[v]$ counts the words that begin with $u$ (with repeats), and $\text{end}[v]$, which is increased only by the words that end at $v$, counts the words equal to $u$.
5. *Claim (c).* The walk takes $|u|$ steps and then reads one number. $\square$

:::note[This proof needs]
1. The children of a node are looked up by letter in constant time (an array of one entry per letter). For a large alphabet, use a `map` and the times get a factor $\log$ of the alphabet size.
2. The alphabet is fixed and small (here 26 lower-case letters); the memory is $26 \cdot (S + 1)$ numbers at most, which is 26 million `int` for $S = 10^6$, about 100 MB. For $S$ above about $10^6$ the memory limit must be checked.
3. Repeated words are allowed, and counted: $\text{pass}$ and $\text{end}$ count words, not different words.
:::

<TheoremCode unit="6.3/thm-1" />

The first line is the tiny instance (step 1: 6 nodes). The prefix counts are step 4: "a" and "ab" are begun by 3 words, "abc" and "b" by 1, "c" by none (the walk falls off, step 3). The last two lines tell the words equal to ab and equal to a apart: 1 and 0. The check builds the trie of every list of up to four words of length 1 to 3 over $\{a, b\}$, repeats included, and compares the counts of every prefix with a scan of the words, and the node count with $S + 1$.

### 4.2 Counting pairs of words through their common beginnings

**Theorem 6.3.2 (common beginnings from the counts).** Let the words $w_1, \dots, w_k$ be stored in a trie with the pass counts of Theorem 6.3.1. (a) $\text{lcp}(w_i, w_j)$ is the number of non-root nodes that lie on the paths of both words. (b) The sum of $\text{lcp}(w_i, w_j)$ over all pairs $i < j$ equals the sum over all non-root nodes $v$ of $\binom{\text{pass}[v]}{2}$. (c) For a stored word $w_i$, the longest common prefix with any other stored word is the depth of the deepest node on the path of $w_i$ whose $\text{pass}$ is at least 2 (0 if there is none).

:::tip[In plain words]
Two words walk down together as long as they have the same letters, and then they part. The number of steps they walk together is the number of nodes they share. So to add up the common beginnings of all pairs, count for every node how many pairs of words pass through it, and add.
:::

**A tiny instance.** The words aaa, aab, aac, ab. The node a has $\text{pass} = 4$ and contributes $\binom42 = 6$; the node aa has $\text{pass} = 3$ and contributes $\binom32 = 3$; ab, aaa, aab, aac have $\text{pass} = 1$ and contribute 0. The sum is 9. Directly: aaa–aab, aaa–aac, aab–aac share 2 letters each (6), and each of them with ab shares 1 (3): total 9. For the word aab, the deepest node on its path with $\text{pass} \ge 2$ is aa, depth 2: its longest common prefix with another word is 2 (with aaa).

**Proof.**
1. *Part (a).* The path of a word $w$ passes the nodes of its prefixes $w[0..1), w[0..2), \dots$. A node is on the paths of both $a$ and $b$ exactly when its string is a prefix of both, that is, a common prefix of $a$ and $b$.
2. The non-root common prefixes of $a$ and $b$ are exactly the prefixes of the longest common prefix of the lengths $1, 2, \dots, \text{lcp}(a, b)$, so there are $\text{lcp}(a, b)$ of them.
3. *Part (b).* Count the pairs $(\{i, j\}, v)$ with $v$ a non-root node on both paths. By (a), each pair $\{i, j\}$ is counted $\text{lcp}(w_i, w_j)$ times. A node $v$ is on the paths of exactly $\text{pass}[v]$ words (Theorem 6.3.1(b)), so it is counted for $\binom{\text{pass}[v]}{2}$ pairs. Both ways of counting give the same total.
4. *Part (c).* The longest common prefix of $w_i$ with another word $w_j$ has length equal to the number of shared nodes (a). Those nodes lie on the path of $w_i$ and have $\text{pass} \ge 2$, because they are on the paths of both $w_i$ and $w_j$. Conversely, a node on the path of $w_i$ with $\text{pass} \ge 2$ is on the path of another word $w_j$, so its depth is at most $\text{lcp}(w_i, w_j)$. The shared nodes of a pair are all the nodes from the root down to the deepest one, so the deepest node on the path of $w_i$ with $\text{pass} \ge 2$ has the largest depth over the other words. $\square$

:::note[This proof needs]
1. $\text{pass}$ counts words with repeats; two equal words share all their nodes (their $\text{lcp}$ is their length), which agrees with (a).
2. The nodes with $\text{pass} \ge 2$ on a path form a beginning of the path (once the count drops to 1 it stays 1 further down), which is why "the deepest" is the same as "all of them".
3. The sum can reach $\binom{k}{2} \cdot \max|w|$, about $10^{10} \cdot 10^3$ for large inputs, so it needs a 64-bit integer.
:::

<TheoremCode unit="6.3/thm-2" />

The first line has the words ab, ac, b: only the node a is shared ($\text{pass} = 2$), so the sum is 1; the word ab has a common beginning of length 1 with another word and b has 0. The second line is the tiny instance: the sum 9, and the values 2 for aab (shared with aaa and aac) and 1 for ab. The last line has two equal words a, a: the node a has $\text{pass} = 2$ and the sum is 1. The check compares the sum and the per-word values with direct computation on every list of up to four words of length 1 to 3 over $\{a, b\}$.

### 4.3 Which dictionary words start here?

**Theorem 6.3.3 (a walk inside a text).** Let the dictionary words be stored in a trie, and let $s$ be a text. For a place $i$ of $s$ (counting from 0), walk the letters $s_i, s_{i+1}, \dots$ down the trie from the root, and stop when an edge is missing or the text ends. The lengths $j - i + 1$ of the walks that end in a node with $\text{end} \ge 1$ are exactly the lengths of the dictionary words that are prefixes of $s[i..]$. The walk takes at most (the length of the longest dictionary word) steps. Consequently the number of ways to cut $s$ into dictionary words, $\text{ways}[i] = \sum \text{ways}[i + \text{length}]$ over those lengths with $\text{ways}[|s|] = 1$, is computed in $O(|s| \cdot L)$ time, where $L$ is the length of the longest word.

:::tip[In plain words]
Reading the text from a place, you walk along the one path that the text spells in the tree. Every time the walk passes a node where a word ends, that word is a beginning of the rest of the text. You never have to try the words one by one, and you stop at the first missing edge.
:::

**A tiny instance.** The dictionary a, ab, b and the text abab. From place 0 the walk reads a (a word ends: length 1), then ab (a word ends: length 2), then aba: no such node, stop. So the words at place 0 have lengths 1 and 2. The numbers of ways: $\text{ways}[4] = 1$; $\text{ways}[3]$ (b) $= 1$; $\text{ways}[2]$ (ab: a then b, or ab) $= \text{ways}[3] + \text{ways}[4] = 2$; $\text{ways}[1]$ (bab) $= \text{ways}[2] = 2$; $\text{ways}[0] = \text{ways}[1] + \text{ways}[2] = 4$.

**Proof.**
1. By Theorem 6.3.1(b), the walk of $s[i..j]$ from the root ends in a node exactly when some dictionary word begins with $s[i..j]$, and in a node with $\text{end} \ge 1$ exactly when $s[i..j]$ itself is a dictionary word.
2. The walk of $s[i..j+1]$ continues the walk of $s[i..j]$ by one edge. If the walk of $s[i..j]$ fell off the tree, then no dictionary word begins with $s[i..j]$, hence none begins with a longer string that starts with it, and stopping is right.
3. So the lengths seen at nodes with $\text{end} \ge 1$ are exactly the lengths of the dictionary words that are prefixes of $s[i..]$, each once.
4. A walk cannot be longer than the longest dictionary word, because no node is deeper than that. So the walk takes at most $L$ steps.
5. *The count of cuttings.* Every cutting of $s[i..]$ into dictionary words starts with a dictionary word that is a prefix of $s[i..]$, of some length $\ell$, followed by a cutting of $s[i+\ell..]$. Splitting the cuttings by the first word gives $\text{ways}[i] = \sum \text{ways}[i + \ell]$ over the lengths $\ell$ found in step 3; the empty rest has one cutting, the empty one.
6. Computing $\text{ways}$ from the end of the text to the start needs one walk per place, so $O(|s| \cdot L)$ in all. $\square$

:::note[This proof needs]
1. The dictionary is fixed before the walks; the trie is built once, in $O(S)$.
2. The cost of a walk is the length of the *longest* word, not the number of words; this is the gain over trying every word at every place ($|s| \cdot k \cdot L$ in the worst case) or every substring of length up to $L$ in a set of strings ($|s| \cdot L$ substrings, each costing $O(L)$ to hash).
3. If the cuttings must use each word at most once, or at most a given number of times, the counts $\text{ways}[i]$ are not enough; more state is needed.
:::

<TheoremCode unit="6.3/thm-3" />

The first line is the tiny instance: the lengths 1 and 2 at place 0, and 4 cuttings of abab. The second, with the dictionary aa and a, counts 5 cuttings of aaaa (the cuttings are 1+1+1+1, 1+1+2, 1+2+1, 2+1+1, 2+2). The third has no cutting of abac with the words ab and c. The check compares the walk with a test of all substrings and the cuttings with a plain recursion, on every string of length 1 to 8 over $\{a, b\}$ and three dictionaries.

### 4.4 Counts that change

**Theorem 6.3.4 (counts that change).** Let the trie hold the multiset of words $W$ with the counts $\text{pass}$ of Theorem 6.3.1. (a) Storing one more copy of a word $w$ adds 1 to $\text{pass}$ of the root and of every node on the path of $w$, and removing a stored copy of $w$ subtracts 1 from the same nodes; no other count changes. After each such change, $\text{pass}[v]$ is again the number of words of the current multiset that begin with the string of $v$. (b) Each change costs $O(|w|)$. (c) To forbid a beginning $u$ (remove every stored word that begins with $u$ and refuse later ones), let $v$ be the node of $u$ and $k = \text{pass}[v]$; subtract $k$ from $\text{pass}$ of the root and of every node on the path of $u$ and mark $v$ blocked; a later word whose path meets a blocked node is not stored. After this, $\text{pass}$ is again the number of live words that begin with each string that a walk can reach, in $O(|u|)$ time.

:::tip[In plain words]
Storing a word adds 1 to the counts of the nodes of its own path and removing it subtracts 1; nothing else moves. So the count for any beginning is up to date after every change, and a question about a beginning still reads one number. Forbidding a beginning is one subtraction along a path: the whole branch below it dies at once.
:::

**A tiny instance.** Store ab, abc, b: $\text{pass}[\text{a}] = 2$, $\text{pass}[\text{ab}] = 2$, $\text{pass}[\text{b}] = 1$. Remove ab: the root, a and ab lose 1, so $\text{pass}[\text{a}] = \text{pass}[\text{ab}] = 1$ (only abc is left). Forbid ab: $k = \text{pass}[\text{ab}] = 1$, subtract 1 from the root, a and ab, and mark ab blocked; now no stored word begins with a, and a later abd is refused.

**Proof.**
1. *Part (a).* By Theorem 6.3.1 (b), $\text{pass}[v]$ counts the words of the multiset that begin with the string of $v$. A word $w$ begins with the string of $v$ exactly when $v$ is on the path of $w$ (or $v$ is the root). So adding a copy of $w$ changes the number for exactly the nodes of its path, each by 1, and removing a copy changes the same nodes by $-1$.
2. *Part (b).* The path has $|w|$ nodes besides the root, and each is changed in constant time.
3. *Part (c).* The $k$ live words that begin with $u$ are exactly the words counted at $v$. Removing them from the multiset lowers the count of every ancestor of $v$ (and of the root) by $k$, because each of those words passes through all of them, and lowers the count of $v$ to 0. The counts below $v$ are not touched in the code, because a walk that meets a blocked node stops there and never reads them.
4. A later word that begins with $u$ would pass through $v$; it is refused, so no count that a walk can read changes. A later word that does not begin with $u$ does not meet $v$ and is stored as in (a).
5. A question for a beginning that passes through $v$ answers 0 (the walk stops at the blocked node), and a question for a beginning that is a proper beginning of $u$ reads an ancestor of $v$, whose count was lowered by $k$ in step 3. $\square$

:::note[This proof needs]
1. A removal must remove a copy that is stored: removing a word that is not in the multiset makes counts negative.
2. A blocked node hides everything below it; if the words below must come back later, the blocking has to be undone on the path, which this theorem does not do.
3. Counts are numbers of words with repeats; a count of different words needs another kept value.
:::

<TheoremCode unit="6.3/thm-4" />

The first line is the tiny instance with the counts of the beginnings a, ab and c: 2, 2 and 0 (part (a)). The second line is the instance after the removal of ab (1 and 1). The third stores ab twice more and removes one copy: the count of ab is 2 and the count of the empty beginning, the root, is 3. The check, which does not use blocking, compares the counts with a search of a multiset by hand, on random sequences of storing and removing words of length 1 to 3 over $\{a, b\}$ and eight beginnings. ## 6. Templates

Four templates. Each shows only the function that matters; the program around it reads the input. The first three use the `Trie` of Theorem 6.3.1 and the last one the `CountTrie` of Theorem 6.3.4 (they stay in the file outside the shown code and are said to be used). Each template is checked against a brute force that compares strings directly, on thousands of random small inputs (words over one to three letters, so that equal beginnings are common) and on fixed tests with one element, all elements equal and large sizes.

### The first word with a given prefix (Theorem 6.3.1, data kept on the nodes)

<CodeSnippet unit="6.3/first-with-prefix" />

**How it works.** Besides the counts of the trie, every node `v` keeps `first[v]`, the smallest index of an inserted word that passes through it. After each insertion `first` is made as long as the number of nodes (`resize` fills the new entries with `INT_MAX`, a very large number from the standard library), and the word is walked once more to lower `first` on its path. The words are inserted in the order of their indices, so the first one to reach a node already has the smallest index there; the `min` makes the code correct for any insertion order. A query walks its string with `find` and reads `first` of the node it ends in, or answers $-1$ when the walk falls off the tree. A query string must not be empty (the root has no `first`).

**Alternative formulation.** Sort the words and keep the index with each; the words with a prefix are a stretch of the sorted list, and the smallest index in the stretch is a range minimum ([topic 5.1](../../phase-5/5-1-sparse-table/)): two binary searches and one table query per question, with no tree.

### The longest common prefix with any other word (Theorem 6.3.2 (c))

<CodeSnippet unit="6.3/best-prefix-with-others" />

**How it works.** All words are inserted, so `pass` of a node is the number of words that begin with its string. For a word the loop walks its path and remembers the largest depth at which `pass` is at least 2: the word itself is counted in `pass`, so a second word must pass through the node too. The depth of the deepest such node is the length of the longest common prefix with another word (an equal word makes the whole path count). The walk never falls off the tree, because the word itself was inserted.

**Alternative formulation.** Sort the words: the best partner of a word is one of its two neighbours in sorted order, so the answer is the larger of two common-prefix lengths with the neighbours ([topic 1.1](../../phase-1/1-1-sorting/)); equal words are neighbours. It needs the comparison of neighbours letter by letter, $O(S)$ in all.

### The number of cuttings into dictionary words (Theorem 6.3.3)

<CodeSnippet unit="6.3/count-cuttings" />

**How it works.** `ways[i]` is the number of cuttings of the rest of the string from place `i`, and `ways[n] = 1` (the empty rest). The loop goes from the end of the string to the start, so that every `ways[j + 1]` it reads is final. For the place `i` the inner loop walks the string down the trie; `child[v][c] == 0` means no word begins with these letters, so the walk stops; at a node where a word ends, `end[v]` is positive and `ways[j + 1]` is added. The additions are taken modulo $10^9 + 7$ ([topic 2.2](../../phase-2/2-2-modular-arithmetic/)). The trie of the dictionary is built once and passed in.

**Alternative formulation.** Put all words in a set of strings and test the substrings of each place up to the length of the longest word: simpler, and fine when the words are short (up to about 20 letters).

### Strings forbidden as beginnings (Theorem 6.3.4)

<CodeSnippet unit="6.3/forbidden-prefix" />

**How it works.** Two sets of strings start empty: the strings of the first kind are forbidden beginnings and the strings of the second kind are the ones to count. The `CountTrie` of Theorem 6.3.4 also gets a `blocked` flag per node (kept in the file outside the shown code). For each query the string is walked and its path is recorded; `covered` becomes true if the walk meets a blocked node, which means that a forbidden beginning already covers the string, so nothing changes. Otherwise a string to count adds 1 along its path, and a forbidden string subtracts the count `k` of its node along the path and blocks the node. The answer after each query is the count at the root. `const auto& [type, s]` unpacks a pair into two names.

**Alternative formulation.** Offline, if all queries are known: sort the forbidden strings and keep only those that are not covered by a shorter one, then count the strings to count against them; it is longer than the trie and does not give the answer after every query.

## 7. Bug catalogue

Each bug below was made by changing one line of a template and running the random stress test against the brute force; the input shown is the smallest one found among thousands of random cases.

### Bug: the last word instead of the first

Template: the first word with a given prefix.

```cpp
first[v] = i;                                      // instead of first[v] = min(first[v], i)
```

Input: `2`, then the words `aa` and `aa`, then `1`, then the query `a`.

Wrong output `2`, correct output `1`. Both words go through the node a, and the second insertion overwrites the index of the first with a larger one. A value kept on a node must be combined with what is already there (here, by the minimum), not replaced; the counts `pass` work the same way, by adding (Theorem 6.3.1 (b)).

**Fix:** take the minimum.

### Bug: a node with one word counts as shared

Template: the longest common prefix with any other word.

```cpp
if (t.pass[v] >= 1) best = depth;                  // instead of >= 2
```

Input: `1`, then the word `b`.

Wrong output `1`, correct output `0`. The word itself passes through every node of its path, so `pass` is at least 1 everywhere; a node is shared with another word only when at least two words pass through it (Theorem 6.3.2 (c)). With a single word the answer must be 0.

**Fix:** require `pass >= 2`.

### Bug: the walk does not stop at a missing edge

Template: the number of cuttings into dictionary words.

```cpp
v = dictionary.child[v][s[j] - 'a'];               // the line  if (!v) break;  is missing
```

Input: `ba`, then `1`, then the word `a`.

Wrong output `1`, correct output `0`. From the place 0 the letter b has no edge, so `v` becomes 0, the root, and the walk goes on as if it had started again at the root: the next letter a leads to the word a, and `ways[2]` is added to `ways[0]`. Node 0 means "no edge", and a walk that reaches it must stop (Theorem 6.3.3, step 2).

**Fix:** stop the walk when `v` is 0.

### Bug: the places are visited from the left

Template: the number of cuttings into dictionary words.

```cpp
for (int i = 0; i < n; i++) {                      // instead of i = n - 1 down to 0
```

Input: `aa`, then `1`, then the word `a`.

Wrong output `0`, correct output `1`. The value `ways[i]` needs `ways[j + 1]` of later places. Going from the left, the place 0 is computed first and reads `ways[1]`, which is still 0 because place 1 has not been processed; so `ways[0]` stays 0 (Theorem 6.3.3, step 6: compute from the end of the text).

**Fix:** loop from the last place to the first.

### Bug: the ancestors keep the count of a forbidden branch

Template: strings forbidden as beginnings.

```cpp
t.pass[v] -= k;                                    // instead of  for (int u : path) t.pass[u] -= k;
```

Input: `2`, then `2 ab` and `1 ab`.

Wrong output `1` for the second query, correct output `0`. The forbidden beginning ab kills the string ab, but only the count of the node ab is lowered; the root still says 1 live string, because the string passed through the root and through a too (Theorem 6.3.4 (c), step 3).

**Fix:** subtract `k` from every node of the path.

### Bug: a string under a blocked node is still counted

Template: strings forbidden as beginnings.

```cpp
if (true) {                                        // instead of  if (!covered) {
```

Input: `3`, then `1 a`, `2 ab` and `2 b`.

Wrong output `0`, `1`, `2`, correct output `0`, `0`, `1`. The string ab begins with the forbidden a, so it must be refused. Without the test it is added along its path and the root count rises (Theorem 6.3.4 (c), step 4).

**Fix:** store a string only when its walk meets no blocked node.

## 8. Worked examples

### Example 1: Yet Another Sigma Problem

[AtCoder ABC 353 E: Yet Another Sigma Problem](https://atcoder.jp/contests/abc353/tasks/abc353_e). In short: for strings $x$ and $y$ let $f(x, y)$ be the length of their longest common prefix; given $N$ strings with total length at most $3 \cdot 10^5$, print the sum of $f(S_i, S_j)$ over all pairs $i < j$.

#### Step 1: Constraints → budget

$N$ up to $3 \cdot 10^5$ gives $N^2 / 2 = 4.5 \cdot 10^{10}$ pairs, too many even if each pair cost one step. The total length is $3 \cdot 10^5$, so a solution that takes time proportional to the total length is needed.

#### Step 2: Question form → candidate tools

- All pairs, comparing letter by letter ([topic 0.5](../../phase-0/0-5-brute-force/)): $4.5 \cdot 10^{10}$ pairs.
- Sort the strings and use the common prefix of neighbours with a stack ([topic 1.6](../../phase-1/1-6-monotonic-stack/)): possible but longer.
- A trie with pass counts: the card "Words that share beginnings: counts, longest common prefixes, per-node data (trie)".

#### Step 3: Property check → decision

The question is the sum over pairs of the common beginning, and Theorem 6.3.2 (b) writes this as a sum over nodes. The sum is up to about $\binom{N}{2}$ times the length, so it needs a 64-bit integer. Decision: a trie with pass counts.

#### Step 4: Proof for this problem

By Theorem 6.3.2 (b) the sum of $f(S_i, S_j)$ over all pairs is the sum over non-root nodes $v$ of the trie of $\binom{\text{pass}[v]}{2}$, where $\text{pass}[v]$ counts the strings that begin with the string of $v$. The trie has at most $3 \cdot 10^5 + 1$ nodes (Theorem 6.3.1 (a)), so the sum is one pass over the nodes.

### Example 2: Find the Length of the Longest Common Prefix

[LeetCode 3043: Find the Length of the Longest Common Prefix](https://leetcode.com/problems/find-the-length-of-the-longest-common-prefix/). In short: two arrays of positive integers up to $10^8$, up to $5 \cdot 10^4$ numbers each; a prefix of a number is formed by some of its digits from the left; find the length of the longest common prefix over all pairs $(x, y)$ with $x$ from the first array and $y$ from the second, or 0.

#### Step 1: Constraints → budget

$n = m = 5 \cdot 10^4$ gives $2.5 \cdot 10^9$ pairs, each compared in up to 9 digits: too many. A solution in about $9 (n + m) = 9 \cdot 10^5$ steps is possible.

#### Step 2: Question form → candidate tools

- All pairs, digit by digit ([topic 0.5](../../phase-0/0-5-brute-force/)): $2.5 \cdot 10^9$ pairs.
- A set of all prefixes of the first array: for each number of the second array test its prefixes from the longest ([topic 0.6](../../phase-0/0-6-stl-toolbox/)); about $9 (n + m)$ set operations.
- A trie of the digits of the first array: the card "Words that share beginnings: counts, longest common prefixes, per-node data (trie)".

#### Step 3: Property check → decision

The question is about the beginning of numbers written in decimal, which are strings of at most 9 digits. The first array is a set of strings and every number of the second is a query that asks for the longest beginning that is also a beginning of a stored string. Decision: a trie of the digits of the first array; the answer for a query is how far its walk goes.

#### Step 4: Proof for this problem

Write each number as a string of digits. By Theorem 6.3.1 (b), the walk of a string $u$ from the root of the trie of the first array's strings ends at the first digit where no stored string continues $u$, so the depth reached is the length of the longest common prefix of $u$ with some stored string. The maximum over the second array's numbers is the answer. Each walk takes at most 9 steps.
