## 1. Why this topic exists

Here is a small problem. There are $n \le 20$ apples with weights up to $10^9$. Split them into two groups so that the difference of the group weights is as small as possible.

Is there a clever rule? "Put each apple into the lighter group" fails: for weights $3, 3, 2, 2, 2$ it builds $\{3, 2, 2\}$ and $\{3, 2\}$ (difference 2), while $\{3, 3\}$ and $\{2, 2, 2\}$ have difference 0. Finding a rule that always works is hard. But there are only $2^{20} \approx 10^6$ ways to split 20 apples, and checking one split takes 20 additions: about $2 \cdot 10^7$ steps, a fraction of a second (topic 0.2).

This topic is about such exhaustive search, called **brute force**: list every candidate, check each one, keep the best. It is often the whole solution when the input is small, and it is always the reference to test a faster solution against (every template in this course has a brute force next to it). Brute force needs two things: a count of the candidates, to know it fits the budget; and a systematic way to list them, so that none is missed. This lesson gives four ways to list candidates: nested loops, bitmasks for subsets, `next_permutation` for orders, and recursion for sequences of choices.

## 3. Definitions

- The **search space** of a problem is the set of all candidates that might be the answer. Example: for "choose some of 3 apples", the search space has $2^3 = 8$ subsets.
- **Brute force** (exhaustive search) checks every candidate in the search space.
- A **bitmask** is an integer used as a set: element $i$ belongs to the set exactly when bit $i$ of the integer is 1. Bit $i$ of `mask` is `(mask >> i) & 1`, and `1 << i` is the number with only bit $i$ set. Example: with $n = 4$, the mask $11 = 1011_2$ is the set $\{0, 1, 3\}$.
- A **permutation** of a list is an arrangement of all its elements in some order. Example: $(2, 0, 1)$ is a permutation of $(0, 1, 2)$; there are $n!$ permutations of $n$ different elements.
- **Lexicographic order** compares two sequences at the first position where they differ, like words in a dictionary. Example: $(1, 3, 2) < (2, 1, 3)$ because $1 < 2$ at the first position.
- A function is **recursive** if it calls itself. Each call must make the problem smaller, and a **base case** handles the smallest problem without a further call. The **recursion depth** is the largest number of calls active at the same time.

## 4. Theory and proofs

### 4.1 Exhaustive search and counting candidates

**Theorem 0.5.1 (exhaustive search).**
1. If every candidate in the search space is checked, and the answer is one of the candidates (or a best value over them), then exhaustive search returns the correct answer.
2. Its cost is (number of candidates) × (cost of checking one), plus the cost of listing them.
3. The common search spaces have these sizes: pairs $i < j$ of $n$ items: $n(n-1)/2$; triples $i < j < k$: $n(n-1)(n-2)/6$; subsets: $2^n$; orders: $n!$; sequences of length $L$ with $k$ choices per position: $k^L$.

:::tip[In plain words]
If you check every candidate and keep the best, you get the right answer; the cost is the number of candidates times the cost of one check. Pairs, triples, subsets and orders have well-known counts, so the budget can be checked before coding.
:::

**A tiny instance.** For $a = (1, 2, 3, 4, 5)$ there are $5 \cdot 4 / 2 = 10$ pairs $i < j$. Checking all of them finds the pairs with sum 6: $(1, 5)$ and $(2, 4)$.

**Proof.**
1. Part 1. Every candidate is examined and the best one (or the one that passes) is kept, so the result is the best over the whole search space, which contains the answer.
2. Part 2. Add the cost of each check: the number of candidates times the cost of one check, plus the cost of listing them.
3. Part 3, pairs. Each of the $n(n-1)$ ordered pairs with $i \ne j$ is counted twice, once in each order, so there are $n(n-1)/2$ unordered pairs.
4. Triples. The $n(n-1)(n-2)$ ordered triples of different items contain each unordered triple $3! = 6$ times, so there are $n(n-1)(n-2)/6$.
5. Subsets. Each of the $n$ items is in or out, independently: $2^n$. Orders. $n$ choices for the first position, $n - 1$ for the second, and so on: $n!$.
6. Sequences. $k$ choices at each of $L$ positions: $k^L$. $\square$

:::note[This proof needs]
1. The search space really contains the answer: no candidate is missing and no constraint of the statement is dropped.
2. The number of candidates times the cost of one check fits the budget.
:::

<TheoremCode unit="0.5/thm-1" />

The second and third example are the limits in the table below: $5 \cdot 10^7$ pairs for $n = 10^4$ and $8.5 \cdot 10^7$ triples for $n = 800$, both about one second.

Rough limits for about $10^8$ simple steps:

| search space | size | largest $n$ |
|---|---|---|
| pairs | $n^2/2$ | about $10^4$ |
| triples | $n^3/6$ | about 800 |
| subsets, checked in $O(n)$ | $2^n \cdot n$ | about 20–22 |
| orders, checked in $O(n)$ | $n! \cdot n$ | about 9–10 |

**Fixing all but one variable.** If a candidate is a tuple $(x, y, z)$ with $x + y + z = S$, loop over $x$ and $y$ only and compute $z = S - x - y$, then check that $z$ is allowed. The search space shrinks from $(S+1)^3$ to $(S+1)^2$ without missing anything, because $z$ is determined by the others. This is often the step that makes nested loops fit.


### 4.2 Subsets as bitmasks

**Theorem 0.5.2 (bitmasks).** For $n$ items numbered $0, \dots, n-1$, the integers $0, 1, \dots, 2^n - 1$ correspond one-to-one to the subsets of the items: the subset of `mask` contains item $i$ exactly when `(mask >> i) & 1` is 1. So the loop `for (mask = 0; mask < (1 << n); mask++)` lists every subset exactly once, and checking each in $O(n)$ costs $O(2^n \cdot n)$.

:::tip[In plain words]
The numbers from 0 to 2^n − 1, written in binary, correspond one to one to the subsets of n items, with bit i telling whether item i is in. A single loop over the numbers lists every subset exactly once.
:::

**A tiny instance.** For $n = 3$ the mask $5 = 101_2$ has bits 0 and 2 set, so it is the subset $\{0, 2\}$; mask 0 is the empty set and mask 7 the set of all three items.

**Proof.**
1. Every integer in $[0, 2^n)$ has a unique binary representation with $n$ digits (bits $0$ to $n-1$), and every choice of $n$ bits is the representation of exactly one integer in that range.
2. Reading bit $i$ as "item $i$ is in" turns each integer into a subset and each subset into an integer, and these two maps undo each other.
3. `mask >> i` shifts bit $i$ into position 0, and `& 1` keeps only that bit, so the test is 1 exactly when item $i$ is in. $\square$

:::note[This proof needs]
1. $n$ is small enough that `1 << n` fits the type: $n \le 30$ for `int`, $n \le 62$ for `1LL << n`, and in practice $2^n \cdot n$ must fit the budget.
2. Each subset can be checked on its own, without knowing the results of other subsets.
:::

<TheoremCode unit="0.5/thm-2" />

The two examples are mask 5 and mask 0 for $n = 3$; the complement mask of $101_2$ is $010_2 = 2$.

A trace for $n = 3$:

| mask | binary (bits 2, 1, 0) | subset |
|---|---|---|
| 0 | 000 | $\{\}$ |
| 1 | 001 | $\{0\}$ |
| 2 | 010 | $\{1\}$ |
| 3 | 011 | $\{0, 1\}$ |
| 4 | 100 | $\{2\}$ |
| 5 | 101 | $\{0, 2\}$ |
| 6 | 110 | $\{1, 2\}$ |
| 7 | 111 | $\{0, 1, 2\}$ |

The complement of `mask` (the items not in it) is `((1 << n) - 1) ^ mask`: `(1 << n) - 1` has all $n$ bits set, and `^` (exclusive or) sets a bit of the result exactly when one of the two numbers has it, so every bit of `mask` is flipped; for a split into two groups, the second group is the complement of the first.


### 4.3 All orders with `next_permutation`

**Theorem 0.5.3 (next permutation).** Let $a$ be a sequence that is not in decreasing order. Let $i$ be the largest index with $a_i < a_{i+1}$, and $j$ the largest index with $a_j > a_i$. Swapping $a_i$ and $a_j$ and then reversing $a_{i+1}, \dots, a_{n-1}$ produces the smallest arrangement of the same elements that is lexicographically greater than $a$. Consequently, starting from the sorted sequence and repeating this step until the sequence is in decreasing order visits every distinct arrangement exactly once, in increasing lexicographic order. C++'s `next_permutation(a.begin(), a.end())` does this step and returns `false` (after sorting the sequence back) when $a$ was already the largest.

:::tip[In plain words]
Starting from the sorted sequence and repeatedly taking the next larger arrangement visits every distinct arrangement exactly once, in increasing order. Starting from an unsorted sequence skips the arrangements before it.
:::

**A tiny instance.** From $a = (1, 3, 2)$: $i = 0$ (since $1 < 3$) and $j = 2$ (the last value above 1 is 2). Swap to get $(2, 3, 1)$, then reverse the part after position 0 to get $(2, 1, 3)$, the next arrangement after $132$.

**Proof.**
1. By the choice of $i$, the suffix $a_{i+1} \ge a_{i+2} \ge \dots \ge a_{n-1}$ is in non-increasing order, which is the largest possible arrangement of its elements.
2. So no arrangement that keeps $a_0, \dots, a_i$ is greater than $a$; a greater one must change some position $\le i$.
3. Keeping $a_0, \dots, a_{i-1}$ and putting at position $i$ a larger value from the suffix gives greater arrangements, and any arrangement that changes an earlier position upward is greater than all of those.
4. The smallest choice at position $i$ is the smallest suffix value that exceeds $a_i$; the suffix is non-increasing, so that is $a_j$ with $j$ the *largest* index with $a_j > a_i$.
5. After the swap the suffix is still non-increasing (the value $a_i$ now at position $j$ is at least $a_{j+1}$ and less than $a_{j-1}$, by the choice of $j$), and its smallest arrangement is its increasing order, which the reversal produces.
6. Each step moves to the immediate successor, so starting from the sorted sequence the loop visits every arrangement once, in order, until the decreasing one. $\square$

:::note[This proof needs]
1. The loop starts from the sorted sequence; otherwise the arrangements before the starting one are skipped.
2. The number of distinct arrangements (at most $n!$) times the cost of checking one fits the budget. With repeated values each distinct arrangement is visited once, so there are fewer than $n!$.
:::

<TheoremCode unit="0.5/thm-3" />

The first example lists all $3! = 6$ arrangements; the second has a repeated value and only 3 distinct arrangements.

A trace for $(1, 2, 3)$: $123 \to 132 \to 213 \to 231 \to 312 \to 321$, then `next_permutation` returns `false`. For $(1, 1, 2)$ it gives only $112 \to 121 \to 211$: three distinct arrangements, not $3! = 6$.


### 4.4 Recursive generation

**Theorem 0.5.4 (recursive choices).** Consider the function

```
rec(pos):
    if pos == L: check the current sequence c[0..L-1]; return
    for each allowed choice v at position pos:
        c[pos] = v
        rec(pos + 1)
```

Called as `rec(0)`, it checks every sequence $c_0, \dots, c_{L-1}$ with each $c_p$ allowed, exactly once. With $k$ choices per position, it checks $k^L$ sequences, makes fewer than $2k^L$ calls when $k \ge 2$, and its recursion depth is $L + 1$.

:::tip[In plain words]
A function that fills one position, tries every allowed value there and calls itself for the next position checks every sequence exactly once. It works even when the number of positions comes from the input.
:::

**A tiny instance.** $L = 2$ positions with $k = 3$ choices: `rec(0)` tries 1, 2, 3 at position 0, and for each calls `rec(1)`, which tries 1, 2, 3 again: $3 \cdot 3 = 9$ sequences $11, 12, 13, 21, \dots, 33$.

**Proof.**
1. Claim: with $c_0, \dots, c_{pos-1}$ fixed, `rec(pos)` checks every completion $c_{pos}, \dots, c_{L-1}$ exactly once. The proof is by induction on $L - pos$.
2. Base case: for $pos = L$ there is exactly one completion (the empty one), and the base case checks it.
3. Step: the loop tries each allowed $c_{pos}$ once, and for each, by the claim for $pos + 1$, `rec(pos + 1)` checks every completion of the rest exactly once. Different values of $c_{pos}$ give different sequences.
4. For the count, level $p$ of the recursion has $k^p$ calls, and $1 + k + \dots + k^L = (k^{L+1} - 1)/(k - 1) < 2k^L$ for $k \ge 2$. $\square$

:::note[This proof needs]
1. The allowed choices at position $pos$ may depend on the earlier choices (for example "at least $c_{pos-1}$" for a non-decreasing sequence), but the loop must try all of them.
2. The number of sequences times the check fits the budget, and the depth $L$ is small (a few thousand calls deep is safe; very deep recursion can overflow the call stack).
:::

<TheoremCode unit="0.5/thm-4" />

The first example is the tiny instance, the second $2^3 = 8$ sequences; in both the sequences come out in lexicographic order.

Recursion is the tool when the number of positions $L$ is part of the input: nested loops would need $L$ loops written in the code. When each position has exactly 2 choices, a bitmask (Section 4.2) lists the same sequences without recursion.


### 4.5 Enumerating the answer

**Theorem 0.5.5 (trying every answer).** If the answer is the smallest integer $x$ in a known range $[lo, hi]$ that satisfies a property $P$, then testing $x = lo, lo + 1, \dots$ and stopping at the first $x$ with $P(x)$ true returns the answer after $(x - lo + 1)$ tests; if no $x \le hi$ passes, there is no answer.

:::tip[In plain words]
If the answer is the smallest value in a known range that passes a test, trying the values from the smallest up and stopping at the first success returns it. If none passes, there is no answer.
:::

**A tiny instance.** The smallest $x$ in $1..100$ with $x^2 \ge 50$: testing $x = 1, 2, \dots$ the first success is $x = 8$ ($49 < 50 \le 64$), after 8 tests.

**Proof.**
1. Every $x$ smaller than the returned one was tested and failed, and the returned one passes, so it is the smallest.
2. If the loop reaches $hi$ without success, every value in the range was tested and failed, so there is no answer. $\square$

:::note[This proof needs]
1. A proven bound $[lo, hi]$ that contains the answer if it exists; the bound often comes from the constraints (for example "the answer is at most 1000" or "the price is at most $10^4$").
2. The range size times the cost of one test fits the budget.
:::

<TheoremCode unit="0.5/thm-5" />

The third example has no answer: $x^2 = 50$ has no integer solution in $1..10$, and the loop reports $-1$ after testing all ten values.

The same idea applies when the answer is not searched directly but one key quantity is: for "how many pizzas of the mixed kind to buy" or "which value to put first", try every value of that one quantity and compute the rest (Section 4.1).

## 6. Templates

Five short functions, one for each card. Each brute force lists the same search space a different way, which is what makes it a useful check.

### Nested loops, computing the last variable (Theorem 0.5.1)

<CodeSnippet unit="0.5/weighted-sum" />

**How it works.** A candidate is a triple $(x, y, z)$, but once $y$ and $z$ are chosen, $x = S - 2y - 3z$ is forced. So two loops run over $y$ and $z$, compute $x$, and count the triple if $x$ is in $[0, K]$. Each triple with $x + 2y + 3z = S$ is counted exactly once, at its own $(y, z)$. For $K = 3000$ that is $3001^2 \approx 9 \cdot 10^6$ steps, while three loops would take $2.7 \cdot 10^{10}$.

**Alternative formulation.** Loop over $z$ only and count the $y$ for which $x$ falls in $[0, K]$ with a formula: one loop, but the bounds need care. The two-loop version is the safe default when it fits.

### All subsets with a bitmask (Theorem 0.5.2)

<CodeSnippet unit="0.5/subset-sum-range" />

**How it works.** `mask` runs over $0, \dots, 2^n - 1$, one integer per subset. For each, the inner loop adds `a[i]` exactly when bit $i$ is set, and the subset is counted if its sum is in $[L, R]$. The cost is $2^n \cdot n \approx 2 \cdot 10^7$ for $n = 20$.

**Alternative formulation.** The recursion of the brute force (take or skip item $i$, then continue with $i + 1$) lists the same subsets with the sum carried along, so each subset costs $O(1)$ instead of $O(n)$: $O(2^n)$ in total.

### All orders with `next_permutation` (Theorem 0.5.3)

<CodeSnippet unit="0.5/best-order" />

**How it works.** `order` starts as $0, 1, \dots, n - 1$, the smallest arrangement. The `do { … } while (next_permutation(…))` loop checks the current order first and then moves to the next one, so every one of the $n!$ orders is checked once, the sorted one included. For $n = 9$: $9! \cdot 8 \approx 2.9 \cdot 10^6$ additions.

**Alternative formulation.** The recursion of the brute force is the same search written by hand. It is useful when some orders can be rejected early, which `next_permutation` cannot do.

### Recursive generation (Theorem 0.5.4)

<CodeSnippet unit="0.5/bounded-steps" />

**How it works.** `rec(pos)` fills position `pos` with every allowed value and calls itself for `pos + 1`; the base case `pos == L` records a finished sequence. The allowed values depend on the previous choice ($|v - c_{pos-1}| \le D$), which a fixed set of loops could also do, but the *number* of positions $L$ comes from the input: recursion handles any $L$ with the same code. Values are tried in increasing order at every position, so the sequences come out in lexicographic order.

**Alternative formulation.** Counting in base $M$, as the brute force does, lists all $M^L$ sequences with one loop; the recursion skips invalid sequences as soon as one position breaks the rule, so it does less work when the condition is strict.

### Trying every answer (Theorem 0.5.5)

<CodeSnippet unit="0.5/smallest-answer" />

**How it works.** The answer is bounded by $10^6$, so the loop tests $x = 1, 2, \dots$ in order and prints the first $x$ that is a multiple of $K$ with digit sum $S$. By Theorem 0.5.5 that is the smallest. At most $10^6$ tests of about 7 steps each.

**Alternative formulation.** Loop over the multiples of $K$ only ($x = K, 2K, \dots$), which tests $10^6 / K$ values instead of $10^6$.

## 7. Bug catalogue

Each bug was made by changing a template from Section 6 (one line, or the two lines of one loop) and running `scripts/stress.sh` on the broken copy. The input shown is the first one the script found.

### Bug: forgetting a bound on the computed variable

Template: nested loops, computing the last variable.

```cpp
if (0 <= x) count++;
```

Input: `5 25`

Wrong output `36`, correct output `5`. The computed $x = S - 2y - 3z$ can be larger than $K$ (for $y = z = 0$ it is 25), and such triples are not in the search space. When a variable is computed instead of looped over, every constraint the loop would have enforced must be checked by hand.

**Fix:** `if (0 <= x && x <= k)`: the computed variable must satisfy all of its own bounds (Theorem 0.5.1, condition 1).

### Bug: stopping one mask early

Template: all subsets with a bitmask.

```cpp
for (int mask = 0; mask < (1 << n) - 1; mask++) {
```

Input: `3 21 28` and the values `4 10 13`.

Wrong output `1`, correct output `2`. The subsets with sums in $[21, 28]$ are $\{10, 13\}$ (23) and $\{4, 10, 13\}$ (27). The last mask, $2^n - 1 = 111_2$, is the set of all items, and the loop never reaches it.

**Fix:** `mask < (1 << n)`: the masks are $0, \dots, 2^n - 1$ inclusive (Theorem 0.5.2).

### Bug: testing bit i with mask & i

Template: all subsets with a bitmask.

```cpp
if (mask & i) sum += a[i];
```

Input: `6 26 34` and the values `8 15 9 11 5 15`.

Wrong output `0`, correct output `15`. `mask & i` tests whether `mask` and the *number* $i$ share a bit, not whether bit $i$ is set. For $i = 0$ it is always 0, so item 0 is never taken; for $i = 3 = 11_2$ it is true whenever bit 0 or bit 1 is set.

**Fix:** `(mask >> i) & 1`, or equivalently `mask & (1 << i)`: compare with the number whose only set bit is bit $i$.

### Bug: a while loop around next_permutation

Template: all orders.

```cpp
while (next_permutation(order.begin(), order.end())) {
    // check the current order
}
```

Input: `2`, then the costs `0 17` and `18 0`.

Wrong output `18`, correct output `17`. `next_permutation` changes the order *before* the first check, so the sorted order $(0, 1)$ is never examined, and here it is the best one.

**Fix:** `do { … } while (next_permutation(…));`, so the first order is checked before the first step (Theorem 0.5.3, condition 1).

### Bug: a base case without return

Template: recursive generation.

```cpp
if (pos == L) {
    found.push_back(c);
}
```

Input: `5 1 0`

Wrong output: the program crashes (segmentation fault). Correct output `1` and the sequence `1 1 1 1 1`. After recording the sequence, the call falls through into the loop, reads `c[pos - 1]` and writes `c[pos]` with `pos == L`, outside the vector, and keeps recursing deeper.

**Fix:** `return;` right after handling the base case. Every recursive function needs a base case that stops without a further call (Theorem 0.5.4).

## 8. Worked examples

### Example 1: Apple Division

[CSES 1623 Apple Division](https://cses.fi/problemset/task/1623) (CSES is the Code Submission Evaluation System problem set). In short: $n \le 20$ apples with weights up to $10^9$; split them into two groups so that the difference of the group weights is as small as possible, and print that difference.

#### Step 1: Constraints → budget

$n \le 20$ is a strong hint: $2^{20} \approx 10^6$, and $2^{20} \cdot 20 \approx 2 \cdot 10^7$ steps fit easily in 1 second. Weights up to $10^9$ make sums up to $2 \cdot 10^{10}$: `long long`.

#### Step 2: Question form → candidate tools

"Split into two groups" means each apple has two options: the card "All subsets as bitmasks" (Theorem 0.5.2). The other candidate is a rule such as "put the next apple into the lighter group", which needs no search; Section 1 shows it fails on $3, 3, 2, 2, 2$.

#### Step 3: Property check → decision

A split is determined by the set of apples in group 1; every subset is a valid split, and checking one costs $O(n)$. There are $2^n$ subsets. No rule is proved to work, while the search space is small. Decision: try every bitmask.

#### Step 4: Proof for this problem

Every split corresponds to exactly one mask (the apples in group 1), and the loop visits every mask (Theorem 0.5.2). For a mask with group-1 weight $s$, group 2 weighs $\mathit{total} - s$, so the difference is $|\mathit{total} - 2s|$. The minimum over all masks is therefore the minimum over all splits (Theorem 0.5.1). Each split is counted twice (a mask and its complement give the same difference), which does not change the minimum. Cost: $2^n \cdot n \approx 2 \cdot 10^7$.

### Example 2: One-stroke Path

[AtCoder Beginner Contest (ABC) 054, problem C: One-stroke Path](https://atcoder.jp/contests/abc054/tasks/abc054_c). In short: an undirected graph with $N \le 8$ vertices (each edge given as a pair of vertices); count the paths that start at vertex 1 and visit every vertex exactly once, moving only along edges.

#### Step 1: Constraints → budget

$N \le 8$. The paths visit the other 7 vertices in some order: at most $7! = 5040$ orders, each checked along 7 edges. Anything works.

#### Step 2: Question form → candidate tools

"Visit every vertex exactly once" asks for an order of the vertices: permutations (Theorem 0.5.3). A second candidate is recursion that walks along edges and never revisits a vertex (Theorem 0.5.4), which is what the brute force does.

#### Step 3: Property check → decision

A path starting at vertex 1 that visits all vertices once is the same as an order of the vertices $2, \dots, N$ in which vertex 1 and the first one are joined by an edge, and so is every consecutive pair. Every such order is one path and every path is one order. Decision: try all orders of $2, \dots, N$ with `next_permutation`, starting from the sorted order.

#### Step 4: Proof for this problem

The vector `rest` starts as $1, 2, \dots, n - 1$ (0-based), which is sorted, so the loop checks every order of the other vertices exactly once (Theorem 0.5.3). An order is counted exactly when vertex 0 is adjacent to the first vertex and every consecutive pair is adjacent, which is the definition of a valid path. Different orders are different paths. The cost is $(N-1)! \cdot (N-1) \le 35\,280$ steps.
