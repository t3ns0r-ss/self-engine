## 1. Why this topic exists

Here is a small problem. How many integers $x$ with $1 \le x \le N$, where $N = 10^{18}$, have a digit sum that is a multiple of 4?

Checking every $x$ ([topic 0.5](../../phase-0/0-5-brute-force/)) is $10^{18}$ steps. A formula ([topic 2.3](../../phase-2/2-3-combinatorics/)) works for "all numbers with exactly 18 digits", where every digit is free, but $N$ is an arbitrary number: below $N = 734\,519$ the allowed digits depend on the digits already chosen.

The key idea: write $x$ with as many digits as $N$ (with leading zeros) and compare it with $N$ from the most significant digit. Either $x = N$, or there is a first position where $x$ has a smaller digit than $N$; before it, $x$ copies $N$, and after it, every digit is free. So a walk along the digits of $N$ needs to remember only two things: whether the prefix still equals $N$'s prefix (a **tight** flag), and whatever small summary the property needs (here, the digit sum modulo 4). That is $19 \cdot 2 \cdot 4$ states with 10 digits each: a few thousand steps instead of $10^{18}$. This is **digit DP**.

### What this topic does not cover

## 3. Definitions

- The **decimal digits** of $N$ are $d_1 d_2 \dots d_L$, with $d_1$ the most significant. Every $x$ with $0 \le x \le N$ is written with exactly $L$ digits, using leading zeros. Example: for $N = 25$, $x = 7$ is written "07".
- A prefix of $x$ is **tight** if it equals the prefix of $N$ of the same length; then the next digit of $x$ can be at most the next digit of $N$. Once a digit is smaller than $N$'s, the prefix is **free** for good.
- A **leading zero** is a zero before the first non-zero digit; it is padding, not a digit of the number. The **started** flag says whether a non-zero digit has appeared.
- $F(N)$ denotes the number of $x$ in $[0, N]$ with the property.

## 4. Theory and proofs

### 4.1 The tight walk

**Theorem 3.8.1 (counting up to N).** Suppose whether $x$ has the property can be decided by reading its digits from left to right while keeping a state $s$ from a small set, updated as $s \leftarrow \delta(s, c)$ for each digit $c$. Let $\text{cnt}(i, t, s)$ be the number of ways to choose the digits at positions $i + 1..L$ so that the whole number has the property, given that the first $i$ digits led to state $s$ and the tight flag $t$. Then
$$\text{cnt}(i, t, s) = \sum_{c = 0}^{u} \text{cnt}\left(i + 1, \ t \wedge (c = d_{i+1}), \ \delta(s, c)\right), \qquad u = \begin{cases} d_{i+1} & \text{if } t,\\ 9 & \text{otherwise,} \end{cases}$$
with $\text{cnt}(L, t, s) = 1$ if $s$ is accepting and 0 otherwise. Then $F(N) = \text{cnt}(0, \text{true}, s_0)$. Time $O(L \cdot 2 \cdot |S| \cdot 10)$.

*Proof.* The numbers $0..N$ written with $L$ digits are exactly the digit strings that are not larger than $N$'s digit string. A string with a tight prefix can continue with a digit up to $d_{i+1}$ (a larger digit would make it larger than $N$), and the prefix stays tight only if the digit equals $d_{i+1}$; a free prefix can continue with any digit. So the recurrence lists every valid continuation once, split by the next digit (Theorem 3.5.1), and the state $s$ carries everything the property needs (Theorem 3.5.2). When the flag is false, the count does not depend on $N$ any more, so memoising $\text{cnt}(i, \text{false}, s)$ is safe; the tight states form a single path and need no memo. $\square$

:::note[This proof needs]
1. The property is decided by a left-to-right state with few values: a digit sum, a remainder, the previous digit, a count of non-zero digits, a mask of digits used.
2. Positions are counted from the most significant digit, so "smaller than $N$" is decided at the first difference.
3. $L$ is the number of digits of $N$ (18 for values below $10^{18}$; it can be $10^4$ if $N$ is given as a string).
:::

Example: $N = 25$, property "digit sum is a multiple of 4", state = digit sum mod 4. The first digit is 0, 1 (free) or 2 (tight):

| first digit | second digit allowed | numbers with the property | count |
|---|---|---|---|
| 0 (free) | 0–9 | 00, 04, 08 | 3 |
| 1 (free) | 0–9 | 13, 17 | 2 |
| 2 (tight) | 0–5 | 22 | 1 |

$F(25) = 6$: the numbers $0, 4, 8, 13, 17, 22$.

### 4.2 Ranges

**Theorem 3.8.2 (ranges).** The number of $x$ in $[A, B]$ with the property is $F(B) - F(A - 1)$ (with $F(-1) = 0$). When $A$ is given as a digit string too long for an integer, use $F(B) - F(A) + [A \text{ has the property}]$ instead of computing $A - 1$.

*Proof.* $[0, B]$ is the disjoint union of $[0, A - 1]$ and $[A, B]$, so the counts subtract; and $F(A - 1) = F(A) - [A \text{ has the property}]$. Modulo a prime, subtract as in Theorem 3.5.3. $\square$

:::note[This proof needs]
1. $F$ counts from 0 (or from 1, consistently in both terms).
2. Modulo $p$, add $p$ before taking the remainder of the difference.
:::

Example: in $[10, 25]$, the digit sums divisible by 4 belong to $13, 17, 22$: $F(25) - F(9) = 6 - 3 = 3$.

### 4.3 Leading zeros and neighbouring digits

Padding with leading zeros is harmless when the property ignores zeros (a digit sum, a remainder of the value). It is wrong when zeros matter: with the rule "no two equal neighbouring digits", the number 5 written as "005" would be rejected because of "00", although 5 has no neighbours at all.

**Theorem 3.8.3 (the started flag).** Add a flag $z$ to the state: $z$ is false while only zeros have been read. A zero read while $z$ is false keeps $z$ false and does not update the rest of the state; the first non-zero digit sets $z$ true. Then the recurrence of Theorem 3.8.1 counts every number $0..N$ once, with the property applied to its digits without padding.

*Proof.* Each number has one $L$-digit representation, so it is counted once. Its leading zeros leave the state as it was before any digit, so the property sees exactly the digits of the number from its first non-zero digit. The number 0 is the string of all zeros, with $z$ false at the end; count it or not as the problem requires. $\square$

:::note[This proof needs]
1. The rules (neighbours differ, digits non-decreasing, number of distinct digits) refer to the digits of the number itself, not its padding.
2. Check 0 separately: many problems count positive integers only.
:::

Example: among $1..100$ there are 90 numbers whose neighbouring digits all differ (9 one-digit numbers and 81 two-digit numbers; 100 fails). Without the started flag, the padded strings "001", …, "009" contain "00" and are rejected, and the count drops to 81.

### 4.4 Totals over a range

**Theorem 3.8.4 (count and total together).** Let each state return a pair (count, total), where count is the number of valid completions and total is the sum of a quantity $g$ over them. If $g$ is additive over digits (the digit sum, the number of times a digit appears), then putting digit $c$ in front of completions with pair $(n, T)$ contributes $(n, \ T + g(c) \cdot n)$. For the sum of the values themselves, a digit $c$ at a position with weight $10^k$ contributes $(n, \ T + c \cdot 10^k \cdot n)$.

*Proof.* Each of the $n$ completions gains $g(c)$ from the new digit, and the rest of its quantity is already in $T$. Summing over the digits allowed at the position adds up disjoint groups, as in Theorem 3.8.1. $\square$

:::note[This proof needs]
1. The quantity is a sum over digit positions (or a value built digit by digit), so it splits as "this digit" plus "the rest".
2. Both parts of the pair are computed from the same states; modulo a prime, reduce both.
:::

Example: the digit sums of $0..25$ add up to 127. By first digit: 0 gives $(10, 45)$, 1 gives $(10, 10 + 45) = (10, 55)$, and 2 (tight, second digit 0–5) gives $(6, 2 \cdot 6 + 15) = (6, 27)$; $45 + 55 + 27 = 127$.

## 6. Templates

Four programs, one per card, all with the same shape: a recursive `go(pos, state, tight, …)` that walks the digits of the bound, a memo used only for states that are no longer tight, and `countUpTo(N)` applied to $B$ and $A - 1$. The brute forces check every number of the range; the generators keep the ranges short (at most 1500 numbers) but place them anywhere up to $10^{18}$, so long bounds are tested too.

### Numbers with few different digits (Theorem 3.8.1)

<Code code={fewDistinct} lang="cpp" title="few-distinct/solution.cpp" />

**How it works.** The state is the set of digits used so far, a 10-bit mask (topic 3.7), plus the started flag: leading zeros are padding and do not add the digit 0 to the set (Theorem 3.8.3). The tight flag limits the next digit to $N$'s digit, and stays on only while the digits copy $N$. A completed string counts if its set has at most $K$ digits; the number 0 is the all-zero string and uses the digit 0. The answer for $[A, B]$ is $F(B) - F(A - 1)$ (Theorem 3.8.2).

**C++ details explained.** The memo arrays are global, so they start as zeros; `memset(seen, 0, sizeof seen)` resets them for each new bound, because the meaning of "position `pos`" depends on the length of $N$. `tight && c == hi` keeps the flag only when the digit equals $N$'s. `to_string(n)` gives the digits of a `long long`.

**Tested.** Stress-tested against a brute force that checks every number in the range, on 5000 random ranges (length up to 1500, placed up to $10^{18}$, $K \le 4$). There are also 5 fixed tests: $[0, 100]$ with $K = 1$ (19: the one-digit numbers and 11, 22, …, 99), $[1, 10^{18}]$ with $K = 10$ (all $10^{18}$), $[0, 0]$, and two large ranges whose answers come from a separate program.

**Alternative formulation.** Count each length separately with a free walk and handle only the numbers with exactly as many digits as $N$ with the tight walk; then no started flag is needed. It is longer to write and easier to get wrong at the boundaries.

### Two remainders (Theorem 3.8.1 with a pair as the state)

<Code code={twoRemainders} lang="cpp" title="two-remainders/solution.cpp" />

**How it works.** Reading a digit $c$ changes the value's remainder from $r$ to $(10r + c) \bmod M$ (topic 2.2) and the digit sum's remainder from $s$ to $(s + c) \bmod D$. Both are small, so the state is the pair. Leading zeros change neither remainder, so they need no special care.

**C++ details explained.** The memo has $20 \cdot 30 \cdot 30$ entries per array. `go` returns `long long`, since counts reach $10^{18}$. The test `rv == 0 && rs == 0` converts to 1 or 0 when returned as a number.

**Tested.** Stress-tested against a brute force over the range, on 5000 random inputs ($M, D \le 30$). There are also 5 fixed tests: the example of Section 4.1 ($[0, 25]$, $M = 1$, $D = 4$: 6) and of Section 4.2 ($[10, 25]$: 3), $[0, 10^{18}]$ with $M = D = 1$ ($10^{18} + 1$), and two large inputs from a separate program.

**Alternative formulation.** Tabulate instead of recursing: for each position, a table over (remainder pair) for the free part, and walk the tight path once, adding at each position the free counts for the digits below $N$'s digit. It is the same sum as Theorem 3.8.1, written as loops.

### Neighbouring digits (Theorem 3.8.3)

<Code code={windyNumbers} lang="cpp" title="windy-numbers/solution.cpp" />

**How it works.** The state is the previous digit of the number, with 10 meaning "none yet". While only zeros have been read, a zero is padding: the previous digit stays "none" and nothing is checked. From the first non-zero digit on, every digit must differ from the previous one by at least 2. Strings that break the rule are never built, so every completed string counts.

**C++ details explained.** `abs(c - prev) < 2` is the forbidden case. The first branch handles padding zeros with `continue`, so the rule below it only sees real digits. `prev` takes 11 values, so the memo has $20 \cdot 11 \cdot 2$ entries.

**Tested.** Stress-tested against a brute force over the range, on 5000 random inputs. There are also 5 fixed tests: $[1, 100]$ (73), $[0, 0]$ (1), $[25, 25]$ (1), and $[0, 10^{18}]$ and $[10^{17}, 10^{18}]$ (from a separate program).

**Alternative formulation.** Instead of the started flag, count the numbers of each length shorter than $N$ separately (first digit 1–9, then free digits) and run the tight walk only for $N$'s own length, with a first digit from 1. Leading zeros then never appear.

### Sum of digit sums (Theorem 3.8.4)

<Code code={digitSumTotal} lang="cpp" title="digit-sum-total/solution.cpp" />

**How it works.** `go` returns a pair: how many completions there are, and the total of their digit sums. Putting digit $c$ in front of $n$ completions with total $t$ adds $c$ to each of them: total $t + c \cdot n$. Summing over the allowed digits gives the pair for the state. The answer is the total for $B$ minus the total for $A - 1$, modulo $10^9 + 7$, with `+ MOD` before the remainder (Theorem 3.5.3).

**C++ details explained.** `auto [n, t] = go(...)` unpacks the pair. The memo has one entry per position, because the free part does not depend on anything else here. Counts are reduced modulo $10^9 + 7$ too, since $n$ reaches $10^{18}$ and $c \cdot n$ must not overflow.

**Tested.** Stress-tested against a brute force that adds the digit sums of the range, on 5000 random inputs. There are also 5 fixed tests: $[0, 25]$ (127, the example of Section 4.4), $[10, 25]$ (82), $[0, 10^{18}]$ and $[1, 10^{18}]$ (both $81 \cdot 10^{18} + 1$ modulo $10^9 + 7$), and a random large range (from a separate program).

**Alternative formulation.** Count, for each position and digit $c$, how many numbers up to $N$ have $c$ there (a formula with the digits of $N$ to the left and right), and add $c$ times that count. It is the classic "count the 1s" trick, faster to run and harder to get right.

## 7. Bug catalogue

Each bug below was made by changing a template from Section 6 and caught by `scripts/stress.sh`. The inputs shown are small failing inputs, found among the random seeds or by hand and checked against the brute force.

### Bug: memoising tight states

Template: numbers with few different digits.

```cpp
if (seen[pos][used][started]) return memo[pos][used][started];
...
seen[pos][used][started] = true, memo[pos][used][started] = total;
```

Input: `0 110 1` (numbers up to 110 with one distinct digit).

Wrong output `20`, correct output `19`. The memo key leaves out the tight flag, so the tight state "prefix 1, digits {1}" (where the next digits are limited by 110) and the free state with the same key share one value. Here the tight state receives the free count, which includes 111 > 110.

**Fix:** store and read only states that are not tight (Theorem 3.8.1); the tight states form a single path and are cheap anyway. Or put the flag into the key.

### Bug: the memo is not reset for the second bound

Template: two remainders.

```cpp
digits = to_string(n);
return go(0, 0, 0, true);   // memset removed
```

Input: `55 100 8 3`.

Wrong output `-2`, correct output `2` (72 and 96). The memo stores counts by position, but "position 1" means a different number of remaining digits for $N = 100$ (three digits) and for $A - 1 = 54$ (two digits). The second call reads counts computed for the first bound.

**Fix:** reset the memo for every bound, or index the states by the number of digits **remaining** (then the memo can be shared, since a free state's count depends only on that).

### Bug: the tight flag never turns off

Template: two remainders.

```cpp
total += go(pos + 1, (rv * 10 + c) % M, (rs + c) % D, tight);
```

Input: `0 25 1 4` (the example of Section 4.1).

Wrong output `4`, correct output `6`. Once a digit is smaller than $N$'s, the rest is free; keeping the flag limits every later digit to $N$'s digit, so 13 and 17 are never built (their second digit is above 5).

**Fix:** `tight && c == hi`: the prefix stays tight only while it copies $N$.

### Bug: leading zeros treated as digits

Template: neighbouring digits.

```cpp
for (int c = 0; c <= hi; c++) {
    if (prev != 10 && abs(c - prev) < 2) continue;   // the padding branch removed
```

Input: `0 12`.

Wrong output `8`, correct output `10` (0, 1, …, 9). The one-digit numbers are walked as "00", "01", …; then 0 followed by 0 or 1 breaks the rule, and the numbers 0 and 1 are lost.

**Fix:** a started flag (Theorem 3.8.3): before the first non-zero digit, a zero is padding and the rule is not checked.

### Bug: the digit counted once instead of once per completion

Template: sum of digit sums.

```cpp
total = (total + t + c) % MOD;
```

Input: `0 25`.

Wrong output `108`, correct output `127`. The digit $c$ is part of every one of the $n$ numbers that continue from it, so it adds $c \cdot n$, not $c$.

**Fix:** total $+ \ c \cdot n$ (Theorem 3.8.4). Check a pair by hand: for the prefix 2 of $N = 25$ the pair is $(6, 2 \cdot 6 + 15) = (6, 27)$.

### Bug: subtracting F(A) instead of F(A − 1)

Template: neighbouring digits.

```cpp
cout << countUpTo(b) - countUpTo(a) << "\n";
```

Input: `5 5`.

Wrong output `0`, correct output `1`. $F(B) - F(A)$ counts $(A, B]$ and loses $A$ itself.

**Fix:** $F(B) - F(A - 1)$ (Theorem 3.8.2); test with a one-number range $A = B$.
