## ac-dp_d Knapsack 1 (tier 2, pattern zero-one, set reserved, for lookalike)
- Budget: N ≤ 100, W ≤ 10^5.
- Idea: best[w] = max value with weight ≤ w; for each item loop w downward: best[w] = max(best[w], best[w − w_i] + v_i). long long.
- Techniques: 3.3
- Needs this topic because: the 0/1 knapsack template. Look-alike partner of Knapsack 2: same statement, W ≤ 10^5 here, so index by weight.
- Tier reasoning: EDP D.

## lc-count-of-sub-multisets-with-bounded-sum Count of Sub-Multisets With Bounded Sum (tier 4, pattern bounded, set practice)
- Budget: sum of nums ≤ 2·10^4: for each distinct value, one pass over the sums with a sliding window, O(distinct values × sum) ≈ 2·10^4 · 200.
- Idea: Group equal values. For a value v that occurs c times, new[s] = old[s] + old[s − v] + … + old[s − c·v], a window of c + 1 terms spaced v apart; update it in O(1) per cell with a running sum along each residue class modulo v (new[s] = new[s − v] + old[s] − old[s − (c + 1)v]). The zeros multiply the answer by (count of zeros + 1). Sum dp[l..r].
- Techniques: 3.3, 3.2
- Needs this topic because: a bounded-multiplicity knapsack whose total work must stay near the table size; the number of distinct values is only about √(2·sum), which makes the table pass affordable.
- Tier reasoning: LeetCode Hard by label.

## lc-number-of-great-partitions Number of Great Partitions (tier 4, pattern subset-sums, set practice)
- Budget: n, k ≤ 1000: a table of n · k = 10^6 cells.
- Idea: If the total is below 2k there is no great partition. Otherwise count the subsets with sum < k by a 0/1 knapsack over sums 0..k − 1, call it B; the bad partitions are those where one of the two groups has sum below k, and both groups cannot be below k at once, so the answer is 2^n − 2·B modulo 10^9 + 7.
- Techniques: 3.3, 3.2
- Needs this topic because: counting subsets by sum with a bounded table (sums above k are never needed) and complementary counting.
- Tier reasoning: LeetCode Hard by label; the table is standard, the complement is the idea.

## lc-minimum-time-to-make-array-sum-at-most-x Minimum Time to Make Array Sum At Most x (tier 4, pattern zero-one, set reserved, for review)
- Budget: n ≤ 1000: a table of n · n cells.
- Idea: After t seconds with resets at distinct indices, an index reset at second j contributes nums1[i] + j · nums2[i] − (stuff); the better choice is to reset indices with larger nums2 later. Sort by nums2 ascending, then dp[j] = the largest total reduction using j resets among the first i indices (each item taken or not, weight 1, value nums1[i] + j · nums2[i]). The answer is the least t with sum(nums1) + t · sum(nums2) − dp[t] ≤ x.
- Techniques: 3.3, 3.2, 1.5, 1.1
- Needs this topic because: an exchange argument fixes the order of resets (1.5), after which a 0/1 table over the number of resets finds the best reduction.
- Tier reasoning: LeetCode Hard by label; two ideas combined.
