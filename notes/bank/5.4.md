## cf-220B Little Elephant and Array (tier 2, pattern threshold-split, set practice) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) A value x can count only if it occurs at least x times overall, so fewer than √(2n) values qualify. Keep prefix counts for each candidate and answer every query by checking all candidates.
- Techniques: 5.4, 1.2
- Needs this topic because: few "large" candidates make per-candidate work affordable.
- Tier reasoning: rating 1800.

## cf-1514D Cut and Stick (tier 3, pattern mo, set practice) †
- Budget: n, q ≤ 3·10^5 (recalled).
- Idea: (recalled) With f = maximum frequency in [l, r] and len its length, the answer is max(1, 2f − len). Find f with Mo's algorithm: cnt[x] and cntOfCnt[c]; on removal, lower the current max when its cntOfCnt becomes 0.
- Techniques: 5.4
- Needs this topic because: maximum frequency maintained under Mo's add/remove.
- Tier reasoning: rating 2000.

## cf-86D Powerful array (tier 4, pattern mo, set practice) †
- Budget: n, t ≤ 2·10^5, values ≤ 10^6 (recalled).
- Idea: (recalled) Power = Σ cnt_s² · s. Mo's algorithm: adding s changes the answer by (2·cnt_s + 1)·s, removing by −(2·cnt_s − 1)·s. 64-bit.
- Techniques: 5.4
- Needs this topic because: an O(1) add/remove aggregate answered offline.
- Tier reasoning: rating 2200.

## cf-438D The Child and Sequence (tier 4, pattern blocks, set reserved, for checkpoint) †
- Budget: n, m ≤ 10^5 (recalled).
- Idea: (recalled) Operations: range sum, range a_i = a_i mod x, point assign. Blocks of size √n keep sum and max. A mod over a full block is skipped when max < x; otherwise touch each element and rebuild sum and max (an element that changes at least halves, so such touches total O(n log A)). Partial blocks and point assignment rebuild one block in O(√n). Queries add full-block sums and partial elements.
- Techniques: 5.4
- Needs this topic because: block summaries with an amortised rebuild; WEAK FIT: a segment tree with max and sum (5.3) also fits, sqrt blocks are the other well-known solution.
- Tier reasoning: rating 2300, a boundary rating kept in tier 4 so it can serve as a checkpoint (877F, also 2300, sits in tier 5 as practice).

## cf-830C Bamboo Partition (tier 4, pattern threshold-split, set reserved, for checkpoint) †
- Budget: n ≤ 100, k ≤ 10^11, a_i ≤ 10^9 (recalled).
- Idea: (recalled) For checking interval d the wasted height is d·S(d) − Σa with S(d) = Σ ⌈a_i/d⌉; find the largest d with d·S(d) − Σa ≤ k (not monotone in d). S is constant on runs of d, and each a_i has O(√a_i) runs, so enumerate the run boundaries of all a_i together. Inside a run with S fixed take d = min(run end, ⌊(k + Σa)/S⌋) when it is at least the run start. Also try d ≥ max a, where S = n. 64-bit.
- Techniques: 5.4
- Needs this topic because: small d are visited one by one and large d fall into few distinct quotient values.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating.

## cf-1654E Arithmetic Operations (tier 4, pattern threshold-split, set reserved, for exam) †
- Budget: n ≤ 10^5, a_i ≤ 10^5 (recalled).
- Idea: (recalled) Minimum changes to make the array an arithmetic progression with integer step d = n − (largest number of indices i with equal a_i − d·i over all d). Take B ≈ √A. For |d| ≤ B, count the values a_i − d·i with an offset array for each d: O(nB). For |d| > B two kept indices i < j satisfy |a_j − a_i| ≤ A, so j − i ≤ A/B; for each i look at the next A/B indices, and when (a_j − a_i) is divisible by (j − i) and the quotient has |d| > B count that quotient; the best count plus 1 is the candidate. O(n·A/B).
- Techniques: 5.4
- Needs this topic because: small slopes by a counting table, large slopes by a short window.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating so it can serve as an exam candidate.

## cf-425D Sereja and Squares (tier 4, pattern threshold-split, set reserved, for drill) †
- Budget: n ≤ 10^5 points, coordinates ≤ 10^5 (recalled).
- Idea: (recalled) Count axis-parallel squares whose four corners are all given points; count each square once from its left column. A column with at most √n points: take every pair (y1 < y2) in it, d = y2 − y1, and test whether (x+d, y1) and (x+d, y2) exist. A heavy column (more than √n points, so at most √n such columns): for every point (x', y) with x' > x set d = x' − x and test (x, y), (x, y+d), (x', y+d). Point lookups by sorted vectors with binary search or a hash set.
- Techniques: 5.4, 1.4
- Needs this topic because: the light and heavy columns need different enumerations; both cost O(n√n) lookups.
- Tier reasoning: rating 2300, kept in tier 4 as a boundary rating.

## cf-343D Water Tree (tier 3, pattern blocks, set reserved, for drill) †
- Budget: n, q ≤ 5·10^5 (recalled).
- Idea: (recalled) Operations on a rooted tree: fill a subtree, empty a vertex and all its ancestors, ask whether v is filled. Euler tour. fill(u) at time t is a range assign of t on the subtree of u (stored as a tag, a point query takes the maximum tag along the path); empty(u) at time t is a point update at u, and the latest empty time seen by v is the range maximum over the subtree of v. v is filled iff its fill time exceeds its empty time. Segment tree, O(log n) each. Looks like a block-decomposition job because of the range updates, but time stamps make a plain segment tree enough.
- Techniques: 5.4, 4.5, 5.3
- Needs this topic because: NOT this topic: this is an earlier-tool drill item (Euler tour 4.5 and segment tree 5.3).
- Tier reasoning: rating 2100, upper end of tier 3.

## cf-369E Valera and Queries (tier 4, pattern mo, set reserved, for drill) †
- Budget: n, m ≤ 10^5 segments and queries, total points ≤ 3·10^5, coordinates ≤ 10^6 (recalled).
- Idea: (recalled) Each query is a set of points; count the segments that contain at least one of them. A segment contains none exactly when it lies strictly inside a gap between consecutive query points (including the gaps before the first and after the last). Count, for each gap (a, b), the segments with l > a and r < b, offline: sort gaps by b, add segments in order of r into a Fenwick tree at l, and query a suffix count. The answer is n minus the sum over gaps.
- Techniques: 5.4, 5.2, 1.1
- Needs this topic because: NOT this topic: offline Fenwick (5.2). Looks like Mo because of many query sets over the same segments.
- Tier reasoning: rating 2200.

## ac-abc403_g Odd Position Sum Query (tier 4, pattern blocks, set reserved, for drill)
- Budget: Q ≤ 3·10^5, values up to 10^9, queries are encoded with the previous answer (online).
- Idea: Insert a value into a multiset and ask for the sum of the elements at odd ranks in sorted order. Online, so values cannot be compressed in advance: use a dynamic segment tree over [1, 10^9] with nodes created on demand; a node stores cnt, the sum of elements at odd ranks inside it and the sum at even ranks; merge: odd = odd(L) + (cnt(L) odd ? even(R) : odd(R)), even symmetric. Insert is O(log V) with about 3·10^5·30 nodes. The answer is the root's odd sum.
- Techniques: 5.4, 5.3
- Needs this topic because: NOT this topic: segment tree with a parity-aware merge (5.3). Looks like sorted blocks with insertion.
- Tier reasoning: ABC G with AtCoder Problems difficulty 2028; tier 4 as for the other reserved F/G items.

## cf-538F A Heap of Heaps (tier 4, pattern threshold-split, set reserved, for review) †
- Budget: n ≤ 2·10^5 (recalled).
- Idea: (recalled) For each k in 1..n−1, count the vertices v ≥ 2 whose value is smaller than their parent's in the k-ary heap layout, parent(v) = ⌊(v−2)/k⌋ + 1. Take B ≈ √n. For k ≤ B compute directly in O(n). For k > B the parent index is at most n/B + 1: for each such parent p build prefix counts c[j] = number of positions ≤ j with a smaller value than a_p (O(n) per p), and for every k > B add c[min(n, kp+1)] − c[k(p−1)+1]. Total O(n√n).
- Techniques: 5.4, 1.2
- Needs this topic because: small k and large k use different loops; neither alone fits in O(n√n).
- Tier reasoning: rating 2200.

## cf-1822G2 Magic Triples (Hard Version) (tier 4, pattern threshold-split, set reserved, for review) †
- Budget: Σ n ≤ 2·10^5, a_i ≤ 10^9 (recalled).
- Idea: (recalled) Count index triples whose values are x, x·b, x·b² for an integer b ≥ 1 (b = 1 gives c(c−1)(c−2) per value with count c). Treat each distinct middle value m with count c_m. Add cnt[m/b]·c_m·cnt[m·b]. Counts from a sorted array or hash map; about n·10^3 lookups.
- Techniques: 5.4, 1.1

- Tier reasoning: rating 2200.

## cf-920F SUM and REPLACE (tier 3, pattern blocks, set reserved, for review) †

## ac-abc384_g Abs Sum (tier 5, pattern mo, set practice)
- Budget: N ≤ 10^5, K ≤ 10^4, values ≤ 2·10^8.
- Idea: Query (X, Y): Σ_{i≤X} Σ_{j≤Y} |A_i − B_j|. Treat (X, Y) as a range-like pair of two moving pointers and order the queries as in Mo's algorithm (block of X, then Y). ## ac-abc405_g Range Shuffle Query (tier 5, pattern mo, set practice)
- Budget: N, Q ≤ 2.5·10^5, A_i, X ≤ N, answers modulo 998244353.
- Idea: For query (L, R, X) keep the elements of A[L..R] with value < X; the number of distinct arrangements is (Σ c_v)! / Π c_v! over v < X. Mo's algorithm over (L, R) maintains the counts c_v; the product of 1/c_v! over v < X and the sum of c_v over v < X must be readable fast. Store them per value bucket: a point change multiplies one value's factor by the inverse of its new count (adding) or by the old count (removing) and updates its bucket, O(1); a query combines whole buckets below X and single values in the last bucket, O(√N). Precompute factorials and inverses. O(N√Q + Q√N).
- Techniques: 5.4, 2.2
- Needs this topic because: Mo's algorithm with an O(1)-update, O(√N)-query structure on values (sqrt buckets).
- Tier reasoning: ABC G with difficulty 2354, tier 5; practice only.
