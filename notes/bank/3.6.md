Solution notes for every bank problem (bank plan Section 7.4). Not shown on the site. † = Codeforces problem checked through the official API only (title, rating, tags); the statement could not be opened from the build environment, so the idea below needs a spot-check on the page.

## ac-dp_n Slimes (tier 3, pattern merge-split, set practice)
- Budget: N ≤ 400.
- Idea: cost[l][r] = min over k of cost[l][k] + cost[k+1][r] + sum(l..r) (prefix sums). O(N³). long long.
- Techniques: 3.6, 1.2
- Needs this topic because: the merge template.
- Tier reasoning: EDP N.

## lc-minimum-score-triangulation-of-polygon Minimum Score Triangulation of Polygon (tier 3, pattern merge-split, set practice)
- Budget: n ≤ 50.
- Idea: best[i][j] = min over i < k < j of best[i][k] + best[k][j] + v_i·v_j·v_k; the triangle on edge (i, j) splits the polygon.
- Techniques: 3.6
- Needs this topic because: choosing the split point that owns the segment's endpoints.
- Tier reasoning: LeetCode Medium.

## lc-minimum-cost-to-cut-a-stick Minimum Cost to Cut a Stick (tier 3, pattern merge-split, set practice)
- Budget: up to 100 cuts.
- Idea: Sort cuts, add 0 and n as ends. cost[i][j] = (c_j − c_i) + min over i < k < j of cost[i][k] + cost[k][j].
- Techniques: 3.6, 1.1
- Needs this topic because: splitting (the reverse of merging) on the cut positions.
- Tier reasoning: LeetCode Hard, but the template applies directly.

## lc-minimum-cost-tree-from-leaf-values Minimum Cost Tree From Leaf Values (tier 2, pattern merge-split, set practice)
- Budget: n ≤ 40.
- Idea: cost[l][r] = min over k of cost[l][k] + cost[k+1][r] + max(l..k)·max(k+1..r).
- Techniques: 3.6
- Needs this topic because: merge-split where the merge cost uses range maxima.
- Tier reasoning: LeetCode Medium (a monotonic-stack greedy also exists).

## lc-burst-balloons Burst Balloons (tier 4, pattern merge-split, set practice)
- Budget: n ≤ 300.
- Idea: Pad with 1s. best[l][r] (open interval) = max over k in (l, r) of best[l][k] + best[k][r] + v_l·v_k·v_r, where k is the last balloon burst inside.
- Techniques: 3.6
- Needs this topic because: choosing the last action, not the first, makes the parts independent.
- Tier reasoning: LeetCode Hard; the "last burst" view is the insight.

## lc-minimum-cost-to-merge-stones Minimum Cost to Merge Stones (tier 4, pattern merge-split, set reserved, for exam)
- Budget: n ≤ 30, 2 ≤ k ≤ 30.
- Idea: Impossible unless (n − 1) % (k − 1) == 0. cost[i][j] = min over m stepping by k − 1 of cost[i][m] + cost[m+1][j]; add sum(i..j) when (j − i) % (k − 1) == 0 (the segment collapses to one pile).
- Techniques: 3.6, 1.2
- Needs this topic because: merge-split with a pile-count condition.
- Tier reasoning: LeetCode Hard.

## lc-guess-number-higher-or-lower-ii Guess Number Higher or Lower II (tier 3, pattern merge-split, set reserved, for review)
- Budget: n ≤ 200.
- Idea: cost[l][r] = min over guess g of g + max(cost[l][g−1], cost[g+1][r]).
- Techniques: 3.6
- Needs this topic because: minimax over a split point: the guess splits the range into two parts, and the worse one counts. It looks like binary search, but the cheapest strategy is not the middle guess.
- Tier reasoning: LeetCode Medium.

## cses-1744 Rectangle Cutting (tier 3, pattern merge-split, set reserved, for later_drill)
- Budget: a, b ≤ 500.
- Idea: moves[a][b] = 0 if a = b, else min over horizontal and vertical cuts of moves of the two parts + 1. O(ab(a + b)) ≈ 1.25·10^8 simple steps.
- Techniques: 3.6
- Needs this topic because: splitting in two dimensions. Reserved as a distractor for 2.1 drills: it looks like a gcd problem, but the Euclid-style greedy is wrong.
- Tier reasoning: CSES.

## lc-predict-the-winner Predict the Winner (tier 2, pattern take-from-ends, set reserved, for lookalike)

## lc-stone-game Stone Game (tier 2, pattern take-from-ends, set reserved, for lookalike)
- Budget: n ≤ 500, n even, odd total.
- Idea: Alice can always take all even-indexed or all odd-indexed piles (she controls the parity of what Bob can reach). One set is larger, so return true.
- Techniques: 0.4
- Needs this topic because: look-alike partner of Predict the Winner: same game, but even n and odd total make the answer always true by a parity argument.
- Tier reasoning: LeetCode Medium.
