## cf-219D Choosing Capital for Treeland (tier 1, pattern direction, set practice) †
- Budget: n ≤ 2·10^5 (recalled).
- Idea: (recalled) The roads of a tree are directed; choose the capital so that the fewest roads have to be reversed for every city to be reachable from it; print the least number and all capitals. Root at city 1 and count the roads that point towards the root: that is the cost for the root. Moving the capital across a road p-c from p to c changes the count by +1 if the road points from p to c (it now points towards the capital) and by -1 if it points from c to p. One pass for the root, one pass over the edges for the rest.
- Techniques: 7.2, 7.1, 3.3, 4.6
- Needs this topic because: the answer for every root changes by ±1 along an edge, and the sign depends on the direction of the road.
- Tier reasoning: rating 1700.

## cf-1882D Tree XOR (tier 2, pattern rerooting, set practice) †
- Budget: n ≤ 2·10^5 (recalled).
- Idea: (recalled) Operation: choose a vertex and a number x and xor x into every vertex of its subtree, at a cost of x times the subtree size; for every vertex taken as the root, the least total cost to make all numbers equal. For a fixed root the best plan uses each edge once: xor the difference of the two ends into the whole part below the child, so the cost is the sum over edges of (a_u xor a_v) times the size of the part away from the root. Moving the root across an edge changes the size of the part away for that one edge only, so the cost for the child is the cost for the parent plus (a_u xor a_v) times (2·size(c) − n) with the right sign; check the signs on a path of three vertices.
- Techniques: 7.2, 7.1, 3.3, 4.6, 1.7
- Needs this topic because: one edge changes sides when the root moves, so the cost changes by one term.
- Tier reasoning: rating 1900.

## ac-abc223_g Vertex Deletion (tier 5, pattern exclude-one, set practice)
- Budget: N ≤ 2·10^5.
- Idea: Count the vertices i such that removing i leaves a maximum matching of the same size as the whole tree. The size of a maximum matching of a rooted tree is found from the leaves up with a pair per vertex: m[v] = the sum of m over the children plus 1 if some child is left free, and free[v] = true when no child is free (the greedy from the leaves is optimal). Removing i splits the tree into the parts beyond its neighbours, so M(T − i) is the sum of the matchings of those parts: the children (their m) and the part above i. The part above a child c is the part of the parent p without c, and the pair (m, free) of it is read from the sums of the other children and the number of free ones among them, both of which can be taken out of the totals. Count the vertices with M(T − i) = M(T).
- Techniques: 7.2, 7.1, 3.3, 4.6
- Needs this topic because: the value of a part is a pair (size, free or not), the part above a child needs the other children without it, and one pass from the root is not enough for every deleted vertex.
- Tier reasoning: ABC G (difficulty 2351).

## lc-minimum-edge-reversals-so-every-node-is-reachable Minimum Edge Reversals So Every Node Is Reachable (tier 4, pattern direction, set reserved, for review)
- Budget: n ≤ 10^5.
- Idea: Treat the edges as undirected. For the root 0 count the edges that point towards the root (they must be reversed). Moving the root across an edge p-c: if the edge is directed p to c, the answer for c is the answer for p plus 1, otherwise minus 1. Breadth-first order from 0, then one pass.
- Techniques: 7.2
- Needs this topic because: a root-dependent count that changes by ±1 along each edge.
- Tier reasoning: LeetCode Hard.
